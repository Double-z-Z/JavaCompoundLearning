# 复利笔记整理

**边学边沉淀，拒绝事后整理！**

**复利核心**：每个知识点必须建立至少2个双向链接，形成知识网络。

---

## 工作流程

### 1. 识别知识类型

在学习过程中，实时识别内容类型：

| 内容类型 | 判断标准 | 保存位置 | 使用模板 |
|---------|---------|---------|---------|
| **练习代码** | 实现的功能、对比测试 | `03-Practice/drills/` | 练习记录模板 |
| **核心概念** | 原理、机制、设计思想 | `02-Knowledge/<主题>/concepts/` | 原子笔记模板 |
| **思维误区** | 错误理解→正确理解的转变 | `03-Practice/reflections/` | 反思记录模板 |
| **对话感悟** | 学习心得、思维升级 | `03-Practice/reflections/` | 反思记录模板 |
| **项目实战** | 多阶段完整项目 | `01-Projects/` | 项目笔记模板（由项目拆解Skill创建） |

### 2. 即时保存策略

#### **场景 A：完成练习**

```
用户完成代码实现
    ↓
判断是否属于某个项目？
    ├── 是 → 保存到：03-Practice/drills/<日期>-<项目名>-<阶段>.md
    │         在练习记录中链接到：[[项目笔记#Phase X]]
    │         更新项目笔记中的"关联练习"链接
    │
    └── 否 → 保存到：03-Practice/drills/<日期>-<主题>.md
    ↓
使用模板：练习记录模板.md
包含：
- 实现了什么
- 对比测试结果
- 关联的概念（更新相关概念的 mastery）
    ↓
继续下一个知识点
```

#### **场景 B：讨论核心概念**

```
用户提问原理/机制
    ↓
AI 解释 + 横向拓展
    ↓
立即保存到：02-Knowledge/<主题>/concepts/<概念>.md
使用模板：原子笔记模板.md
包含：
- 一句话定义
- 核心理解（自由写作）
- 关键关联（至少2个双向链接 + 关联原因）
- 我的误区
- mastery=20 (初识)
    ↓
继续深入或切换到下一个话题
```

#### **场景 C：纠正思维误区**

```
用户表达错误理解
    ↓
AI 追问 + 引导反思
    ↓
用户顿悟
    ↓
立即记录到：03-Practice/reflections/<日期>-<主题>-dialogue.md
使用模板：反思记录模板.md
包含：
- 问题 → 我的回答 → AI 追问 → 最终理解
- 顿悟时刻
- 相关概念的 mastery 更新（+20分深度理解）
    ↓
继续对话
```

### 3. 掌握度（mastery）更新流程

每个原子笔记的 frontmatter 中包含 `mastery` 字段，由AI根据学习活动自动更新。

#### 分值等级

| 分值 | 等级 | 判定标准 |
|-----|------|---------|
| 0-30 | 🌱 初识 | 刚创建笔记，理解表面 |
| 31-60 | 🌿 理解 | 能解释概念，完成相关练习 |
| 61-85 | 🍎 应用 | 能在项目中正确使用 |
| 86-100 | 🌳 掌握 | 能向他人讲解，处理边界情况 |

#### 更新触发条件

**+10-20分：完成练习**
- 完成相关 drill，验证理解
- 在练习中正确应用概念
- 在练习记录的AI评价中记录：`- [[概念A]]: +15分 (正确应用)`

**+10-15分：建立新关联**
- 发现与已有知识的新连接
- 更新笔记添加双向链接
- 在原子笔记的AI评价中记录更新

**+15-25分：教学/讲解**
- 向他人解释这个概念
- 在对话中纠正他人误区
- 在反思记录的AI评价中记录更新

**-5-10分：发现理解偏差**
- 练习中犯错
- 对话中发现误解
- 创建错误档案时记录

#### 更新操作

在原子笔记的 `🤖 AI评价` 区域记录：
```markdown
### 掌握度评估
- 当前等级：🌿理解
- 更新记录：
  - 2026-04-13: mastery=20 (初建笔记)
  - 2026-04-14: mastery=45 (完成练习，正确应用)
```

同时更新 frontmatter：
```yaml
---
mastery: 45
---
```

### 4. GOAL 缺口与 Gap 矩阵同步（笔记保存后必做）

**Step 4.1：检查 GOAL 缺口填补**
```
保存原子笔记后：
1. 检查笔记的 frontmatter.related_goal
2. 如果关联了某个 GOAL，打开该 GOAL 文件
3. 检查该概念是否对应 GOAL 的某个缺口
4. 如果该概念已验证（mastery ≥ 61），标记缺口为 🟢 已达标
5. 更新 GOAL 文件的进度统计
```

**Step 4.2：更新 Gap 诊断矩阵**
```
如该笔记关联某 GOAL 缺口：
1. 打开 `.agent/_system/META-Gap-诊断矩阵.md`
2. 找到对应 GOAL 的缺口行
3. 更新进度列（如：epoll机制 mastery=20→65）
4. 如 mastery ≥ 61，标记该缺口为 🟢 已验证
```

**Step 4.3：更新 EMRG 关联**
```
保存原子笔记后：
1. 检查笔记的 frontmatter.related_emrg
2. 如果属于某 EMRG 主题，打开该 EMRG 文件
3. 检查 EMRG 的成熟度是否需要更新：
   - 新增 verified 笔记（mastery ≥ 61）→ 更新 EMRG 进度
   - 新增双向链接 → 更新 EMRG 的链接数统计
4. 如 EMRG 下笔记数量变化，检查是否触发涌现条件（见第5节）
```

### 5. 质量红线

#### 笔记晋升门槛（进入 EMRG 前必须满足）

- [ ] **实践门槛**：有练习记录、项目实战或生产 Incident 关联
- [ ] **链接门槛**：双向链接 ≥ 2 个已有知识点（Dataview 验证）
- [ ] **价值门槛**：删除它，某 GOAL 缺口将无法填补？（人工判断）

#### 保存前查重

```
1. 执行 obsidian search query="概念关键词"
2. 如命中已有笔记：
   → 内容覆盖 → 补充链接，不新建
   → 内容补充 → 扩充现有笔记
```

#### ❌ 禁止

- 先写大笔记，再事后拆分
- 只记录到临时文件，不结构化
- 对话结束才想起来保存
- 原子笔记少于2个双向链接
- 创建无新链接的孤岛笔记

#### ✅ 必须

- 每个知识点讨论完立即保存
- 按模板结构化内容
- 添加知识关联（至少 2 个 + 关联原因）
- 更新 .agent/profile.md
- 更新相关概念的 mastery 字段

### 7. 涌现检测（整理笔记专属）

在整理笔记时，同步检测涌现触发条件：

#### 涌现规则检测

```
检查是否触发涌现条件？

1. 密度阈值检测
   - 同一Tag下原子笔记≥5篇？
   - 该Tag下双向链接≥3条？
   → 如果是，建议创建EMRG

2. 链接熵增检测
   - 某笔记被≥3个不同MOC/EMRG引用？
   → 如果是，建议创建交叉EMRG

3. 概念裂变检测
   - 某个EMRG下子主题超过7个？
   → 如果是，建议分裂EMRG
```

#### 涌现建议格式

当检测到触发条件时，在汇总中输出：

```markdown
## 涌现检测报告

| 触发类型 | 检测结果 | LLM建议 |
|---------|---------|---------|
| 密度阈值 | Tag#redis下有6篇笔记，4条链接 | 建议创建EMRG-Redis |
| 链接熵增 | [[缓存行伪共享]]被3个EMRG引用 | 建议创建交叉EMRG |

⚠️ **请决策**：✅ 同意创建 / ❌ 拒绝 / ⏸️ 暂缓
```

#### 涌现日志更新

用户同意后，**必须追加到** `.agent/_system/META-涌现触发器日志.md`：

```markdown
### YYYY-MM-DD: [事件描述]

| 字段 | 值 |
|------|-----|
| 触发类型 | 密度阈值/链接熵增/实践验证/时间衰减/概念裂变 |
| 涉及笔记 | [[笔记1]], [[笔记2]] |
| 涉及EMRG | [[EMRG-xxx]] |
| LLM建议 | 创建/合并/分裂/归档 |
| 最终决策 | ✅同意 |
| 原因 | ... |
```

### 9. 对话后萃取流程（非可选）

**触发**：任何以 dialogue/reflection/summary 形式保存到 `03-Practice/reflections/` 的对话结束后，**必须**执行本流程。

**核心原则**：对话记录是"原料仓库"，洞察必须被萃取到知识图谱中才能成为复利资产。

---

**Step 1: 自动提取关键洞察**

- 读取本次对话历史（或刚保存的 reflection 文件正文）
- 提取 1-3 个"可复用的认知结论"
  - 不是全文摘要，是可指导实践的洞察
  - 格式：一句话结论 + 为什么重要 + 适用边界
- 排除：
  - 纯事实复述（如"Redis 支持 String 类型"）
  - 过于具体的调试步骤（如"在第 37 行加了 synchronized"）
  - 尚未验证的猜测

---

**Step 2: 检查是否已存在**

```
使用 obsidian search query="洞察关键词"
├── 命中已有原子笔记
│   → 比较：新洞察 vs 已有笔记的内容
│   ├── 内容覆盖 → 在已有笔记中补充链接和案例，不新建
│   └── 内容补充 → 扩充现有笔记的"核心理解"部分
│
└── 未命中
    → 进入 Step 3：生成原子笔记草稿
```

---

**Step 3: 写入草稿到 `02-Knowledge/<主题>/concepts/`**

按 `05-Templates/原子笔记模板.md` 生成草稿：

```markdown
---
type: atomic-note
id: CONCEPT-<简述>
date: YYYY-MM-DD
mastery: 20              # 初识，如对话中已纠正误区可设为 40
source: "[[03-Practice/reflections/对话文件名]]"
related_emrg: [EMRG-xxx]
related_goal: [GOAL-xxx]
---

# 概念名称

## 一句话定义
...

## 核心理解
...

## 关键关联
- [[已有概念A]] - 关联原因：...
- [[已有概念B]] - 关联原因：...

## 我的误区（如适用）
<!-- 来自对话中的顿悟时刻 -->
```

**草稿生成后，输出给用户确认**：
> "我从本次对话中提取了以下洞察，已按原子笔记模板生成草稿：
> 1. [[概念A]] - ...
> 2. [[概念B]] - ...
> 是否确认写入？或需要修改？"

---

**Step 4: 更新 reflection 文件的 frontmatter**

用户确认写入后，在原对话记录中追加/更新 frontmatter：

```yaml
insights_extracted: true
key_insights:
  - "洞察1的一句话描述"
  - "洞察2的一句话描述"
extracted_notes:
  - "[[02-Knowledge/主题/concepts/概念A]]"
  - "[[02-Knowledge/主题/concepts/概念B]]"
```

---

**Step 5: 更新相关系统状态**

1. **mastery 同步**
   - 在原子笔记的 `🤖 AI评价` 区域记录对话带来的 mastery 变化
   - 同步更新 `.agent/profile.md` 的掌握度追踪

2. **EMRG 成熟度检查**
   - 如新增 verified 级别笔记（mastery ≥ 61）→ 检查 EMRG 成熟度是否需要更新
   - 如新增双向链接 → 更新 EMRG 链接数统计

3. **Gap 矩阵同步（如关联 GOAL）**
   - 如笔记关联了 GOAL 缺口，且 mastery ≥ 61 → 标记缺口为 🟢 已达标
