# 复利笔记整理

**边学边沉淀，拒绝事后整理！**

**复利核心**：每个知识点必须建立至少2个双向链接，形成知识网络。

***

## 工作流程

### 1. 识别知识类型

在学习过程中，实时识别内容类型：

| 内容类型     | 判断标准         | 保存位置                          | 使用模板                 |
| -------- | ------------ | ----------------------------- | -------------------- |
| **练习代码** | 实现的功能、对比测试   | `03-Practice/drills/`         | 练习记录模板               |
| **核心概念** | 原理、机制、设计思想   | `02-Knowledge/<主题>/concepts/` | 原子笔记模板               |
| **思维误区** | 错误理解→正确理解的转变 | `03-Practice/reflections/`    | 反思记录模板               |
| **对话感悟** | 学习心得、思维升级    | `03-Practice/reflections/`    | 反思记录模板               |
| **项目实战** | 多阶段完整项目      | `01-Projects/`                | 项目笔记模板（由项目拆解Skill创建） |

### 2. 保存前检查：质量红线

**任何笔记保存前，必须执行以下检查。**

#### 2.1 保存前查重

```
1. 执行 obsidian search query="概念关键词"
2. 如命中已有笔记：
   ├── 内容覆盖 → 补充链接，不新建
   └── 内容补充 → 扩充现有笔记
```

#### 2.2 笔记晋升门槛

- [ ] **实践门槛**：有练习记录、项目实战或生产 Incident 关联
- [ ] **链接门槛**：双向链接 ≥ 2 个已有知识点（Dataview 验证）
- [ ] **价值门槛**：删除它，某 GOAL 缺口将无法填补？（人工判断）

#### 2.3 ❌ 禁止 / ✅ 必须

| ❌ 禁止          | ✅ 必须                  |
| ------------- | --------------------- |
| 先写大笔记，再事后拆分   | 每个知识点讨论完立即保存          |
| 只记录到临时文件，不结构化 | 按模板结构化内容              |
| 对话结束才想起来保存    | 添加知识关联（至少 2 个 + 关联原因） |
| 原子笔记少于2个双向链接  | 更新相关概念的 mastery 字段    |

### 4. 保存后处理（强制）

**任何笔记保存后，必须按以下顺序执行，不可跳过。**

#### 4.1 涌现检测（执行入口）

**Step 1: 读取候选标签**

- 从刚保存笔记的 frontmatter `tags` 字段中提取概念标签

**Step 2: 获取标签笔记列表**

- 对每个候选标签执行：`obsidian search tag:<标签>`
- 获取笔记列表，按创建时间排序
- 如数量 < 5，跳过该标签

**Step 3: 确定枢纽候选**

- 取列表中**最老的 2 篇**笔记作为枢纽候选
- 如数量 > 8，增加第 3 篇最老笔记作为枢纽候选

**Step 4: 查枢纽 backlinks**

- 对每个枢纽候选执行：`obsidian backlinks file="<枢纽笔记名>"`
- 过滤 backlinks：只保留源笔记也在 Step 2 列表中的（即同 tag 引用）
- 汇总同 tag 反向链接总数 B

**Step 5: 触发判断与申报**

- B ≥ 3 且 `04-Maps/Emergent/EMRG-<标签>.md` 不存在？
  - 是 → 触发密度溢出，将事件按 `.agent/_system/META-涌现触发器日志.md` 格式写入日志，状态 🟡 待审批
  - 否 → 跳过涌现检测，进入 4.2

**申报后处理**：
- 不在整理笔记中执行创建/审批
- 由用户在每周回顾中统一审批，或手动调用 **EMRG管理 Skill** 处理
- 如用户立即要求处理，引导至 EMRG管理 Skill 的「分支 A: 创建 EMRG」

#### 4.2 对话萃取（仅 reflections）

- 如果保存到 `03-Practice/reflections/` → 立即调用 `### 7.` 的对话后萃取流程
- 其他类型 → 跳过

#### 4.3 mastery 更新

根据学习活动自动更新原子笔记的 `mastery` 字段：

| 分值     | 等级    | 标准            |
| ------ | ----- | ------------- |
| 0-30   | 🌱 初识 | 刚创建笔记，理解表面    |
| 31-60  | 🌿 理解 | 能解释概念，完成相关练习  |
| 61-85  | 🍎 应用 | 能在项目中正确使用     |
| 86-100 | 🌳 掌握 | 能向他人讲解，处理边界情况 |

**更新幅度**：

- 完成练习：+10\~20
- 建立新关联：+10\~15
- 教学/纠正误区：+15\~25
- 发现理解偏差：-5\~-10

**更新位置**：

1. 原子笔记 frontmatter：`mastery: XX`
2. 原子笔记 `🤖 AI评价` 区域记录更新日志
3. `.agent/profile.md` 的「当前快照」——仅更新知识点列表的最新 mastery 值

#### 4.4 同步关联系统

1. **EMRG 成熟度**
   - 如笔记关联了 `related_emrg`，检查 EMRG 成熟度是否需要更新
   - 新增 verified 笔记（mastery ≥ 61）→ 更新 EMRG 进度

### 6. 涌现检测规则库（只读参考）

> 本节为规则详细说明，**实际执行入口在** **`4.1`**。

#### 6.1 密度阈值检测

- 同一主题下原子笔记 ≥ 5 篇？
- 该主题下双向链接 ≥ 3 条？
- → 建议创建 EMRG

#### 6.2 链接熵增检测

- 某笔记被 ≥ 3 个不同 EMRG 引用？
- → 建议创建交叉 EMRG

#### 6.3 概念裂变检测

- 某个 EMRG 下子主题超过 7 个？
- → 建议分裂 EMRG

#### 6.4 对话主题密度检测

- 扫描 `03-Practice/reflections/` 过去 30 天的 frontmatter
- 同一 `topics` 下出现 ≥ 3 篇对话？且尚无对应 EMRG？
- → 建议创建 EMRG，证据来源为对话洞察

#### 6.5 涌现建议格式

```markdown
## 涌现检测报告

| 触发类型 | 检测结果 | LLM建议 |
|---------|---------|---------|
| 密度阈值 | Tag#redis下有6篇笔记，4条链接 | 建议创建EMRG-Redis |
| 链接熵增 | [[缓存行伪共享]]被3个EMRG引用 | 建议创建交叉EMRG |
| 对话主题密度 | 过去30天WebFlux对话3篇，无对应EMRG | 建议创建EMRG-WebFlux |

⚠️ **请决策**：✅ 同意创建 / ❌ 拒绝 / ⏸️ 暂缓
```

#### 6.6 涌现日志模板

用户同意后，追加到 `.agent/_system/META-涌现触发器日志.md`，并创建 `04-Maps/Emergent/EMRG-<标签>.md`：

```markdown
### YYYY-MM-DD: [事件描述]

| 字段 | 值 |
|------|-----|
| 触发类型 | 密度阈值/链接熵增/实践验证/时间衰减/概念裂变/对话主题密度 |
| 涉及笔记 | [[笔记1]], [[笔记2]] |
| 涉及EMRG | [[EMRG-xxx]] |
| LLM建议 | 创建/合并/分裂/归档 |
| 最终决策 | ✅同意 |
| 原因 | ... |
```

### 7. 对话后萃取流程（执行入口在 4.2）

**触发**：保存到 `03-Practice/reflections/` 的对话结束后。

**核心原则**：对话记录是"原料仓库"，洞察必须被萃取到知识图谱中。

#### 7.1 自动提取关键洞察

- 读取对话历史（或 reflection 文件正文）
- 提取 1-3 个"可复用的认知结论"
  - 不是全文摘要，是可指导实践的洞察
  - 格式：一句话结论 + 为什么重要 + 适用边界
- 排除：纯事实复述、过于具体的调试步骤、尚未验证的猜测

#### 7.2 检查是否已存在

```
使用 obsidian search query="洞察关键词"
├── 命中已有原子笔记
│   ├── 内容覆盖 → 补充链接，不新建
│   └── 内容补充 → 扩充现有笔记
│
└── 未命中 → 进入 7.3：生成原子笔记草稿
```

#### 7.3 写入草稿

按 `05-Templates/原子笔记模板.md` 生成草稿，frontmatter 包含：

```yaml
source: "[[03-Practice/reflections/对话文件名]]"
related_emrg: [EMRG-xxx]
related_goal: [GOAL-xxx]
```

**草稿生成后输出给用户确认**：

> "我从本次对话中提取了以下洞察，已生成草稿：
>
> 1. \[\[概念A]] - ...
>    是否确认写入？"

#### 7.4 更新 reflection 文件的 frontmatter

用户确认后：

```yaml
insights_extracted: true
key_insights:
  - "洞察1的一句话描述"
extracted_notes:
  - "[[02-Knowledge/主题/concepts/概念A]]"
```

#### 7.5 同步关联系统

1. **mastery 同步**：在原子笔记 `🤖 AI评价` 区域记录变化，同步 `.agent/profile.md`
2. **EMRG 成熟度**：如新增 verified 笔记 → 更新 EMRG 进度

### 8. 示例流程

#### 示例：学习 LongAdder

```
1. 用户实现 LongAdderCounter
   → 保存到 03-Practice/drills/2026-04-11-concurrent-counters.md

4. 保存后处理
   → 涌现检测：concurrency 主题已有 8 篇，EMRG-并发编程 已存在 → 跳过
   → 对话萃取：提取"CAS 必要性"洞察 → 已存在于 LongAdder.md → 补充链接
   → mastery 同步：更新 profile.md
```
