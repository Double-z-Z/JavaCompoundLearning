## 步骤详解

### 步骤 4: 知识回流检查（项目 → EMRG）

**为什么**: 项目实战中产生的概念洞察如果只留在项目笔记里，EMRG 永远缺内容，导致后续学习推荐时误判为"未掌握"。

**执行方法**:
```
1. 扫描项目笔记（{项目名}.md / docs/）中的 wikilink
2. 提取项目涉及的所有原子笔记列表
3. 对每个原子笔记，检查其 frontmatter 的 related_emrg：
   ├── 已关联且 EMRG 核心成员表格中存在 → ✅ 通过
   ├── 已关联但 EMRG 核心成员表格中不存在 → 补充到 EMRG
   └── 未关联 → 根据主题匹配到对应 EMRG，更新双方 frontmatter
4. 检查项目笔记自身的 related_emrg：
   ├── 存在 → 确认 EMRG 中已链接该项目
   └── 不存在 → 根据项目主题匹配到对应 EMRG，写入 related_emrg
5. 项目笔记 → EMRG 项目实战表格同步（强制）：
   ├── 读取项目笔记 frontmatter 的 related_emrg 列表
   ├── 对每个 EMRG，检查其「项目实战」表格中是否包含该项目
   ├── 未包含 → 在表格中添加一行：项目名、状态（来自项目笔记 status/mastery）、关联笔记
   └── 已包含 → 对比状态是否一致，不一致则同步更新
```

**输出格式**:
```markdown
### 知识回流检查

| 原子笔记 | 当前 EMRG 关联 | 动作 |
|---------|---------------|------|
| [[Sentinel-Entry生命周期]] | EMRG-Sentinel-高级特性 ✅ | 无 |
| [[数据倾斜解决方案]] | 无 ❌ | 纳入 EMRG-Redis |
| [[Redis Pipeline在秒杀中的应用]] | 无 ❌ | 纳入 EMRG-Redis |
```

### 步骤 5: Gap 闭环检查（项目 → GOAL）

**为什么**: 项目是为了填补 GOAL 缺口而做的，但项目完成后 Gap 矩阵往往没有同步更新，导致系统继续推荐已完成的缺口。

**执行方法**:
```
1. 读取项目笔记的 related_goal（或根据项目主题推断对应 GOAL）
2. 读取对应 GOAL 的 gap_analysis / gaps[]
3. 对比项目产出与缺口描述：
   ├── 项目直接填补了某缺口 → 更新 Gap 矩阵为 🟢 已达标
   ├── 项目部分填补了某缺口 → 更新 Gap 矩阵为 🟡 进行中，补充证据
   └── 项目未涉及某缺口 → 保持原状态
4. 更新 META-Gap-诊断矩阵.md 的"当前 EMRG 证据"和"差距"列
```

**输出格式**:
```markdown
### Gap 闭环检查

| 缺口 ID | 缺口描述 | 项目证据 | 原状态 | 新状态 |
|---------|---------|---------|--------|--------|
| G-RED-04 | 缓存策略最佳实践 | redis-counter-service-webflux 实现了 Caffeine + Redis 多级缓存 | 🟡 进行中 | 🟢 已达标 |
| G-SPR-03 | 服务注册/发现/熔断/网关 | 项目使用了 Sentinel 熔断，但缺网关/注册发现 | 🔴 高 | 🟡 进行中 |
```

## AI评估职责

### 1. 检查新评估证据

| 证据类型 | 映射维度 |
|---------|---------|
| 新原子笔记 | 核心技术知识 |
| 新项目代码 | 工程实践 |
| 新错误档案 | 问题分析 |
| 新架构讨论 | 架构设计 |

### 2. 置信度判定

- **高置信度**：代码+对话+错误档案交叉验证
- **中置信度**：仅有笔记或单次对话
- **低置信度**：仅有计划或自我报告

### 3. 更新评估档案（扩展）

- 更新 `.agent/assessment/current.json`
- 更新 `04-Maps/META-能力雷达图.md`
- **更新 EMRG 核心成员表格**：将项目涉及的新原子笔记纳入对应 EMRG
- **更新 EMRG 项目实战表格**：将项目笔记同步到其 `related_emrg` 对应的所有 EMRG 的「项目实战」表格中（新增或更新状态）
- **更新 META-Gap-诊断矩阵.md**：同步 GOAL 缺口的填补状态
- 更新 `.agent/profile.md` 中「当前快照」的知识点列表及最新 mastery 值
  - ✅ 允许：修改某知识点的当前 mastery 数值
  - ❌ 禁止：写入历史变化过程、评估详情、产出物清单
  - 详细评估记录写入 `03-Practice/assessment/`

### 4. 推荐学习路径

- 识别最低分维度
- 推荐下一学习主题
- 生成带评估验证点的学习计划

## 里程碑定义

由学习者自主设定，非固定时间：
- 完成一个主题的系统学习（如"完成NIO专题"）
- 达到某个能力等级（如"并发编程达到L3"）
- 完成一个综合项目（如"完成高并发计数器服务"）
- 积累一定量的知识资产（如"产出10个原子笔记"）
