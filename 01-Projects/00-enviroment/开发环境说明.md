## 网络拓扑

```
外部笔记本 (WSL: 192.168.1.2)
        ↓ 192.168.1.x
家用路由器 (192.168.1.1)
        ↓
PVE 宿主机 / WRT (WAN: 192.168.1.7, LAN: 10.0.0.1/24)
        ↓ NAT 转换
PVE 内部虚拟网桥 (10.0.0.1/24)
        ↓
    ├── 开发机 (10.0.0.142:8080) ← 应用服务器
    └── Redis VM (10.0.0.104:6379) ← 被测系统
```

## 关键约束

1. **开发机无法操控 PVE** - PVE 宿主机需要手动操作
2. **开发机无法操控外部压测端** - 外部笔记本需要手动执行命令
3. **WSL 与 PVE 内部之间隔着一个路由器（WRT NAT）** - 网络路径经过家用路由器和 PVE NAT 转换
4. **开发机位于虚拟机内部** - 可以直接访问 Redis VM

## 测试注意事项

- **外部压测路径**：WSL → 家用路由器 → PVE NAT → Redis VM（约 4-5 万 QPS）
- **内部压测路径**：开发机 → PVE 内部网桥 → Redis VM（约 15-17 万 QPS）
- **瓶颈位置**：外部测试时，NAT 转换和路由器转发可能是主要瓶颈
- PVE 内多台 VM 同时压测存在 CPU 资源竞争

## 瓶颈分析

### 外部压测（WSL → Redis）瓶颈点

1. **WSL 虚拟网卡** - Windows 虚拟网络栈
2. **家用路由器** - 转发能力有限
3. **PVE NAT 转换** - iptables/NAT 转发 CPU 消耗

### 可能的优化方向

1. **有线直连 PVE** - 绕过家用路由器
2. **调整路由器 QoS/转发规则** - 如果可操控
3. **PVE 网络优化** - VirtIO 驱动、vhost-net
