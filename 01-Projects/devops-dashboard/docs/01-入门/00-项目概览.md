# DevOps Dashboard — 项目概览

> **AI-Native DevOps 实验平台** | 从传统手动配置 (V1) 向 MCP AI-Native 演进

---

## 1. 项目定位

DevOps Dashboard 是一个 **AI 驱动的 DevOps 实验平台**，核心使命是：

> **让开发者通过自然语言与 AI 协作，快速创建实验环境、执行压测、收集证据、得出结论。**

### 核心价值

| 维度 | 说明 |
|------|------|
| **意图驱动** | 用户描述意图，AI 调用 MCP Tools 逐步执行，无需手写复杂 YAML/JSON |
| **工具发现** | MCP Resources 机制让 AI 实时发现基础设施状态，避免基于静态知识推断 |
| **保守交互** | AI 仅作为向导，所有写操作需用户显式确认，保障基础设施安全 |
| **渐进增强** | MCP 作为 AI 交互的唯一协议，逐步替代旧有接口 |

### 目标用户

- 需要快速验证技术选型的开发者
- 进行 Spike 实验的技术团队
- 希望通过 AI 辅助提升 DevOps 效率的工程师

## 2. 技术栈

### 后端核心

| 技术 | 版本 | 用途 |
|------|------|------|
| **Spring Boot** | 3.x | 应用框架 |
| **WebFlux** | Reactor | 响应式非阻塞 I/O |
| **MCP SDK** | `mcp-server-spring-webflux` | AI 交互协议适配 |
| **PostgreSQL** | 15+ | 持久化存储（JSONB 支持动态 Schema） |
| **Docker Compose** | - | 环境编排（Phase 2） |

### 开发工具

| 工具 | 用途 |
|------|------|
| **Lombok** | 减少样板代码（禁止在实体类使用 `@Data`） |
| **MapStruct** | DTO 转换（编译时代码生成） |
| **SpringDoc OpenAPI 3.0** | API 文档自动生成 |
| **wrk / hey** | 压测工具（部署在 Loadgen Host） |

### AI 客户端兼容性

支持任何 MCP Client：**Claude Desktop**、**Trae**、**Kimi** 等。

## 3. DDD 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│                     接口层 (Interface)                       │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │              MCP Server (Adapter)                       │  │
│  │              Tool/Resource/Prompt 注册                   │  │
│  │              (AI 专用)                                  │  │
│  └─────────────────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│                     应用层 (Application)                      │
│  HostService │ EnvironmentService │ LoadgenService          │
│  TemplateLibrary │ ExperimentService │ EvidenceCollector    │
│  MonitoringService                                        │
├─────────────────────────────────────────────────────────────┤
│                      领域层 (Domain)                         │
│  ┌──────────┐ ┌────────────┐ ┌─────────────────┐           │
│  │   Host   │ │Environment │ │ExperimentSession│           │
│  │ (聚合根)  │ │ (聚合根)    │ │   (聚合根)       │           │
│  └──────────┘ └────────────┘ └─────────────────┘           │
│  ServiceTemplate │ Evidence │ Value Objects                 │
│  Domain Services: NetworkPathAnalyzer                      │
├─────────────────────────────────────────────────────────────┤
│                   基础设施层 (Infrastructure)                │
│  PostgreSQL │ DockerComposeProvider │ SshCommandExecutor    │
│  YamlHostRepository │ TemplateRepository                   │
└─────────────────────────────────────────────────────────────┘
```

### 层级职责

| 层级 | 包路径 | 职责 |
|------|--------|------|
| **接口层** | `interface` / `mcp` | 协议适配、参数校验、结果格式化 |
| **应用层** | `application` | 用例编排、事务边界、跨聚合协调 |
| **领域层** | `domain` | 业务规则、状态机、不变量保护 |
| **基础设施层** | `infrastructure` | 技术实现细节、外部系统集成 |

## 5. 设计原则速查表

| # | 原则 | 一句话说明 | 来源 |
|---|------|-----------|------|
| 1 | **保守交互** | AI 只向导不决策；每步写操作需用户确认 | ADR-MCP-002 |
| 2 | **原子工具** | 一 Tool 一职责，禁止粗粒度"一键完成"封装 | ADR-MCP-005 |
| 3 | **发现优先** | 先查只读 Resources 获取真实状态，再呈现选项 | ADR-MCP-002 |
| 4 | **角色分离** | MCP Host / Target Host / Loadgen Host 三者显式区分 | ADR-MCP-003 |
| 5 | **层次拓扑** | PVE → VM → Docker 父子关系必须表达 | ADR-MCP-004 |
| 6 | **网络感知** | 压测前分析网络路径，提示结果可信度 | ADR-MCP-006 |
| 7 | **响应式保持** | WebFlux 非阻塞，流式日志支持背压控制 | ADR-MCP-009 |
| 8 | **渐进改造** | MCP 作为 AI 交互的唯一协议 | ADR-MCP-010 |
| 9 | **聚合根优先** | Host / Environment / ExperimentSession 是核心业务实体 | DD-1, DD-2 |
| 10 | **插件化基础设施** | Docker Compose / K8s / Ansible 可互换 | DD-4 |

## 6. 四大聚合根

| 聚合根 | 身份标识 | 核心职责 | 状态数 |
|--------|---------|---------|--------|
| **Host** | `HostId` | 基础设施节点管理，角色与拓扑维护 | 3 |
| **Environment** | `EnvironmentId` | 运行空间生命周期与资源分配 | 6 |
| **ExperimentSession** | `SessionId` | 实验全流程管理与证据聚合 | 9 |
| **Evidence** | `EvidenceId` | 结构化证据存储与溯源 | - |
