# 领域模型

> V2 阶段领域模型：4 个聚合根 + 值对象 + 领域服务

## 1. 聚合根总览

| 聚合根 | 身份标识 | 核心职责 | 状态数 | 新增阶段 |
|--------|---------|---------|-------|---------|
| **Host** | `HostId` | 基础设施节点管理，角色与拓扑维护 | 3 | V2 新增 |

## 2. Host（主机节点）— 聚合根

**身份标识**: `HostId`

**核心职责**: 管理基础设施的物理/逻辑节点，维护角色、拓扑和能力声明。

### 2.1 领域模型

```java
package devops.dashboard.domain.host;

public class Host {
    private final HostId id;
    private final HostType type;              // PVE_HYPERVISOR, VM, BARE_METAL, LOCAL
    private final HostId parentId;            // null for root nodes
    private final String label;
    private final NetworkZone networkZone;    // 如 "lan-10.0.0"
    private final Set<Capability> capabilities; // DOCKER, NATIVE, VM
    private final Set<HostRole> roles;        // MCP_HOST, TARGET, LOADGEN
    private final ResourceCapacity resources;
    private final AccessInfo access;          // SSH 连接信息
    private final Set<LoadgenTool> loadgenTools; // 仅 LOADGEN 角色有效
    private final HostStatus status;
    private final Instant lastHeartbeat;

    public boolean isTarget() { return roles.contains(HostRole.TARGET); }
    public boolean isLoadgen() { return roles.contains(HostRole.LOADGEN); }
    public boolean isMcpHost() { return roles.contains(HostRole.MCP_HOST); }
    public boolean supportsDocker() { return capabilities.contains(Capability.DOCKER); }
    public boolean supportsNative() { return capabilities.contains(Capability.NATIVE); }
    public boolean hasParent(HostId candidate) { return candidate.equals(this.parentId); }
    public boolean isSibling(Host other) {
        if (this.parentId == null || other.parentId == null) return false;
        return this.parentId.equals(other.parentId);
    }
}
```

## 3. Environment（环境）— 聚合根

**身份标识**: `EnvironmentId`

**核心职责**: 管理运行空间的生命周期和资源分配。

### 3.1 领域模型（V2 增强）

```java
package devops.dashboard.domain.environment;

public class Environment {
    private final EnvironmentId id;
    private final HostId hostId;            // V2 新增：绑定到 Target Host
    private final EnvironmentType type;    // DEV, TEST, STAGING, EXPERIMENT
    private final RuntimeType runtime;      // V2 新增：DOCKER | NATIVE
    private final EnvironmentStatus status;
    private final List<ServiceInstance> services;
    private final ResourceQuota resourceQuota;
    private final LifecyclePolicy lifecyclePolicy;
    private final Map<String, Endpoint> accessEndpoints;

    public void markAsRunning() {
        validateTransition(EnvironmentStatus.RUNNING);
        this.status = EnvironmentStatus.RUNNING;
    }

    public void markAsStopped() {
        validateTransition(EnvironmentStatus.STOPPED);
        this.status = EnvironmentStatus.STOPPED;
    }

    public void destroy() {
        validateTransition(EnvironmentStatus.DESTROYED);
        this.status = EnvironmentStatus.DESTROYED;
    }
}
```

### 3.3 不变量

- 同一环境下服务端口不冲突
- 资源使用不超过配额
- 状态转移合法: `CREATING → RUNNING → STOPPED → DESTROYED`
- 必须关联到有效的 Target Host（V2）

## 4. ExperimentSession（实验会话）— 聚合根

**身份标识**: `SessionId`

**核心职责**: 管理一次用户与 AI 的实验交互全流程，聚合证据并得出结论。

> **V2 新增**: 替代 V1 的 `ExperimentRun`，增加了 Session 概念以支持多轮 AI 对话。

### 4.1 领域模型

```java
package devops.dashboard.domain.experiment;

public class ExperimentSession {
    private final SessionId id;
    private final String intent;               // 用户原始意图文本
    private final HostId targetHostId;         // 实验部署的目标 Host
    private final HostId loadgenHostId;        // 压测使用的 Host
    private final EnvironmentId environmentId;
    private final SessionStatus status;
    private final List<Evidence> evidenceLog;
    private final Conclusion conclusion;
    private final Instant createdAt;
    private final Instant archivedAt;

    public void addEvidence(Evidence evidence) {
        if (status == SessionStatus.ARCHIVED || status == SessionStatus.CONCLUDED) {
            throw new IllegalStateException("无法向已归档或已结束的会话添加证据");
        }
        this.evidenceLog.add(evidence);
    }

    public void conclude(Conclusion conclusion) {
        if (this.evidenceLog.isEmpty()) {
            throw new IllegalStateException("无证据无法得出结论");
        }
        this.conclusion = conclusion;
        this.status = SessionStatus.CONCLUDED;
    }

    public void archive() {
        if (status != SessionStatus.CONCLUDED) {
            throw new IllegalStateException("只能归档已结束的会话");
        }
        this.status = SessionStatus.ARCHIVED;
        this.archivedAt = Instant.now();
    }
}
```

### 4.2 枚举定义

## 5. Evidence（证据）— 聚合根

**身份标识**: `EvidenceId`

**核心职责**: 结构化存储实验过程中的各类证据，确保可追溯。

### 5.1 领域模型

```java

public class Evidence {
    private final EvidenceId id;
    private final EvidenceType type;
    private final String name;              // 如 "qps", "latency_p99", "health_check"
    private final String value;             // 原始值（字符串化）
    private final String unit;              // 单位
    private final EvidenceSource source;    // 来源
    private final HostId hostId;            // 关联主机（可选）

## 7. 非聚合根领域对象

### Pipeline（流程编排器）

**定位**: 不是聚合根，而是流程编排工具。

**组成**:
- Stage (阶段): Validate → Build → Deploy → Verify
- Step (步骤): 每个 Stage 内的具体操作
- Gate (门禁): automatic / manual_approval

**关键特性**: 支持条件执行、失败处理策略（abort/continue/retry）、超时控制

## 9. 设计约束总结

### 不变量规则

| 聚合根 | 不变量 | 校验时机 |
|--------|--------|---------|
| Host | parent_id 引用必须存在 | 创建/更新时 |
| Host | roles 与 capabilities 一致（LOADGEN → NATIVE） | 创建/更新时 |
| Environment | host_id 必须是 TARGET 角色 | 创建时 |
| Environment | runtime 与 host capabilities 匹配 | 创建时 |
| Environment | 服务端口不冲突 | 部署服务时 |
| Environment | 资源不超配额 | 创建/扩展时 |
| ExperimentSession | 结论前必须有证据 | conclude 时 |
| ExperimentSession | 只能归档已结束的会话 | archive 时 |

### 跨聚合引用规则

- ExperimentSession → Environment: 通过 `EnvironmentId` 引用（非持有对象）
- ExperimentSession → Host: 通过 `targetHostId` / `loadgenHostId` 引用
- Evidence → Environment / Session: 可选关联，确保可追溯
- **禁止**: 直接持有其他聚合根的对象引用

#### DeployPipeline — 编排聚合根

    private final PipelineStatus status;
    private final List<PipelineStage> stages;

    public Mono<PipelineResult> execute() { /* Saga 协调 */ }
    private Mono<PipelineResult> compensate(Throwable error) { /* 失败回滚 */ }

```

- **职责**: 作为 MCP 部署领域的【首选入口】，原子化编排 `env_create` → `env_deploy_service` → `test_health_check` → `analyze_network_path`
- **关键约束**: `serviceName` 必须在 `ServiceRegistry` 白名单中；失败时自动补偿清理

### 10.2 Environment 状态机精化

V3 将 V2 的 6 状态精化为新的 6 状态：

| V2 状态 | V3 状态 | 说明 |
|---------|---------|------|
| `CREATING` | `CREATING` | 不变 |
| `RUNNING` | `RUNNING` | 不变 |
| `STOPPED` | `DESTROYED` | 直接销毁，不再保留 STOPPED |
| `DESTROYED` | `DESTROYED` | 不变 |
| `FAILED` | `ERROR` | 统一为 ERROR |
| `NOT_FOUND` | — | 不作为状态，查询不存在时返回错误 |
| — | `READY` | **新增**: 环境就绪，允许部署 |
| — | `DEPLOYING` | **新增**: 部署锁定中 |

```
CREATING → READY → DEPLOYING → RUNNING → DESTROYED
              ↘        ↘           ↘
               ERROR ← ERROR ← ERROR
```
