## 2. 核心概念模型

### 2.1 Host（主机节点）

```java
public class Host {
    private final HostId id;
    private final HostType type;           // PVE_HYPERVISOR, VM, BARE_METAL, LOCAL
    private final HostId parentId;         // null if root
    private final String label;
    private final NetworkZone networkZone; // 如 "lan-10.0.0"
    private final Set<Capability> capabilities; // DOCKER, NATIVE, VM
    private final Set<HostRole> roles;     // MCP_HOST, TARGET, LOADGEN
    private final ResourceCapacity resources;
    private final AccessInfo access;       // SSH 连接信息
    private final Set<LoadgenTool> loadgenTools; // 仅 LOADGEN 角色有效
    private final HostStatus status;
}
```

**关键业务方法**:
- `isTarget()` / `isLoadgen()` / `isMcpHost()`: 角色判断
- `supportsDocker()` / `supportsNative()`: 能力判断
- `isSibling(Host other)`: 判断是否同宿主机（用于网络路径分析）

### 2.2 Environment（环境）— V2 增强

```java
public class Environment {
    private final EnvironmentId id;
    private final HostId hostId;           // V2 新增：明确归属哪个 Target Host
    private final EnvironmentType type;    // DEV, TEST, STAGING, EXPERIMENT
    private final RuntimeType runtime;     // V2 新增: DOCKER | NATIVE
    private final EnvironmentStatus status;
    private final List<ServiceInstance> services;
    private final ResourceQuota resourceQuota;
    private final LifecyclePolicy lifecyclePolicy;
    private final Map<String, Endpoint> accessEndpoints;
}
```

### 2.3 ExperimentSession（实验会话）— V2 新增

```java
public class ExperimentSession {
    private final SessionId id;
    private final String intent;           // 用户原始意图文本
    private final HostId targetHostId;     // 实验部署的目标 Host
    private final HostId loadgenHostId;    // 压测使用的 Host
    private final EnvironmentId environmentId;
    private final SessionStatus status;
    private final List<Evidence> evidenceLog;
    private final Conclusion conclusion;
    private final Instant createdAt;
    private final Instant archivedAt;
}
```

## 3. 标准实验流程数据流

以 **"验证 Nacos 单机 1000 QPS"** 为例：

```
用户: "我要验证 Nacos 单机 1000 QPS"
  │
  ▼
AI Client
  │ 1. 调用 Resource: hosts://topology
  │ 2. 调用 Resource: templates://list
  ▼
MCP Server 返回拓扑和模板
  │
  ▼
AI 向用户呈现选项：
  "可用 Target Host: [A] vm-fedora-dev [B] vm-ubuntu-test"
  "可用 Loadgen Host: [A] vm-loadgen-01"
  │
  ▼
用户: "选 B 作为 Target，A 作为 Loadgen"
  │
  ▼
AI 调用 Tool: analyze_network_path(source=vm-loadgen-01, target=vm-ubuntu-test)
  │
  ▼
AI 向用户提示："同 PVE 宿主机内通信，未过物理网卡，结果可能偏乐观"
  │
  ▼
用户: "确认，先这样测"
  │
  ▼
AI 调用 Tool: env_create(target_host_id=vm-ubuntu-test)
  │
  ▼
MCP Server → EnvironmentService.createFromSpec()
  │  校验 hostId 为 TARGET 角色
  │  校验 runtime 与 capabilities 匹配
  │  校验资源充足
  ▼
AI 调用 Tool: env_deploy_service(template=nacos-server)
  │
  ▼
AI 调用 Tool: env_deploy_service(template=mysql)
  │
  ▼
AI 调用 Tool: test_health_check(env_id=env-xxx)
  │
  ▼
AI 向用户汇报："环境就绪，Console: http://10.0.0.103:8848"
  │
  ▼
用户: "执行压测，100 连接 60 秒"
  │
  ▼
AI 调用 Tool: test_load(
    loadgen_host_id=vm-loadgen-01,
    target_url=http://10.0.0.103:8848/nacos/,
    connections=100,
    duration=60s
  )
  │
  ▼
MCP Server → LoadgenService → SSH 在 vm-loadgen-01 执行 wrk
  │
  ▼
AI 调用 Tool: test_collect_metrics(env_id=env-xxx)
  │
  ▼
AI 向用户呈现：
  ╔══════════════════════════════════════════════════╗
  ║  压测结果                                        ║
  ║  QPS: 1200 (目标 1000 ✅)                         ║
  ║  P99 Latency: 45ms                                ║
  ║  Error Rate: 0.01%                                 ║
  ╠══════════════════════════════════════════════════╣
  ║  资源指标 (Target Host)                            ║
  ║  CPU: 62% | Memory: 4.2GB/8GB | Network: 80Mbps   ║
  ╚══════════════════════════════════════════════════╝
  │
  ▼
用户: "提交结论 ACCEPT"
  │
  ▼
AI 调用 Tool: session_conclude(decision=ACCEPT, summary="Nacos 单机可支撑 1000+ QPS")
  │
  ▼
MCP Server → EvidenceCollector 归档证据 → Session 状态变为 CONCLUDED
```

### 错误处理数据流

```
test_health_check 失败
  │
  ▼
AI 调用 Tool: test_stream_logs(env_id, service_name=nacos-server, grep=ERROR)
  │
  ▼
AI 调用 Tool: test_exec_command(env_id, command="netstat -tlnp \| grep 8848")
  │
  ▼
AI 向用户汇报：
  "健康检查失败。发现端口 8848 已被占用（进程 PID 1234）。
   建议：
   [A] 销毁现有环境重新部署（自动选择新端口）
   [B] 手动释放端口后重试
   [C] 指定其他端口覆盖部署"
```

## 4. 部署架构

### 4.1 独立进程模式（推荐生产使用）

```
┌─────────────────┐     SSE/HTTP      ┌──────────────────────┐
│   AI Client     │ ◄──────────────► │  MCP Server          │
│ (Claude/Trae)   │   Port 8081      │  (Spring Boot +      │
│                 │                  │   WebFlux + MCP SDK) │
└─────────────────┘                  └──────────────────────┘
                                              │
                                              │ REST / RSocket
                                              ▼
                                       ┌──────────────────────┐
                                       │  DevOps Dashboard    │
                                       │  Core API            │
                                       │  Port 8080           │
                                       └──────────────────────┘
```

**特点**:
- MCP Server 与主应用分离，独立扩缩容
- 主应用故障不影响 MCP Server 的发现类功能
- 适合生产环境

### 4.2 同进程模式（简化开发部署）

```
┌─────────────────────────────────────────────────────────────┐
│              DevOps Dashboard Application                    │
│  ┌─────────────────┐                                        │
│  │  REST Controller│  ← /api/v1/* (现有前端/外部调用)        │
│  └─────────────────┘                                        │
│  ┌─────────────────┐                                        │
│  │  MCP Controller │  ← /mcp/sse (AI 专用)                  │
│  │  (MCP SDK)      │                                        │
│  └─────────────────┘                                        │
│  ┌───────────────────────────────────────────────────────┐  │
│  │              Service Layer (共享)                      │  │
│  │  HostService | EnvironmentService | LoadgenService ...  │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

**访问路径**:
- REST API: `http://host:8080/api/v1/*`
- MCP SSE: `http://host:8080/mcp/sse`

**特点**:
- 单 JVM 部署，简化运维
- 共享 Service Layer，减少网络开销
- 适合开发环境

## 5. 安全边界表

| 操作 | 是否需要确认 | 原因 | 危险等级 |
|------|-------------|------|---------|
| `hosts://topology` | 否 | 只读查询 | 🟢 安全 |
| `templates://list` | 否 | 只读查询 | 🟢 安全 |
| `env_create` | **是** | 占用 Target Host 资源 | 🟡 中等 |
| `env_deploy_service` | **是** | 变更端口/资源分配 | 🟡 中等 |
| `env_destroy` | **是 + 二次确认** | 不可逆，数据丢失 | 🔴 高危 |
| `test_health_check` | 否 | 只读探测 | 🟢 安全 |
| `test_functional` | 否 | 只读验证 | 🟢 安全 |
| `test_load` | **是** | 消耗目标端和压测端资源 | 🟡 中等 |
| `test_exec_command` | **是** | 任意命令执行风险 | 🔴 高危 |
| `test_stream_logs` | 否 | 只读日志流 | 🟢 安全 |
| `analyze_network_path` | 否 | 只读分析 | 🟢 安全 |
| `session_conclude` | 是 | 提交结论不可修改 | 🟡 中等 |
| `submit_evidence_note` | 否 | 数据录入 | 🟢 安全 |

### 命令执行安全策略

```yaml
# application-mcp.yml
devops:
  security:
    exec-command:
      allowed-patterns:
        - "^curl\\s+-s\\s+http://.*"
        - "^netstat\\s+-tlnp"
        - "^ps\\s+aux"
        - "^docker\\s+(logs|ps|inspect|stats)"
      blocked-patterns:
        - "rm\\s+-rf"
        - "mkfs"
        - ">\\s*/etc/"
        - "chmod\\s+777"
        - "\\|\\s*sh"
        - "\\$\\("
```

## 6. 与现有系统的边界

```
┌────────────────────────────────────────┐
│  MCP Server 层 (新增)                  │
│  • 负责:                               │
│    - MCP Protocol 适配                 │
│    - AI 交互逻辑                       │
│    - Host 拓扑管理                     │
│    - 参数校验与转换                    │
│                                        │
│  • 不直接操作:                         │
│    - Docker Daemon                    │
│    - 远程 SSH 命令                     │
│    - 数据库 CRUD                       │
└────────────────────────────────────────┘
              │
              │ 调用 Application Service
              ▼
┌────────────────────────────────────────┐
│  应用服务层 (现有 + 少量新增)           │
│                                        │
│  新增:                                 │
│  • HostService                        │
│  • LoadgenService                     │
│  • EvidenceCollector                  │
│                                        │
│  保持不变:                             │
│  • EnvironmentService                 │
│  • TemplateLibrary                    │
│  • MonitoringService                  │
│  • ExperimentService                  │
└────────────────────────────────────────┘
              │
              │ 调用 Repository / Provider
              ▼
┌────────────────────────────────────────┐
│  基础设施层 (完全不变)                  │
│                                        │
│  • PostgreSQL Repository              │
│  • DockerComposeProvider              │
│  • SshCommandExecutor                 │
│  • YamlHostRepository                 │
│  • TemplateRepository                 │
└────────────────────────────────────────┘
```

### 边界原则

| 层级 | 可以做什么 | 不能做什么 |
|------|-----------|-----------|
| **MCP Server** | 协议适配、参数校验、结果格式化、Prompt 管理 | 直接操作基础设施、直接访问数据库 |
| **Application Service** | 用例编排、事务边界、跨聚合协调 | 包含业务规则细节 |
| **Domain** | 业务规则、状态机、不变量保护 | 依赖框架/技术细节 |
| **Infrastructure** | 技术实现、外部系统集成 | 包含业务逻辑 |
