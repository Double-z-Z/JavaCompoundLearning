## 改造原则

### 核心设计理念

```
┌─────────────────────────────────────────────┐
│           渐进式增强，而非推倒重来            │
│                                             │
│   V1 (REST API) ──保持不变──→ 继续服务      │
│        │                                    │
│        ├── 新增 domain/host                  │
│        ├── 新增 application/host             │
│        ├── 新增 mcp/ 适配层                  │
│        │                                    │
│        ▼                                    │
│   V2 (MCP + REST) ──双轨运行──→ 增强能力    │
└─────────────────────────────────────────────┘
```

### 四大原则

| # | 原则 | 说明 | 示例 |
|---|------|------|------|
| 1 | **渐进式** | 不一次性推翻现有代码，按 Phase 逐步引入 MCP 能力 | Phase 1 只做只读 Resource，不做写操作 |
| 2 | **零侵入** | 现有 `domain`、`infrastructure` 包不修改，通过新增包和少量 Service 扩展实现 | Environment.java 仅增加 `hostId` 字段 |
| 3 | **双轨运行** | REST API 与 MCP Server 共存，前端和 AI 各自使用适合的接口 | 前端用 REST，AI 用 MCP |
| 4 | **可回滚** | 每个 Phase 都是独立的，如果 MCP 方案不适用，可以关闭 MCP Server 而不影响核心功能 | 删除 `mcp/` 包即可回滚 |

### 兼容性保证

- ✅ REST API 接口签名不变
- ✅ 数据库 Schema 向后兼容（仅新增字段）
- ✅ 现有单元测试全部通过
- ✅ 新增功能通过 Feature Flag 控制（可选）

#### 1. Host 领域模型

```java
// domain/host/Host.java
public class Host {
    private final HostId id;
    private final HostType type;                          // pve-hypervisor | vm | bare-metal | local
    private final HostId parentId;                         // 父节点 ID（PVE 为 null）
    private final String label;
    private final String networkZone;
    private final Set<Capability> capabilities;            // docker | native | vm
    private final Set<HostRole> roles;                     // mcp-host | target | loadgen
    private final Resources resources;                     // CPU/Memory
    private final HostAccess access;                       // SSH 连接信息
    private final Set<LoadgenTool> loadgenTools;           // wrk | hey | ab (仅 loadgen 角色)

    // 业务方法
    public boolean isTarget() { return roles.contains(HostRole.TARGET); }
    public boolean isLoadgen() { return roles.contains(HostRole.LOADGEN); }
    public boolean supportsDocker() { return capabilities.contains(Capability.DOCKER); }
    public boolean hasLoadgenTool(LoadgenTool tool) { return loadgenTools.contains(tool); }
}
```

#### 3. DevOpsMcpServer 入口

```java
// mcp/server/DevOpsMcpServer.java
@Configuration
@EnableMcpServer
public class DevOpsMcpServer {

    @Bean
    public McpServerFeatures serverFeatures() {
        return McpServerFeatures.builder()
            .experimentalFeatures(Map.of("host_topology", true))
            .build();
    }

    @Bean
    public List<McpTool> tools(
            DiscoveryHandler discoveryHandler,
            EnvironmentHandler envHandler,
            TestingHandler testingHandler,
            DiagnosisHandler diagnosisHandler,
            EvidenceHandler evidenceHandler) {
        
        return List.of(
            // Phase 1: 只注册发现类 Resource（在 DiscoveryHandler 中处理）
            // Phase 2+: 注册写操作 Tool
            envHandler.getCreateTool(),
            envHandler.getDeployServiceTool(),
            envHandler.getAccessTool(),
            envHandler.getDestroyTool(),
            testingHandler.getHealthCheckTool(),
            testingHandler.getFunctionalTool(),
            testingHandler.getLoadTool(),
            testingHandler.getCollectMetricsTool(),
            testingHandler.getStreamLogsTool(),
            testingHandler.getExecCommandTool(),
            diagnosisHandler.getAnalyzeNetworkPathTool(),
            evidenceHandler.getSessionCreateTool(),
            evidenceHandler.getSessionRecordEvidenceTool(),
            evidenceHandler.getSessionConcludeTool()
        );
    }

    @Bean
    public List<McpResource> resources(DiscoveryHandler discoveryHandler) {
        return List.of(
            discoveryHandler.getHostsTopology(),
            discoveryHandler.getTemplatesList()
            // envs://list 在运行时动态生成
        );
    }
}
```

```java
// application/service/impl/EnvironmentServiceImpl.java
@Service
public class EnvironmentServiceImpl implements EnvironmentService {

    private final EnvironmentRepository environmentRepository;
    private final HostRepository hostRepository;  // V2 新增注入
    private final EnvironmentProvisioner provisioner;

    @Override
    public Environment createFromSpec(EnvironmentSpec spec) {
        // ===== V2 新增：校验 Host =====
        if (spec.getHostId() != null) {
            Host host = hostRepository.findById(spec.getHostId())
                .orElseThrow(() -> new HostNotFoundException(spec.getHostId().value()));

            if (!host.isTarget()) {
                throw new InvalidHostRoleException(spec.getHostId().value(), "TARGET");
            }

            if (spec.getRuntime() == RuntimeType.DOCKER && !host.supportsDocker()) {
                throw new HostCapabilityMismatchException(spec.getHostId().value(), "DOCKER");
            }

            // 可选：资源可用性检查
            if (spec.getResourceQuota() != null) {
                int requiredCpu = parseCpu(spec.getResourceQuota().getCpuLimit());
                int requiredMem = parseMemory(spec.getResourceQuota().getMemoryLimit());
                if (!hostService.checkResourceAvailability(spec.getHostId(), requiredCpu, requiredMem)) {
                    throw new ResourceQuotaExceededException("Insufficient resources on host " + spec.getHostId());
                }
            }
        }
        // ===== V2 新增结束 =====

        // 原有创建逻辑继续...
        Environment environment = new Environment.Builder()
            .id(EnvironmentId.generate())
            .name(spec.getName())
            .type(spec.getType())
            .hostId(spec.getHostId())           // V2
            .runtime(spec.getRuntime())          // V2
            .resourceQuota(spec.getResourceQuota())
            .lifecyclePolicy(spec.getLifecyclePolicy())
            .status(EnvironmentStatus.CREATING)
            .createdAt(Instant.now())
            .build();

        return environmentRepository.save(environment);
    }
}
```

```java
// mcp/handler/EnvironmentHandler.java
@Component
public class EnvironmentHandler extends McpHandler {

    private final EnvironmentService environmentService;
    private final HostService hostService;
    private final TemplateService templateService;

    public McpTool getCreateTool() {
        return McpTool.builder()
            .name("env_create")
            .description("在指定的 Target Host 上创建一个新的空环境...")
            .inputSchema(JsonSchema.of(EnvCreateRequest.class))
            .handler(this::handleCreate)
            .build();
    }

    private Mono<McpCallToolResult> handleCreate(Map<String, Object> args) {
        EnvCreateRequest req = JsonUtils.fromMap(args, EnvCreateRequest.class);

        // 1. 校验 Target Host
        hostService.validateRole(HostId.of(req.getTargetHostId()), HostRole.TARGET);
        
        if (req.getRuntime() != null) {
            hostService.validateCapability(
                HostId.of(req.getTargetHostId()), 
                Capability.valueOf(req.getRuntime().toUpperCase())
            );
        }

        // 2. 构建 EnvironmentSpec
        EnvironmentSpec spec = EnvironmentSpec.builder()
            .name(req.getEnvName())
            .type(EnvironmentType.valueOf(req.getType()))
            .hostId(HostId.of(req.getTargetHostId()))
            .runtime(RuntimeType.valueOf(req.getRuntime() != null ? req.getRuntime() : "docker"))
            .resourceQuota(parseResourceLimit(req.getResourceLimit()))
            .lifecyclePolicy(LifecyclePolicy.autoDestroy(parseDuration(req.getAutoDestroyDuration())))
            .build();

        // 3. 调用服务层创建
        return handleAsync(environmentService.createFromSpec(spec)
            .map(env -> new EnvCreateResponse(
                env.getId().value(),
                env.getName(),
                env.getHostId().value(),
                hostService.getHostLabel(env.getHostId()),
                env.getStatus().name(),
                env.getRuntime().name(),
                env.getLifecyclePolicy().getAutoDestroyAt(),
                env.getCreatedAt()
            )));
    }

    // 其他 Tool 方法...
    public McpTool getDeployServiceTool() { /* ... */ }
    public McpTool getAccessTool() { /* ... */ }
    public McpTool getDestroyTool() { /* ... */ }
}
```

```java
    private final HostRepository hostRepository;
    private final SshCommandExecutor sshExecutor;  // 复用现有组件

    @Override

        Host host = hostRepository.findById(spec.getLoadgenHostId())
            .orElseThrow(() -> new HostNotFoundException(spec.getLoadgenHostId()));

        String command = buildCommand(spec);

        return sshExecutor.execute(
                host.getAccess(), 
                command, 
                spec.getDuration().plusSeconds(10)  // 额外缓冲时间
            )
            .map(this::parseOutput);
    }

    private String buildCommand(LoadTestSpec spec) {
        return switch (spec.getTool()) {
            case WRK -> buildWrkCommand(spec);
            case HEY -> buildHeyCommand(spec);
            case AB -> buildAbCommand(spec);
        };

            threads,
            spec.getConnections(),
            spec.getDuration().getSeconds(),
            spec.getMethod() == HttpMethod.POST ? "-s /tmp/post.lua" : "",
            spec.getTargetUrl()
        );
```

## 回滚方案

### 回滚触发条件

- MCP SDK 版本兼容性问题导致频繁崩溃
- AI 交互质量不达预期，用户反馈负面
- 安全审计发现无法接受的风险
- 性能开销过大影响主服务

### 回滚步骤

```
回滚操作（预计 10 分钟）:

1. 关闭 MCP Server
   ┌─────────────────────────────────────┐
   │ 方式 A: 配置关闭                     │
   │ # application-mcp.yml               │
   │ mcp:                                │
   │   server:                           │
   │     enabled: false                  │
   └─────────────────────────────────────┘
   
   ┌─────────────────────────────────────┐
   │ 方式 B: 移除模块（彻底回滚）          │
   │ rm -rf src/main/java/.../mcp/       │
   │ rm resources/application-mcp.yml    │
   │ rm resources/hosts.yml              │
   └─────────────────────────────────────┘

2. 清理依赖（如选择方式 B）
   # pom.xml
   <!-- 删除 mcp-server-spring-webflux -->

3. 重启应用
   mvn spring-boot:run
   
4. 验证
   - REST API 正常工作（端口 8080）
   - 端口 8081 已关闭
   - 所有现有功能不受影响
```

### 回滚影响评估

| 维度 | 影响 | 恢复时间 |
|------|------|---------|
| REST API | ❌ 无影响 | 0 分钟 |
| 数据库 | ❌ 无影响（未修改 Schema） | 0 分钟 |
| 现有环境 | ❌ 无影响 | 0 分钟 |
| Host 领域对象 | ⚠️ 可保留（对 REST 也有益） | 0 分钟 |
| MCP 功能 | ✅ 完全移除 | 10 分钟 |

**结论**: 回滚成本极低，风险可控。

| R7 | 并发环境创建导致端口冲突 | 中 | 中 | 端口分配器组件；冲突自动重试；端口池预分配 | Dev |

### 应急预案

#### R1: MCP SDK 严重 Bug

```
检测: 频繁 SSE 断连 / Tool 调用超时
响应:
1. 立即切换到 REST API 模式（前端降级）
2. 收集日志，提 Issue 到 MCP SDK 仓库
3. 如 24h 内无修复，临时回滚到 Phase 1 前
4. 评估替换方案（stdio 传输 / 自实现 HTTP bridge）
```

#### R4: AI 执行危险操作

```
检测: 未确认即销毁生产环境 / 执行 rm -rf
响应:
1. 立即停止 MCP Server
2. 从操作日志回溯具体 Tool 调用
3. 检查 Prompt 是否被绕过
4. 增强 Prompts 约束条件
5. 增加 double-confirm 机制（关键操作需两次确认）
```
