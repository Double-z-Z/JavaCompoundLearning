# 数据结构定义

本文档定义所有核心领域对象的完整数据结构（YAML Schema 格式），融合 V1 REST API 与 V2 MCP AI-Native 两代设计。

---

## 1. Host（主机节点）

Host 是基础设施的**物理/逻辑节点**，高于 Environment。V2 新增核心概念。

```yaml
host:
  # === 身份 ===
  id: string                    # "pve-01", "vm-fedora-dev"
  type: enum                    # PVE_HYPERVISOR | VM | BARE_METAL | LOCAL
  parent_id: string | null      # 父节点 ID，根节点为 null

  # === 描述 ===
  label: string                 # "PVE 虚拟化宿主机"
  network_zone: string          # "lan-10.0.0"

  # === 能力与角色 ===
  capabilities: []              # DOCKER, NATIVE, VM
  roles: []                     # MCP_HOST, TARGET, LOADGEN

  # === 资源容量 ===
  resources:
    cpu_total: int              # 核心数
    mem_total_mb: int           # 总内存 MB
    disk_total_gb: int          # 总磁盘 GB
    cpu_free: int               # 空闲核心数（动态更新）
    mem_free_mb: int            # 空闲内存 MB（动态更新）

  # === 访问信息 ===
  access:
    ssh_host: string            # "10.0.0.102"
    ssh_port: int               # 22
    user: string                # "dev"
    key_path: string            # "/home/dev/.ssh/id_rsa"
    password: string | null     # 备选，可空

  # === 压测工具（仅 LOADGEN 角色有效）===
  loadgen_tools: []             # WRK, HEY, AB, JMETER, K6

  # === 状态 ===
  status: enum                  # ONLINE | OFFLINE | UNKNOWN
  last_heartbeat: datetime
```

### 枚举定义

| 枚举 | 可选值 | 说明 |
|------|--------|------|
| `HostType` | `PVE_HYPERVISOR`, `VM`, `BARE_METAL`, `LOCAL` | 节点类型 |
| `HostRole` | `MCP_HOST`, `TARGET`, `LOADGEN` | 节点角色（可多选） |
| `Capability` | `DOCKER`, `NATIVE`, `VM` | 运行能力（可多选） |
| `HostStatus` | `ONLINE`, `OFFLINE`, `UNKNOWN` | 在线状态 |

### 角色与能力约束

| 角色 | 必须具备的能力 | 说明 |
|------|---------------|------|
| `MCP_HOST` | 无硬性要求 | 运行 MCP Server 进程的节点 |
| `TARGET` | `DOCKER` 或 `NATIVE` | 可部署环境/服务的节点 |
| `LOADGEN` | `NATIVE` | 可执行压测命令的节点 |

### 层次关系规则

- `PVE_HYPERVISOR` 节点的 `parent_id` 必须为 `null`
- `VM` 节点的 `parent_id` 必须指向一个 `PVE_HYPERVISOR`
- `BARE_METAL` / `LOCAL` 节点的 `parent_id` 必须为 `null`

## 2. Environment（环境）

Environment 显式绑定到 Target Host。V1 基础上增加 `hostId`、`runtime` 字段。

```yaml
environment:
  # === 身份与元数据 ===
  id: string                    # "env-20260517-nacos-dev"
  name: string                  # "Nacos开发环境"
  host_id: string               # V2新增：归属 Target Host ID
  created_at: datetime

  status: enum                  # CREATING | RUNNING | STOPPED | DESTROYED | FAILED

  access_endpoints:             # 创建后系统填充
    console_url: url
    api_url: url

  # === 规格说明 (值对象) ===
  spec:
    type: enum                  # DEV | TEST | STAGING | PROD | EXPERIMENT
    runtime: enum               # V2新增：DOCKER | NATIVE，默认 DOCKER

    target_nodes:[]             # 目标节点列表（V1 遗留，V2 以 host_id 为主）
      - node_id: string
        ip: string
        role: enum              # primary | secondary

    resource_quota:             # 资源配额
      cpu:
        request: string         # "500m"
        limit: string           # "2000m"
      memory:
        request: string         # "512Mi"
        limit: string           # "2Gi"

    lifecycle_policy:           # 生命周期策略
      auto_destroy: bool
      max_lifetime: duration    # "24h"
      idle_timeout: duration    # "2h"

  # === 网络配置 (值对象) ===
  network:
    mode: enum                  # bridge | host | overlay
    network_name: string

  # === 服务实例列表 (实体) ===
  services: []
    - instance_id: string
      service_template: string  # 引用模板名（如 nacos-server）

      status: enum              # PENDING | DEPLOYING | RUNNING | STOPPED | FAILED

      config:
        image: string
        ports: []               # container_port, host_port, protocol
        environment_variables: {}  # KEY=VALUE
        volumes: []             # source, destination, mode
        depends_on: []          # 依赖的服务名

        health_check:           # 健康检查
          endpoint: string
          initial_delay_seconds: int
          period_seconds: int
          timeout_seconds: int

      runtime:                  # 运行时信息（系统填充）
        container_id: string
        started_at: datetime
        resource_usage:
          cpu_percent: float
          memory_mb: int
        last_health_check:
          timestamp: datetime
          status: enum          # healthy | unhealthy
          response_time_ms: int
```

### RuntimeType 说明

| 值 | 说明 | 适用场景 |
|----|------|---------|
| `DOCKER` | 通过 Docker Compose / Docker API 部署 | 默认值，大多数中间件服务 |
| `NATIVE` | 直接在 Host 上运行进程（systemd、二进制） | 本地编译的应用、无容器化需求 |

### hostId 与 runtime 的校验规则

- `host_id` 必须指向一个存在的 Host，且该 Host 的 roles 包含 `TARGET`
- 当 `runtime=DOCKER` 时，目标 Host 的 capabilities 必须包含 `DOCKER`
- 当 `runtime=NATIVE` 时，目标 Host 的 capabilities 必须包含 `NATIVE`
- Environment 创建时会校验目标 Host 的资源是否充足（`canAccommodate`）

## 3. ExperimentSession（实验会话）

一次用户与 AI 的实验交互产生一个 Session，用于聚合证据。V2 替代 V1 的 ExperimentRun 概念。

```yaml
experiment_session:
  # === 身份 ===
  id: string                    # "sess-20260517-nacos-perf-001"
  intent: string                # 用户原始意图文本："验证 Nacos 单机 1000 QPS"

  # === 关联资源 ===
  target_host_id: string        # 实验部署的目标 Host ID
  loadgen_host_id: string       # 压测使用的 Host ID
  environment_id: string        # 关联的环境 ID

  # === 状态 ===
  status: enum                  # 见下方 SessionStatus 枚举

  # === 证据日志 ===
  evidence_log: []              # Evidence 对象列表（见第 5 节）

  # === 结论 ===
  conclusion:
    decision: enum              # ACCEPT | REJECT | NEED_MORE_DATA | INCONCLUSIVE
    summary: text               # 结论摘要
    lessons_learned: []         # 经验教训
    next_steps: []              # 后续行动

  # === 时间戳 ===
  created_at: datetime
  archived_at: datetime | null
```

### SessionStatus 状态枚举

| 状态 | 说明 |
|------|------|
| `PLANNING` | 用户与 AI 对话规划中 |
| `PROVISIONING` | 创建环境中 |
| `DEPLOYING` | 部署服务中 |
| `VERIFYING` | 功能验证中 |
| `LOAD_TESTING` | 压测中 |
| `COLLECTING` | 收集证据中 |
| `CONCLUDED` | 已提交结论 |
| `ARCHIVED` | 已归档 |

## 4. Evidence（证据）

统一收集、结构化存储实验过程中的各类证据。V2 新增领域模型。

```yaml
evidence:
  # === 身份 ===
  id: string                    # "evi-20260517-qps-001"

  # === 分类 ===
  type: enum                    # METRIC | ARTIFACT | OBSERVATION | CHECK_RESULT
  name: string                  # "throughput_qps", "latency_p99", "health_check"
  value: string                 # 原始值（字符串化）："1280.5", "12.3ms"
  unit: string                  # "qps", "ms", "%", ""

  # === 来源 ===
  source: enum                  # LOAD_TEST_TOOL | MONITORING_AGENT | HEALTH_CHECK | FUNCTIONAL_TEST | MANUAL_INPUT | COMMAND_EXEC

  # === 关联 ===
  host_id: string | null        # 关联主机（可选）
  environment_id: string | null # 关联环境（可选）
  session_id: string            # 所属实验会话

  # === 元数据 ===
  collected_at: datetime
  metadata: {}                  # 扩展字段，自由键值对
```

### EvidenceType 枚举

| 类型 | value 示例 | unit 示例 | 典型来源 |
|------|-----------|-----------|---------|
| `METRIC` | `"1280.5"` | `"qps"`, `"ms"`, `"%"` | wrk 输出解析、Prometheus 查询 |
| `ARTIFACT` | `"/logs/nacos-error.log"` | - | 日志文件路径、截图路径 |
| `OBSERVATION` | `"控制台显示注册成功但 API 返回 500"` | - | 用户手动记录 |
| `CHECK_RESULT` | `"passed"` / `"failed"` | - | HTTP 健康检查、功能测试脚本 |

### EvidenceSource 枚举

| 来源 | 说明 |
|------|------|
| `LOAD_TEST_TOOL` | wrk/hey/ab/jmeter/k6 输出解析 |
| `MONITORING_AGENT` | Prometheus/cAdvisor 指标采集 |
| `HEALTH_CHECK` | HTTP 健康检查端点探测 |
| `FUNCTIONAL_TEST` | 功能测试脚本执行结果 |
| `MANUAL_INPUT` | 用户手动输入的观察或结论 |
| `COMMAND_EXEC` | 远程命令执行（exec_command）的结果 |

## 5. LoadTestSpec / LoadTestResult（压测规格与结果）

V2 新增，用于结构化管理远程压测。

### LoadTestSpec（压测规格）

```yaml
load_test_spec:
  loadgen_host_id: string       # 压测端 Host ID（必须为 LOADGEN 角色）
  target_url: string            # 被测 URL："http://10.0.0.103:8848/nacos/v1/ns/instance/list"
  method: enum                 # GET | POST | PUT | DELETE
  tool: enum                   # WRK | HEY | AB | JMETER | K6
  duration: duration           # "60s"
  connections: int             # 100
  rps_limit: int | null        # 可选限速（每秒请求数）
  payload: string | null       # POST body（可选）
  headers: {}                  # 自定义请求头
```

### LoadTestResult（压测结果）

```yaml
load_test_result:
  total_requests: long         # 总请求数
  avg_qps: double              # 平均 QPS
  avg_latency_ms: double       # 平均延迟 ms
  p50_latency_ms: double       # P50 延迟 ms
  p99_latency_ms: double       # P99 延迟 ms
  error_rate_percent: double   # 错误率 %
  raw_output: {}               # 原始命令输出（键值对），供人工复查
```

## 6. NetworkPath（网络路径分析结果）

V2 新增，用于分析压测机到目标机的网络拓扑。

```yaml
network_path:
  source_id: string            # 源 Host ID
  target_id: string            # 目标 Host ID
  target_port: int             # 目标端口

  path_type: enum              # SAME_HOST | SAME_HYPERVISOR | SAME_LAN | WAN
  estimated_hops: int          # 估计跳数
  estimated_rtt_ms: double     # 估计往返延迟 ms
  goes_through_bridge: bool    # 是否经过网桥
  physical_nic_involved: bool  # 是否经过物理网卡
  warning: string | null       # 可信度提示（如 "同宿主机内通信，未过物理网卡"）
```

### PathType 枚举与特征

| PathType | 显示名 | 典型 RTT | 物理网卡 | 说明 |
|----------|--------|----------|---------|------|
| `SAME_HOST` | 同机 | <0.1ms | 否 | 源和目标是同一台机器 |
| `SAME_HYPERVISOR` | 同虚拟化宿主机 | ~0.1-1ms | 否 | 同一 PVE 下的不同 VM |
| `SAME_LAN` | 同局域网 | ~0.1-1ms | 是 | 同一交换机/网段 |
| `WAN` | 跨网络 | >1ms | 是 | 跨网段或跨公网 |

## 7. Pipeline 结构（V1 遗留）

```yaml
pipeline:
  id: string
  name: string                  # "Nacos标准部署流水线"

  trigger:
    type: enum                  # manual | webhook | scheduled

  stages: []                    # 阶段列表（有序）
    - stage_id: string
      name: string              # "前置校验"
      order: int                # 执行顺序
      gate_type: enum           # automatic | manual_approval

      approval_config:          # 仅 manual_approval 时有效
        required_approvers: int
        timeout_minutes: int
        auto_reject_on_timeout: bool

      steps: []                 # 步骤列表
        - step_id: string
          name: string          # "Maven单元测试"
          action: enum          # maven_test | docker_build | deploy | health_check | ...

          config: {}            # action-specific 配置

          timeout_seconds: int

          success_criteria: {}
            exit_code: int
            test_pass_rate: int # %

          on_failure: enum      # abort_pipeline | continue | retry
```

## 8. 状态机约束

### Environment 状态转移

```
CREATING ──→ RUNNING ──→ STOPPED ──→ DESTROYED
   │           │           │
   ↓           ↓           ↓
 FAILED      FAILED      FAILED
```

**合法转移**:

| 当前状态 | 可转移到 | 说明 |
|---------|---------|------|
| `CREATING` | `RUNNING`, `FAILED` | 创建完成或失败 |
| `RUNNING` | `STOPPED`, `FAILED` | 手动停止或异常 |
| `STOPPED` | `RUNNING`, `DESTROYED`, `FAILED` | 重启、销毁或销毁失败 |
| `DESTROYED` | — | 终态，不可转移 |
| `FAILED` | `RUNNING`, `DESTROYED` | 重试恢复或强制销毁 |

### ExperimentSession 状态转移

```
PLANNING ──→ PROVISIONING ──→ DEPLOYING ──→ VERIFYING ──→ LOAD_TESTING ──→ COLLECTING ──→ CONCLUDED ──→ ARCHIVED
   │            │              │             │              │               │              │
   ↓            ↓              ↓             ↓              ↓               ↓              ↓
(均可取消)   CANCELLED      CANCELLED    CANCELLED      CANCELLED      CANCELLED      CANCELLED
```

**关键规则**:
- 任何非终态都可 `CANCELLED`
- `ARCHIVED` 为终态
- `CONCLUDED` 之后必须经用户确认才能进入 `ARCHIVED`

### Experiment（V1 遗留）状态转移

```
PLANNING ──→ RUNNING ──→ COMPLETED ──→ ARCHIVED
   │           │           │
   ↓           ↓           ↓
 CANCELLED  CANCELLED   CANCELLED
```

## 9. 默认值参考表

### 环境生命周期默认值

| 配置项 | 个人模式默认值 | 企业模式默认值 | 实验模式固定值 |
|--------|--------------|---------------|--------------|
| max_lifetime | 24h | 永久（手动销毁） | 2h |
| idle_timeout | 2h | 不启用 | 不启用 |
| auto_destroy | false | false | true |
| runtime | DOCKER | DOCKER | DOCKER |

### 健康检查默认值

| 配置项 | 默认值 | 说明 |
|--------|-------|------|
| interval（period_seconds） | 10s（个人）/ 30s（企业） | 检查间隔 |
| initial_delay_seconds | 因服务而异 | 见各服务模板 |
| timeout_seconds | 5s | 单次超时 |

### 流水线默认值

| 配置项 | 个人模式默认值 | 企业模式默认值 |
|--------|--------------|---------------|
| gate_type | automatic | manual_approval |
| auto_reject_on_timeout | false | true |
| on_failure（step） | abort_pipeline | continue |

### 资源配额建议

| 环境类型 | CPU request | CPU limit | Memory request | Memory limit |
|---------|------------|----------|---------------|-------------|
| DEV | 250m | 1000m | 256Mi | 1Gi |
| TEST | 500m | 2000m | 512Mi | 2Gi |
| EXPERIMENT | 500m | 2000m | 512Mi | 2Gi |
| STAGING | 1000m | 4000m | 1Gi | 4Gi |
| PROD | 按需评估 | 按需评估 | 按需评估 | 按需评估 |
