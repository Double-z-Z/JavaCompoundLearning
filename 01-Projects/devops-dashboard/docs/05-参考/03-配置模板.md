# 配置模板

本文档汇总 DevOps Dashboard 项目所有配置文件的完整模板，融合 V1 与 V2 设计。每个配置文件只出现一次，去重合并。

---

## 1. hosts.yml — 主机拓扑注册表

**文件位置**: `src/main/resources/hosts.yml`

声明你的基础设施拓扑：PVE 宿主机 → 虚拟机层次结构，以及每台机器的角色、能力、SSH 访问信息。

```yaml
# ============================================
# DevOps Dashboard — 主机拓扑配置
# ============================================
# 说明:
#   - type: pve-hypervisor(宿主机) | vm(虚拟机) | bare-metal(裸金属) | local(本机)
#   - roles: mcp-host(运行MCP Server) | target(可部署环境) | loadgen(可压测)，可多选
#   - capabilities: docker | native | vm，可多选
#   - parent: 父节点 ID，仅 VM 类型需要指定
# ============================================

hosts:
  # ===== PVE 虚拟化宿主机 =====
  - id: pve-01
    type: pve-hypervisor
    label: "PVE 虚拟化宿主机"
    network_zone: lan-10.0.0
    capabilities: [vm]
    roles: []
    resources:
      cpu_total: 32
      mem_total_mb: 128000

  # ===== Fedora 开发环境 (MCP Server 运行于此) =====
  - id: vm-fedora-dev
    type: vm
    parent: pve-01
    label: "Fedora 开发环境 (MCP Server 运行于此)"
    network_zone: lan-10.0.0
    capabilities: [docker, native]
    roles: [mcp-host, target]
    resources:
      cpu_total: 8
      cpu_free: 6
      mem_total_mb: 16384
      mem_free_mb: 12000
    access:
      ssh: 10.0.0.102
      port: 22
      user: dev
      key_path: /home/dev/.ssh/id_rsa

  # ===== Ubuntu 测试环境 =====
  - id: vm-ubuntu-test
    type: vm
    parent: pve-01
    label: "Ubuntu 测试环境"
    network_zone: lan-10.0.0
    capabilities: [docker, native]
    roles: [target]
    resources:
      cpu_total: 4
      cpu_free: 3
      mem_total_mb: 8192
      mem_free_mb: 6144
    access:
      ssh: 10.0.0.103
      port: 22
      user: test
      key_path: /home/dev/.ssh/id_rsa

  # ===== 专用压测机 =====
  - id: vm-loadgen-01
    type: vm
    parent: pve-01
    label: "专用压测机"
    network_zone: lan-10.0.0
    capabilities: [native]
    roles: [loadgen]
    resources:
      cpu_total: 8
      cpu_free: 8
      mem_total_mb: 8192
      mem_free_mb: 8192
    access:
      ssh: 10.0.0.104
      port: 22
      user: loadgen
      key_path: /home/dev/.ssh/id_rsa
    loadgen_tools: [wrk, hey, ab]
```

### 配置要点

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | 全局唯一标识符 |
| `type` | ✅ | 节点类型 |
| `parent` | 仅 VM | 指向 PVE_HYPERVISOR 的 ID |
| `roles` | ✅ | 至少一个角色（空数组仅限宿主机） |
| `capabilities` | ✅ | 必须与 roles 匹配（LOADGEN → NATIVE, TARGET → DOCKER/NATIVE） |
| `access` | 非 LOCAL | SSH 连接信息 |
| `loadgen_tools` | LOADGEN 角色 | 已安装的压测工具列表 |

### 校验规则

- `parent` 引用的 ID 必须存在于 hosts 列表中
- VM 节点的 `parent` 必须指向 `PVE_HYPERVISOR` 类型节点
- `roles` 包含 `TARGET` 时，`capabilities` 必须包含 `DOCKER` 或 `NATIVE`
- `roles` 包含 `LOADGEN` 时，`capabilities` 必须包含 `NATIVE`
- `loadgen_tools` 仅在 `roles` 包含 `LOADGEN` 时有效

## 2. application-mcp.yml — MCP Server 配置

**文件位置**: `src/main/resources/application-mcp.yml`

控制 MCP Server 的传输方式、端口、安全策略和主机拓扑加载。

```yaml
# ============================================
# DevOps Dashboard MCP Server 配置
# ============================================

server:
  port: 8081                  # MCP Server 独立端口，避免与主应用 REST API (8080) 冲突

spring:
  application:
    name: devops-mcp-server
  profiles:
    active: mcp               # 激活 mcp profile

# ============================================
# MCP 协议配置
# ============================================
mcp:
  server:
    enabled: true             # 总开关，设为 false 可完全禁用 MCP Server
    transport: sse            # 传输方式: sse | stdio | http
    path: /mcp/sse            # SSE 端点路径

    # 可选：简单认证保护（生产环境建议启用）
    # auth:
    #   type: bearer
    #   token: your-secret-token-here

# ============================================
# DevOps 基础设施配置
# ============================================
devops:
  hosts:
    config-path: classpath:hosts.yml       # 主机拓扑配置文件路径
    refresh-interval: 60s                   # 动态刷新拓扑间隔

  # 可选：限制 MCP 可执行的危险命令白名单/黑名单
  security:
    exec-command:
      allowed-patterns:
        - "^curl\\s+-s\\s+http://.*"       # 允许 curl 诊断
        - "^netstat\\s+-tlnp"              # 允许 netstat
        - "^ps\\s+aux"                     # 允许 ps
        - "^docker\\s+(ps|logs|inspect)"   # 允许 Docker 只读命令
        - "^java\\s+-version"              # 允许 Java 版本检查
      blocked-patterns:
        - "rm\\s+-rf"                      # 禁止递归删除
        - "mkfs"                            # 禁止格式化
        - ">\\s*/etc/"                      # 禁止写系统文件
        - "chmod\\s+777"                    # 禁止开放权限
        - "shutdown\\s+"                    # 禁止关机
        - "reboot"                          # 禁止重启

# ============================================
# 日志配置
# ============================================
logging:
  level:
    devops.dashboard.mcp: DEBUG            # MCP 层详细日志（调试时开启）
    io.modelcontextprotocol: INFO           # MCP SDK 日志
    root: WARN                              # 其他日志保持简洁
```

### 传输方式对比

| transport | 适用场景 | 端口 | 说明 |
|-----------|---------|------|------|
| `sse` | 远程连接（推荐） | 8081 | Trae/Claude Desktop 通过 HTTP SSE 连接，无需本地 Java 环境 |
| `stdio` | 本地进程嵌入 | 无 | MCP Server 作为子进程运行，通过标准输入输出通信 |
| `http` | 自定义集成 | 8081 | 原始 HTTP 接口，适合自定义客户端 |

## 3. Claude Desktop 配置

**文件位置**:
- macOS/Linux: `~/.config/claude/config.json`
- Windows: `%APPDATA%\Claude\config.json`

```json
{
  "mcpServers": {
    "devops-dashboard": {
      "url": "http://10.0.0.102:8081/mcp/sse",
      "env": {
        "DEVOPS_API_BASE": "http://10.0.0.102:8080"
      }
    }
  }
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `url` | ✅ | MCP SSE 端点完整 URL |
| `env` | ❌ | 传递给 MCP Server 的环境变量（可选） |

> **注意**: 如果 MCP Server 启用了 Bearer 认证，需在请求头中携带 Token。Claude Desktop 目前不原生支持自定义 headers，可通过 Nginx 反向代理注入。

## 4. Trae 配置

**配置方式**: Trae IDE 设置 → MCP 面板 → 手动添加

### 方式一：全局配置（推荐）

在 Trae MCP 面板中添加：

```json
{
  "mcpServers": {
    "devops-dashboard": {
      "type": "sse",
      "url": "http://10.0.0.102:8081/mcp/sse",
      "headers": {
        "Authorization": "Bearer optional-token-if-you-add-auth"
      }
    }
  }
}
```

### 方式二：项目级配置

**文件位置**: 项目根目录 `.trae/mcp.json`

```json
{
  "mcpServers": {
    "devops-dashboard": {
      "type": "sse",
      "url": "http://10.0.0.102:8081/mcp/sse"
    }
  }
}
```

项目级 MCP 会随项目代码版本控制，打开项目时自动加载。修改后需在 MCP 面板点击「刷新」。

## 5. systemd Service 文件模板（生产环境）

**文件位置**: `/etc/systemd/system/devops-mcp.service`

用于生产环境管理 MCP Server 进程的自动启停、崩溃重启。

```ini
[Unit]
Description=DevOps Dashboard MCP Server
Documentation=https://your-docs-url
After=network.target docker.service
Wants=docker.service

[Service]
Type=simple
User=dev
Group=dev

WorkingDirectory=/home/dev/devops-dashboard

ExecStart=/usr/bin/java \
  -Dspring.profiles.active=mcp \
  -Dserver.port=8081 \
  -Xms512m \
  -Xmx1024m \
  -jar /home/dev/devops-dashboard/target/devops-dashboard-0.0.1-SNAPSHOT.jar

Restart=always
RestartSec=10

StandardOutput=journal
StandardError=journal
SyslogIdentifier=devops-mcp

# 安全加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/home/dev/devops-dashboard/logs

# 资源限制
LimitNOFILE=65536
MemoryMax=2G

[Install]
WantedBy=multi-user.target
```

### 使用方法

```bash
# 安装并启用
sudo systemctl daemon-reload
sudo systemctl enable devops-mcp
sudo systemctl start devops-mcp

# 查看状态
sudo systemctl status devops-mcp

# 查看日志
journalctl -u devops-mcp -f

# 停止/重启
sudo systemctl stop devops-mcp
sudo systemctl restart devops-mcp
```

## 6. Nginx 反向代理配置（可选）

**适用场景**: 统一入口、域名访问、HTTPS 终结、认证注入

**文件位置**: `/etc/nginx/conf.d/devops-mcp.conf`

```nginx
# ============================================
# DevOps Dashboard MCP Server — Nginx 反向代理
# ============================================
# 前提: sudo apt install nginx (或 yum install nginx)
# ============================================

upstream devops_mcp_backend {
    server 10.0.0.102:8081;
    keepalive 32;
}

server {
    listen 80;
    server_name devops.local;

    # SSE 端点代理（核心配置）
    location /mcp/sse {
        proxy_pass http://devops_mcp_backend/mcp/sse;

        # SSE 必须配置
        proxy_http_version 1.1;
        proxy_set_header Connection '';
        proxy_set_header X-Accel-Buffering no;

        # 禁用缓冲和缓存
        proxy_buffering off;
        proxy_cache off;

        # 长连接超时（SSE 是持久连接）
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;

        # 传递真实 IP
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 可选：注入 Bearer Token
        # proxy_set_header Authorization "Bearer your-secret-token";
    }

    # 健康检查端点
    location /actuator/health {
        proxy_pass http://devops_mcp_backend/actuator/health;
        proxy_set_header Host $host;
    }

    # 默认拒绝其他路径
    location / {
        return 404;
    }

    # 访问日志
    access_log /var/log/nginx/devops-mcp.access.log;
    error_log /var/log/nginx/devops-mcp.error.log;
}
```

### 使用 Nginx 后的 AI 客户端配置变更

Trae / Claude Desktop 中的 URL 改为：

```json
{
  "mcpServers": {
    "devops-dashboard": {
      "type": "sse",
      "url": "http://devops.local/mcp/sse"
    }
  }
}
```

### HTTPS 配置（可选，使用 Let's Encrypt）

```bash
# 安装 certbot
sudo apt install certbot python3-certbot-nginx

# 自动获取证书并配置
sudo certbot --nginx -d devops.local

# 自动续期（certbot 已自动添加 cronjob）
sudo certbot renew --dry-run
```

## 配置文件速查表

| 文件 | 用途 | 修改频率 |
|------|------|---------|
| `hosts.yml` | 声明主机拓扑 | 低（新增/移除节点时） |
| `application-mcp.yml` | MCP Server 行为控制 | 中（调优安全策略/日志级别时） |
| `~/.config/claude/config.json` | Claude Desktop 连接配置 | 低（首次配置后） |
| `.trae/mcp.json` | Trae 项目级 MCP 配置 | 低（首次配置后） |
| `/etc/systemd/system/devops-mcp.service` | 生产环境进程管理 | 极低（部署时一次性） |
| `/etc/nginx/conf.d/devops-mcp.conf` | 反向代理 + HTTPS | 极低（部署时一次性） |
