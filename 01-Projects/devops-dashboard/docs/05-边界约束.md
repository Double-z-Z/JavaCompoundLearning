# 边界约束规范

> **用途**: 定义 MCP Tool 的 description 编写规范、错误响应格式、状态机约束与参数校验规则。
> **前置阅读**: [00-术语表.md](../00-术语表.md)

---

## 1. Description 三段式规范

### 1.1 模板

```markdown
【角色标签】功能一句话。
技术价值一句话（为什么必须走我）。
错误示例：❌ 禁止 ... 这将导致 ...
```

### 1.2 角色标签

| 标签 | 用途 | 示例工具 |
|------|------|---------|
| `【首选入口】` | 高层编排聚合根，AI 应该优先调用 | `deploy_pipeline` |
| `【唯一入口】` | 不可替代，所有同类操作必须经过此 | `env_create`, `env_get_logs`, `test_exec_command` |
| `【唯一合法】` | 审计类工具，本地替代会导致结果失真 | `test_health_check`, `test_load`, `analyze_network_path` |

### 1.3 示例

**env_create**:
```
【唯一入口】在远程宿主机上创建隔离的部署环境。
所有环境生命周期必须通过此工具管理，以确保网络策略、资源配额、监控探针和 DNS 记录被正确注入。
错误示例：❌ 禁止本地执行 'docker run -d redis'，这将绕过网络隔离，导致后续 analyze_network_path 无法追踪流量路径，且不会被服务发现注册。
```

**test_load**:
```
【唯一合法】对 MCP 管理的服务执行负载测试（wrk / hey / ab）。
测试端由 MCP 宿主机调度，确保压测流量经过正确的网络路径和防火墙规则。
错误示例：❌ 禁止在本地笔记本直接执行 wrk，以避免跨网络延迟干扰和带宽瓶颈导致的测试结果失真。
```

## 2. 错误响应规范

### 2.1 格式

```json
{
  "isError": true,
  "content": [
    {
      "type": "text",
      "text": "{\"error\":{\"code\":-32000,\"message\":\"...\",\"data\":{...}}}"
    }
  ]
}
```

### 2.2 data 字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | integer | 是 | 错误码，统一为整数 |
| `message` | string | 是 | 业务错误简述 |
| `currentStatus` | string | 条件 | 状态机错误时必填，当前对象状态 |
| `requiredStatus` | string | 条件 | 状态机错误时必填，期望状态 |
| `suggestion` | string | 是 | 人可读的错误解释和修复建议 |
| `forbidden` | string | **关键** | 明确否定本地替代方案，形成心理锚点 |
| `nextSteps` | string[] | **关键** | 合法的 MCP Tool 回退路径 |

### 2.3 设计意图

- **封堵绕过**: `forbidden` 直接在 AI 上下文中否定本地操作
- **引导回退**: `nextSteps` 告诉 AI "你应该调用这些 Tools"，而不是自行解决
- **一致性**: 所有错误统一格式，便于 AI Client 解析和呈现

### 2.4 示例

**状态机错误**:
```json
{
  "error": {
    "code": -32000,
    "message": "当前状态为 CREATING，不允许 DEPLOYING 操作",
    "data": {
      "currentStatus": "CREATING",
      "requiredStatus": "READY",
      "suggestion": "等待 env_create 完成，或调用 env_list 确认状态",
      "forbidden": "禁止通过 SSH 进入容器手动部署",
      "nextSteps": ["调用 env_list 查看当前状态", "调用 env_get_logs 查看初始化进度"]
    }
  }
}
```

**服务未注册**:
```json
{
  "error": {
    "code": -32000,
    "message": "服务 'unknown-service' 未在 MCP 目录注册",
    "data": {
      "availableServices": ["redis-counter-service", "devops-dashboard", "mcp-host-agent", "redis-cache"],
      "forbidden": "禁止部署未注册服务",
      "nextSteps": ["调用 env_list 查看已部署服务", "联系管理员注册新服务"]
    }
  }
}
```

## 3. 状态机约束

### 3.1 Environment 状态转换

```
CREATING  → READY | ERROR
READY     → DEPLOYING | DESTROYED
DEPLOYING → RUNNING | ERROR
RUNNING   → DESTROYED | DEPLOYING (覆盖部署)
ERROR     → DESTROYED | READY (修复后)
DESTROYED → (终态)
```

### 3.2 状态与 Tool 的对应关系

| 状态 | 允许调用的 Tools | 禁止调用的 Tools |
|------|-----------------|-----------------|
| `CREATING` | `env_get_logs` | `env_deploy_service`, `test_health_check`, `test_load` |
| `READY` | `env_deploy_service`, `env_destroy`, `env_get_logs` | `test_health_check`, `test_load` |
| `DEPLOYING` | `env_get_logs` | `env_deploy_service`（并发部署被锁） |
| `RUNNING` | `test_*`, `env_get_logs`, `env_destroy`, `env_deploy_service`（覆盖） | 无 |
| `ERROR` | `env_get_logs`, `env_destroy` | `env_deploy_service`（需先修复到 READY） |
| `DESTROYED` | 无 | 全部 |

### 3.3 并发控制

状态转换时必须加分布式锁，防止 AI 并发调用导致竞态：

```java
public Mono<Void> deployWithLock(EnvironmentId envId) {
    return lockService.acquire("env:" + envId.value(), Duration.ofSeconds(30))
        .flatMap(lock -> {
            Environment env = repository.findById(envId);
            env.validateTransition(DEPLOYING);
            env.transitionTo(DEPLOYING);
            return repository.save(env)
                .doFinally(signal -> lockService.release(lock));
        });
}
```

## 4. 参数校验规则

### 4.1 通用规则

| 参数类型 | 校验要求 | 示例 |
|---------|---------|------|
| ID 类 | 必须存在于对应数据源 | `envId` 必须在 `env_list` 中 |
| 枚举类 | 必须匹配预定义 enum 值 | `isolationType` ∈ [docker, native] |
| 版本类 | 给出格式示例，但不做严格校验 | `1.0-SNAPSHOT`, `latest` |
| ID 格式 | 只允许 `[a-z0-9-]` | `redis-counter-tomcat` |

### 4.2 数据源约束

每个参数描述必须包含"数据源指向"：

```json
{
  "hostId": {
    "type": "string",
    "description": "目标宿主机 ID，必须来自 env_list 返回的 availableHosts 列表中的 id 字段"
  },
  "envId": {
    "type": "string",
    "description": "目标环境 ID，必须来自 env_create 返回的 envId 字段"
  }
}
```

### 4.3 服务目录白名单

`env_deploy_service` 的 `serviceName` 必须在 `ServiceRegistry` 中注册：

```java
Set<String> serviceRegistry = Set.of(
    "redis-counter-service",
    "devops-dashboard",
    "mcp-host-agent",
    "redis-cache"
);
```

白名单与 `tools/list` 返回的 `serviceName` enum 必须同步。

## 5. Pipeline Saga 补偿规则

| 失败步骤 | 已完成的步骤 | 补偿操作 |
|---------|-------------|---------|
| env_create 失败 | 无 | 无 |
| env_deploy_service 失败 | env_create 成功 | env_destroy(createdEnvId) |
| test_health_check 失败 | env_create, env_deploy_service 成功 | env_destroy(createdEnvId) 或标记为 ERROR 保留排查 |
| analyze_network_path 失败 | 前述全部成功 | 仅报告警告，不清理（网络分析非致命） |

补偿操作必须是幂等的（`env_destroy` 对 DESTROYED 环境无操作）。

## 6. 命名风格约束

### 6.1 参数命名

- 统一使用 **camelCase**
- 禁止使用 **snake_case**

| 旧命名 (snake_case) | 新命名 (camelCase) |
|--------------------|-------------------|
| `target_host_id` | `targetHostId` |
| `env_id` | `envId` |
| `service_name` | `serviceName` |
| `resource_limit` | `resourceLimit` |
| `config_override` | `configOverride` |
| `port_mapping` | — (已移除) |

### 6.2 词汇统一

| 禁止的歧义用法 | 正确用法 | 上下文 |
|---------------|---------|--------|
| `type` (Host 物理形态) | `hostType` | Host Context |
| `type` (环境业务用途) | `environmentType` | Environment Context |
| `type` (运行时隔离) | `isolationType` | Environment Context |
| `runtime` (隔离类型) | `isolationType` | Environment Context |
| `runtime` (版本约束) | `runtimeConstraint` | Environment Context |
| `templateName` (外部契约) | `serviceName` | Deploy Context |
| `envType` | `isolationType` | Pipeline Context |
