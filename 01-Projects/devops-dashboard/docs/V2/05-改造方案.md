# DevOps MCP Server — 改造方案

> 文档编号: DES-MCP-004
> 依赖: DES-MCP-003

---

## 1. 改造原则

1. **渐进式**: 不一次性推翻现有代码，按 Phase 逐步引入 MCP 能力
2. **零侵入**: 现有 `domain`、`infrastructure` 包不修改，通过新增 `mcp` 包和少量 Service 扩展实现
3. **双轨运行**: REST API 与 MCP Server 共存，前端和 AI 各自使用适合的接口
4. **可回滚**: 每个 Phase 都是独立的，如果 MCP 方案不适用，可以关闭 MCP Server 而不影响核心功能

### Phase 1: 基础 Host 层 + MCP Server 骨架（1-2 天）

**目标**: 让 MCP Server 能启动，能读取主机拓扑，不暴露写操作。

**关键实现**: `SshLoadgenService`

```java
@Service
public class SshLoadgenService implements LoadgenService {

    private final HostRepository hostRepository;
    private final SshCommandExecutor sshExecutor;  // 复用现有组件

    @Override
    public Mono<LoadTestResult> executeLoadTest(LoadTestSpec spec) {
        Host host = hostRepository.findById(spec.getLoadgenHostId())
            .orElseThrow(() -> new HostNotFoundException(spec.getLoadgenHostId()));

        String command = buildCommand(spec);

        return sshExecutor.execute(host.getAccess(), command, 
                spec.getDuration().plusSeconds(10))
            .map(this::parseOutput);
    }

    private String buildCommand(LoadTestSpec spec) {
        return switch (spec.getTool()) {
            case WRK -> buildWrkCommand(spec);
            case HEY -> buildHeyCommand(spec);
            case AB -> buildAbCommand(spec);
        };
    }

    private String buildWrkCommand(LoadTestSpec spec) {
        return String.format("wrk -t%d -c%d -d%ds %s %s",
            Math.min(spec.getConnections(), 12),
            spec.getConnections(),
            spec.getDuration().getSeconds(),
            spec.getMethod() == HttpMethod.POST ? "-s /path/to/post.lua" : "",
            spec.getTargetUrl()
        );
    }
}
```

**验证方式**:

## 5. 回滚方案

如果 MCP 方案不适用，回滚非常简单：

1. **关闭 MCP Server**: 移除 `application-mcp.yml` 或设置 `mcp.server.enabled=false`
2. **移除 MCP 模块**: 删除 `mcp/` 包，不影响任何现有功能
3. **保留增强的领域层**: `Host`、`Evidence` 等新增领域对象可以保留，它们对 REST API 也是有益的（如 Host 管理页面）

## 8. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| MCP SDK 版本不稳定 | 协议兼容性问题 | 锁定版本 0.8.0，关注官方 Release Notes |
| SSH 远程执行安全风险 | 命令注入、越权 | test_exec_command 必须用户确认；使用受限用户（非 root） |
| 压测导致目标机过载 | 服务崩溃、数据丢失 | env_create 默认 2h 自动销毁；LoadgenService 增加资源上限检查 |
| AI 过度推断 | 自动执行危险操作 | Prompts 中明确禁止自动执行；所有写操作 Tool 设计为需确认 |
| 网络路径分析不准确 | 压测结果误导 | 明确标注 "same-hypervisor" 限制；提供 tc/netem 建议 |

## 10. 总结

这个改造方案的核心是 **"MCP 作为附加层，领域能力渐进增强"**。

你不需重写任何现有代码，只需：
1. 新增 `Host` 领域对象表达你的 PVE/VM 拓扑
2. 新增 `LoadgenService` 实现远程压测
3. 新增 `mcp/` 包作为协议适配层
4. 通过 YAML 配置声明你的基础设施

最终效果是：**你对 AI 说一句话，AI 调用 MCP Tools 替你完成环境搭建、服务部署、性能压测、证据收集、报告归档。你只需做选择题和确认。**
