# DevOps Dashboard V3 — MCP 领域模型重构

> **版本**: v3.0 (聚合根入口 + 反退化约束)
> **状态**: 设计阶段
> **最后更新**: 2026-05-23
>
> **一句话**: V2 提供"积木"，V3 提供"唯一合法路径"——AI 无法绕过 MCP 进行本地操作。

---

## 为什么需要 V3

V2 完成了 MCP 化改造，提供了原子化的 Tools 和 Resources。但在实际运行中发现 AI 存在**绕过倾向**：

| 现象                            | 根因           | V3 对策                             |
| ----------------------------- | ------------ | --------------------------------- |
| AI 本地执行 `docker run -d redis` | 工具缺少"唯一入口"语义 | 聚合根描述加 `【唯一入口】`，错误响应加 `forbidden` |
| AI 手动拆解部署步骤                   | 缺少高层编排聚合根    | 新增 `deploy_pipeline` 作为首选入口       |
| AI 通过 SSH 直连查日志               | 缺少闭环排查工具     | 新增 `env_get_logs` 作为唯一合法日志源       |
| AI 编造 serviceName / hostId    | 参数缺少数据源约束    | 所有 ID 参数必须声明"来自 XX 返回"            |
| AI 本地执行 `wrk`/`traceroute`    | 工具描述未强调不可替代性 | 三段式描述：角色 + 价值 + 反例                |

**核心设计目标**: 让 MCP 成为 AI 决策树中的**唯一可达路径**，本地执行在语义上不可达。

---

## V3 与 V2 的关系

```
V2 (原子化工具集) ──────────────→ V3 (聚合根入口 + 反退化)
=================                  ===========================
提供 15 个 Tools                   精简为 10 个核心 Tools
功能导向描述                       三段式领域契约描述
AI 可自由组合                      AI 被引导走聚合根入口
参数自由填写                       参数必须来自上游 Tool 返回
错误信息仅说明原因                 错误信息封堵替代方案 + 给出 nextSteps
```

- **V2 文档**保留在 `docs/V2/` 和 `docs/01~07/`，作为历史基线。
- **V3 文档**存放在 `docs/V3/`，同步更新 `docs/README.md` 等基础索引文档。
- **代码层面**: V3 在 V2 的 `mcp/` 包基础上增强，不修改 `domain/` `infrastructure/` 核心包。

## 核心变化速查

### 1. 新增 2 个聚合根

| 聚合根 | Tool | 职责 |
|--------|------|------|
| **DeployPipeline** | `deploy_pipeline` | 编排完整部署流水线：创建 → 部署 → 健康检查 → 网络验证 |
| **LogAggregate** | `env_get_logs` | 闭环排查：替代 SSH + `docker logs`，统一日志格式与脱敏 |

### 2. 改造 8 个现有工具

所有现有工具的 `description` 升级为**三段式领域契约**：
```markdown
【角色标签】功能一句话。
技术价值一句话（为什么必须走我）。
错误示例：❌ 禁止 ... 这将导致 ...
```

### 3. Environment 状态机精化

V2 的 `CREATING → RUNNING → STOPPED → DESTROYED` 精化为：
```
CREATING → READY → DEPLOYING → RUNNING → DESTROYED
              ↘       ↘           ↘
               ERROR ← ERROR ← ERROR
```

> 注：状态机已在服务端实现，V3 文档中仅保留简要定义，不展开理论设计。

### 4. 参数级约束

- **数据源指向**: `必须来自 env_list 返回的 id 字段`
- **enum 白名单**: `serviceName`、`checkType`、`tool`、`protocol` 等全部枚举
- **格式约束**: ID 只允许 `[a-z0-9-]`

### 5. 错误响应封堵

```json
{
  "error": {
    "code": -32000,
    "message": "业务错误简述",
    "data": {
      "currentStatus": "RUNNING",
      "requiredStatus": "READY",
      "suggestion": "调用 env_list 确认状态，或 env_get_logs 排查",
      "forbidden": "禁止本地执行 docker/ssh/curl 替代",
      "nextSteps": ["step1", "step2"]
    }
  }
}
```
