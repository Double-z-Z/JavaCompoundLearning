# V3 领域模型改造

> 在 V2 的 4 个聚合根（Host / Environment / ExperimentSession / Evidence）基础上，新增 2 个聚合根，改造 Environment 状态机。
>
> **前置**: V2 的 `02-设计/02-领域模型.md`

---

## 1. 聚合根总览（V3）

| 聚合根 | 身份标识 | 核心职责 | V3 变更 |
|--------|---------|---------|---------|
| **Host** | `HostId` | 基础设施节点管理 | 【保留】V2 定义不变 |
| **Environment** | `EnvironmentId` | 运行空间生命周期 | 【改造】状态机精化，新增 READY/DEPLOYING/ERROR |
| **ExperimentSession** | `SessionId` | 实验全流程管理 | 【保留】V2 定义不变 |
| **Evidence** | `EvidenceId` | 结构化证据存储 | 【保留】V2 定义不变 |
| **DeployPipeline** | `PipelineId` | 【新增】部署流水线编排 | 协调 env_create → deploy → health → network |
| **LogAggregate** | `LogQueryId` | 【新增】日志聚合与排查 | 替代 SSH/docker logs，统一格式与脱敏 |

## 2. DeployPipeline — 新增编排聚合根

**身份标识**: `PipelineId`

**核心职责**: 作为 MCP 部署领域的**首选入口**，封装完整部署流水线的原子化编排。

### 2.1 领域模型

```java
package devops.dashboard.domain.mcp;

public class DeployPipeline {
    private final PipelineId id;
    private final DeploySpec spec;           // 用户传入的部署规格
    private final PipelineStatus status;
    private final List<PipelineStage> stages; // 内部阶段跟踪
    private final EnvironmentId createdEnvId; // 已创建的环境（用于补偿）
    private final Instant createdAt;
    private final Instant completedAt;

    /**
     * 执行完整流水线：创建 → 部署 → 健康检查 → 网络验证
     * 任何子步骤失败触发补偿清理（Saga 模式）
     */
    public Mono<PipelineResult> execute() {
        return stageCreateEnv()
            .flatMap(this::stageDeployService)
            .flatMap(this::stageHealthCheck)
            .flatMap(this::stageNetworkVerify)
            .map(this::buildSuccessResult)
            .onErrorResume(this::compensate);
    }

    /**
     * 补偿清理：根据已完成的阶段逆向回滚
     */
    private Mono<PipelineResult> compensate(Throwable error) {
        if (createdEnvId != null && !spec.isKeepOnFailure()) {
            return envDestroy(createdEnvId)
                .thenReturn(buildFailureResult(error));
        }
        return Mono.just(buildFailureResult(error));
    }
}
```

### 2.2 值对象

```java
public class DeploySpec {
    private final String serviceName;        // 来自 ServiceRegistry 白名单
    private final HostId targetHostId;       // 来自 env_list / hosts://topology
    private final String version;            // 镜像标签或 Git tag
    private final RuntimeType runtime;       // docker | native
    private final List<String> verifyEndpoints; // 部署后验证的 HTTP 端点
    private final String runtimeConstraint;  // 如 'openjdk:21-jre-slim'
    private final boolean keepOnFailure;     // 失败时是否保留环境用于排查
}

public enum PipelineStatus {
    PENDING,     // 已创建，未执行
    CREATING,    // env_create 阶段
    DEPLOYING,   // env_deploy_service 阶段
    VERIFYING,   // test_health_check 阶段
    ANALYZING,   // analyze_network_path 阶段
    SUCCEEDED,   // 全部通过
    FAILED,      // 某阶段失败，已触发补偿
    COMPENSATED  // 补偿完成
}

public class PipelineStage {
    private final String name;               // "env_create" | "env_deploy" | "health_check" | "network_verify"
    private final StageStatus status;
    private final String output;             // 阶段输出摘要
    private final Instant startedAt;
    private final Instant completedAt;
}

public enum StageStatus {
    PENDING, RUNNING, SUCCEEDED, FAILED, SKIPPED
}
```

### 2.3 核心约束

| 约束 | 说明 |
|------|------|
| 入口唯一性 | `deploy_pipeline` 是部署的【首选入口】，AI 不应手动分步调用子工具 |
| 原子性 | 任何子步骤失败 → 整体失败 → 触发补偿清理（除非 `keepOnFailure=true`） |
| 服务白名单 | `serviceName` 必须在 `ServiceRegistry` 中注册 |
| 资源前置校验 | 执行前校验 targetHostId 的 role、capability、resource |

## 3. LogAggregate — 新增日志聚合根

**身份标识**: `LogQueryId`

**核心职责**: 作为 MCP 管理的指定环境的**唯一合法日志来源**，替代 SSH + `docker logs`。

### 3.1 领域模型

```java

        validateEnvExists(envId);
        return logProvider.fetch(envId, serviceName, spec)

            .map(this::desensitize);

    }

    private LogLine desensitize(LogLine line) {
        // 脱敏：密码、Token、密钥等敏感信息替换为 ***

```

### 3.2 值对象

```java
public class LogQuerySpec {
    private final int tailLines;             // 默认 100
    private final String since;              // 如 '10m'、'1h'、'2024-01-01T00:00:00Z'
    private final LogLevel minLevel;         // 最低日志级别过滤

    DEBUG, INFO, WARN, ERROR, FATAL
}

    private final Instant timestamp;
    private final LogLevel level;

}
```

### 3.3 与 V2 的 test_stream_logs 对比

| 维度 | V2 test_stream_logs | V3 env_get_logs |
|------|--------------------|-----------------|
| 定位 | 测试诊断工具之一 | 日志领域聚合根 |
| 语义 | `test_` 前缀暗示"测试用" | `env_get_logs` 明确表示环境日志入口 |
| 聚合能力 | 单服务日志 | 支持整个环境聚合日志（serviceName 留空） |
| 格式 | 原始容器日志 | 统一格式 + 脱敏 |
| 审计 | 无 | 查询记录写入 MCP 审计日志 |

## 4. Environment — 状态机改造

V3 对 V2 的 `Environment` 聚合根进行**状态精化**，引入 `READY`、`DEPLOYING`、`ERROR`，移除 `STOPPED`、`FAILED`、`NOT_FOUND`。

### 4.1 状态枚举（V3）

```java
public enum EnvironmentStatus {
    CREATING,   // env_create 已调用，初始化中
    READY,      // 环境就绪，允许部署（V3 新增）
    DEPLOYING,  // env_deploy_service 已锁定，部署中（V3 新增）
    RUNNING,    // 部署成功，健康检查通过
    ERROR,      // 部署或检查失败，需排查（V3 新增，替代 FAILED）
    DESTROYED   // env_destroy 完成，资源已释放
}
```

### 4.2 状态转换规则

```java
public class Environment {

    private static final Map<EnvironmentStatus, Set<EnvironmentStatus>> VALID_TRANSITIONS = Map.of(
        CREATING,  Set.of(READY, ERROR),
        READY,     Set.of(DEPLOYING, DESTROYED),
        DEPLOYING, Set.of(RUNNING, ERROR),
        RUNNING,   Set.of(DESTROYED, DEPLOYING),  // DEPLOYING 支持覆盖部署
        ERROR,     Set.of(DESTROYED, READY),      // READY 支持修复后重新部署
        DESTROYED, Set.of()                       // 终态
    );

    public void transitionTo(EnvironmentStatus newStatus) {
        if (!VALID_TRANSITIONS.get(this.status).contains(newStatus)) {
            throw new InvalidEnvironmentTransitionException(
                String.format("当前状态为 %s，不允许转换为 %s。必须先执行 %s。",
                    this.status, newStatus, suggestPrecondition(newStatus))
            );
        }
        this.status = newStatus;
    }

    private String suggestPrecondition(EnvironmentStatus target) {
        return switch (target) {
            case DEPLOYING -> "确认环境处于 READY 或 RUNNING 状态";
            case RUNNING -> "等待部署完成";
            case DESTROYED -> "先停止或修复环境";
            default -> "检查当前状态";
        };
    }
}
```

### 4.3 状态与 Tool 的对应关系

| 状态 | 允许调用的 Tools | 禁止调用的 Tools |
|------|-----------------|-----------------|
| `CREATING` | `env_get_logs`（查看初始化日志） | `env_deploy_service`, `test_health_check`, `test_load` |
| `READY` | `env_deploy_service`, `env_destroy`, `env_get_logs` | `test_health_check`, `test_load`（无可部署服务） |
| `DEPLOYING` | `env_get_logs`（查看部署日志） | `env_deploy_service`（并发部署被锁） |
| `RUNNING` | `test_*`, `env_get_logs`, `env_destroy`, `env_deploy_service`（覆盖） | 无 |
| `ERROR` | `env_get_logs`（排查）, `env_destroy` | `env_deploy_service`（需先修复到 READY） |
| `DESTROYED` | 无 | 全部 |

### 4.4 并发控制

状态转换时必须加分布式锁，防止 AI 并发调用导致竞态：

```java
public Mono<Void> deployWithLock(EnvironmentId envId) {
    return lockService.acquire("env:" + envId.value(), Duration.ofSeconds(30))
        .flatMap(lock -> {
            Environment env = repository.findById(envId);
            env.validateTransition(DEPLOYING);  // 校验当前状态
            env.transitionTo(DEPLOYING);
            return repository.save(env)
                .doFinally(signal -> lockService.release(lock));
        });
}
```

## 5. 现有工具改造为领域对象

V2 的 8 个底层工具在 V3 中继续存在，但升级为**带有边界约束描述的领域对象**。

### 5.1 改造对照表

| 原工具（V2） | V3 改造要点 | 核心描述模板 |
|-------------|------------|-------------|
| `env_create` | 增加资源配额参数 `resourceLimit` | `【唯一入口】... 禁止本地 docker run ...` |
| `env_deploy_service` | 增加状态机前置校验、serviceName enum | `必须目标环境状态为 READY ... 直接手动部署将导致监控失效` |
| `env_list` | 增加宿主机/状态筛选 | `此列表是 env_create/env_deploy_service 的唯一数据源` |
| `env_destroy` | 增加优雅停机/强制标志 | `禁止本地 docker rm -f ... 导致状态不一致` |
| `test_health_check` | 增加 `envId` 替代 `hostId` | `必须来自 env_list 中 RUNNING 状态的环境` |
| `test_load` | 增加 `envId` 替代 `hostId`/`target_url` | `禁止本地 wrk ... 避免跨网络延迟干扰` |
| `test_exec_command` | 增加工作目录/命令白名单 | `【唯一合法远程执行】禁止交互式命令` |
| `analyze_network_path` | 增加 `sourceHostId` + `targetEnvId` | `禁止本地 traceroute ... NAT/SD-WAN 差异` |

### 5.2 改造后的参数规范（通用）

每个参数描述必须包含：

1. **数据源指向**：`必须来自 XXXX 返回的 YYYY 字段`
2. **enum 约束**：可枚举的字段必须列出全部合法值
3. **格式约束**：ID 类只允许 `[a-z0-9-]`，版本号格式示例

示例：

```json
{
  "name": {
    "type": "string",
    "description": "环境标识符，将用于 DNS 和服务发现（如 redis-counter-tomcat）。只允许小写字母、数字和连字符"
  },
  "hostId": {
    "type": "string",
    "description": "目标宿主机 ID，必须来自 env_list 返回的 availableHosts 列表中的 id 字段"
  },
  "serviceName": {
    "type": "string",
    "enum": ["redis-counter-service", "devops-dashboard", "mcp-host-agent", "redis-cache"],
    "description": "MCP 服务目录中已注册的服务名"
  }
}
```

## 8. 设计约束总结

### 8.1 不变量规则

| 聚合根 | 不变量 | 校验时机 |
|--------|--------|---------|
| DeployPipeline | serviceName 必须在 ServiceRegistry 中 | execute 前 |
| DeployPipeline | targetHostId 必须是 TARGET 角色 | execute 前 |
| LogAggregate | envId 必须存在于 env_list | stream 前 |
| Environment | 状态转换必须符合 VALID_TRANSITIONS | transitionTo 时 |
| Environment | DEPLOYING 状态必须持有分布式锁 | env_deploy_service 调用前 |
| Host | parent_id 引用必须存在 | 创建/更新时 |

### 8.2 跨聚合引用规则

- `DeployPipeline` → `Environment`: 通过 `EnvironmentId` 引用
- `DeployPipeline` → `Host`: 通过 `targetHostId` 引用
- `LogAggregate` → `Environment`: 通过 `envId` 引用
- **禁止**: 直接持有其他聚合根的对象引用
