# V3 边界约束与反退化机制

> 本文档定义 V3 的核心约束规范，确保 AI 无法绕过 MCP 进行本地操作。
>
> **目标**: 让 MCP 成为 AI 决策树中的**唯一可达路径**。

---

## 1. 描述层约束（Tool Description）

### 1.1 三段式模板

每个工具的 `description` 必须按以下**三段式**编写：

```markdown
【角色标签】功能一句话。
技术价值一句话（为什么必须走我）。
错误示例：❌ 禁止 ... 这将导致 ...
```

### 1.2 角色标签规范

| 标签 | 适用范围 | 语义强度 | 示例工具 |
|------|---------|---------|---------|
| `【首选入口】` | 高层编排聚合根 | 最强 — AI 应该优先调用，不自行组合子工具 | `deploy_pipeline` |
| `【唯一入口】` | 不可替代，所有同类操作必须经过此 | 强 — 禁止任何替代路径 | `env_create`, `env_get_logs`, `test_exec_command` |
| `【唯一合法】` | 审计/测试类工具，本地替代会导致结果失真 | 中强 — 强调结果可信度和审计要求 | `test_health_check`, `test_load`, `analyze_network_path` |

### 1.3 三段式示例

**env_create（【唯一入口】）**:
```markdown
【唯一入口】在远程宿主机上创建隔离的部署环境。
所有环境生命周期必须通过此工具管理，以确保网络策略、资源配额、监控探针和 DNS 记录被正确注入。
错误示例：❌ 禁止本地执行 'docker run -d redis'，这将绕过网络隔离，导致后续 analyze_network_path 无法追踪流量路径，且不会被服务发现注册。
```

**test_load（【唯一合法】）**:
```markdown
【唯一合法】对 MCP 管理的服务执行负载测试（wrk / hey / ab）。
测试端由 MCP 宿主机调度，确保压测流量经过正确的网络路径和防火墙规则。
错误示例：❌ 禁止在本地笔记本直接执行 wrk，以避免跨网络延迟干扰和带宽瓶颈导致的测试结果失真。
```

### 1.4 禁止出现的描述风格

| ❌ V2 风格 | ✅ V3 风格 |
|-----------|-----------|
| "在指定的 Target Host 上创建一个新的空环境。" | "【唯一入口】在远程宿主机上创建隔离的部署环境。所有环境生命周期必须通过此工具管理..." |
| "对指定环境中的指定服务执行健康检查。" | "【唯一合法】对 MCP 管理的环境执行健康检查。检查结果会被记录到 MCP 审计日志..." |
| "获取服务的最近日志，用于故障排查。" | "【唯一合法】获取指定 MCP 管理环境的实时或历史日志。这是排查部署问题的唯一合法日志来源..." |

## 2. 参数校验约束

### 2.1 数据源指向规范

每个 ID 类参数描述必须包含**数据源指向**：

```json
{
  "description": "... 必须来自 {tool} 返回的 {field} 字段"
}
```

**规范示例**:

| 参数 | V2 描述 | V3 描述 |
|------|---------|---------|
| `envId` | `"环境 ID"` | `"环境 ID，必须来自 env_list 返回的 id 字段"` |
| `hostId` | `"目标宿主机 ID"` | `"目标宿主机 ID，必须来自 env_list 返回的 availableHosts 列表中的 id 字段"` |
| `serviceName` | `"服务名"` | `"服务名，必须是 MCP 服务目录中已注册的服务"` |

### 2.2 enum 约束

可枚举的字段必须列出**全部合法值**：

```json
{
  "serviceName": {
    "type": "string",
    "enum": ["redis-counter-service", "devops-dashboard", "mcp-host-agent", "redis-cache"],
    "description": "服务名，必须是 MCP 服务目录中已注册的服务"
  },
  "checkType": {
    "type": "string",
    "enum": ["http", "tcp", "dns"],
    "description": "检查类型。http 会验证状态码 2xx；tcp 验证端口连通性；dns 验证域名解析"
  },
  "tool": {
    "type": "string",
    "enum": ["wrk", "hey", "ab"],
    "description": "压测工具"
  },
  "protocol": {
    "type": "string",
    "enum": ["tcp", "udp", "icmp"],
    "description": "探测协议，默认 tcp"
  }
}
```

### 2.3 格式约束

| 字段类型 | 格式要求 | 说明 |
|---------|---------|------|
| ID 类 | `[a-z0-9-]+` | 只允许小写字母、数字和连字符 |
| 版本号 | 给出示例 | `'1.0-SNAPSHOT'`、`'latest'`、`'sha-7a3f2b'` |
| 时间范围 | ISO 8601 或相对时间 | `'2024-01-01T00:00:00Z'`、`'10m'`、`'1h'` |
| 资源配额 | 带单位字符串 | `'1.0'`、`'512m'`、`'2g'` |

## 3. 返回错误封堵（Error Response）

### 3.1 统一错误格式

当工具校验失败或调用异常时，返回给 AI 的错误 JSON 必须包含：

```json
{
  "error": {
    "code": -32000,
    "message": "业务错误简述",
    "data": {
      "currentStatus": "RUNNING",
      "requiredStatus": "READY",
      "suggestion": "调用 env_list 确认状态，或 env_get_logs 排查",
      "forbidden": "禁止本地执行 docker/ssh/curl 替代",
      "nextSteps": ["env_list", "env_get_logs", "test_health_check"]
    }
  }
}
```

### 3.2 关键字段说明

| 字段 | 必填 | 作用 |
|------|------|------|
| `code` | 是 | MCP 错误码，-32000 为业务错误 |
| `message` | 是 | 人可读的错误简述 |
| `currentStatus` | 条件 | 当前对象状态（状态机错误时必填） |
| `requiredStatus` | 条件 | 期望状态（状态机错误时必填） |
| `suggestion` | 是 | 修复建议，人可读 |
| `forbidden` | **关键** | 明确否定本地替代方案，形成心理锚点 |
| `nextSteps` | **关键** | 给出合法的 MCP 内回退路径，避免 AI 自行"创新" |

### 3.3 错误示例库

**状态机错误**:
```json
{
  "error": {
    "code": -32000,
    "message": "当前状态为 CREATING，不允许 DEPLOYING 操作",
    "data": {
      "currentStatus": "CREATING",
      "requiredStatus": "READY",
      "suggestion": "等待 env_create 完成，或调用 env_list 确认状态",
      "forbidden": "禁止通过 SSH 进入容器手动部署",
      "nextSteps": ["env_list", "env_get_logs"]
    }
  }
}
```

**服务未注册错误**:
```json
{
  "error": {
    "code": -32000,
    "message": "服务 'unknown-service' 未在 MCP 目录注册",
    "data": {
      "availableServices": ["redis-counter-service", "devops-dashboard", "mcp-host-agent", "redis-cache"],
      "suggestion": "检查 serviceName 是否拼写正确",
      "forbidden": "禁止部署未注册服务",
      "nextSteps": ["env_list"]
    }
  }
}
```

**主机角色错误**:
```json
{
  "error": {
    "code": -32000,
    "message": "主机 vm-loadgen-01 不具备 TARGET 角色",
    "data": {
      "hostId": "vm-loadgen-01",
      "actualRoles": ["loadgen"],
      "requiredRole": "TARGET",
      "suggestion": "从 env_list 的 availableHosts 中选择 roles 包含 target 的节点",
      "forbidden": "禁止向非 TARGET 节点部署服务",
      "nextSteps": ["env_list"]
    }
  }
}
```

**环境锁定错误**:
```json
{
  "error": {
    "code": -32000,
    "message": "环境 env-001 当前被锁定（DEPLOYING 进行中）",
    "data": {
      "currentStatus": "DEPLOYING",
      "suggestion": "等待当前部署完成，或 30 秒后重试",
      "forbidden": "禁止并发操作同一环境",
      "nextSteps": ["env_list", "env_get_logs"]
    }
  }
}
```

## 4. 服务目录校验（Service Registry）

### 4.1 注册表设计

`env_deploy_service` 的 `serviceName` 必须在 Server 端维护注册表：

```java
@Component
public class ServiceRegistry {
    private final Set<String> registeredServices = Set.of(
        "redis-counter-service",
        "devops-dashboard",
        "mcp-host-agent",
        "redis-cache"
    );

    public boolean isRegistered(String serviceName) {
        return registeredServices.contains(serviceName);
    }

    public Set<String> getAvailableServices() {
        return registeredServices;
    }
}
```

### 4.2 未注册服务错误

AI 传入未注册的服务名时，返回：

```json
{
  "error": {
    "code": -32000,
    "message": "服务 'X' 未在 MCP 目录注册。可用服务：[...]",
    "data": {
      "forbidden": "禁止部署未注册服务",
      "nextSteps": ["env_list"]
    }
  }
}
```

### 4.3 注册表同步

- `tools/list` 返回的 `serviceName` enum 必须与 `ServiceRegistry` 同步
- 新服务通过配置文件注册（如 `application-mcp.yml`），无需改代码重启

```yaml
# application-mcp.yml
devops:
  mcp:
    service-registry:
      - redis-counter-service
      - devops-dashboard
      - mcp-host-agent
      - redis-cache
```

## 5. 命令白名单（test_exec_command）

### 5.1 允许模式

```yaml
devops:
  security:
    exec-command:
      allowed-patterns:
        - "^curl\\s+-s\\s+http://.*"
        - "^netstat\\s+-tlnp"
        - "^ps\\s+aux"
        - "^docker\\s+(logs|ps|inspect|stats)"
        - "^jstat\\s+-gc"
        - "^jmap\\s+-histo"
```

### 5.2 禁止模式

```yaml
      blocked-patterns:
        - "rm\\s+-rf"
        - "mkfs"
        - ">\\s*/etc/"
        - "chmod\\s+777"
        - "\\|\\s*sh"
        - "\\$\\("
        - "sudo"
        - "dd\\s+if="
```

### 5.3 交互式命令拦截

```java
public class CommandValidator {
    private static final Set<String> INTERACTIVE_COMMANDS = Set.of(
        "vim", "vi", "nano", "top", "htop", "less", "more",
        "mysql", "psql", "redis-cli"  // 交互式客户端
    );

    public void validate(String command) {
        String cmd = command.trim().split("\\s+")[0];
        if (INTERACTIVE_COMMANDS.contains(cmd)) {
            throw new IllegalCommandException(
                "禁止交互式命令: " + cmd + ". 请使用非交互式替代方案。"
            );
        }
    }
}
```

## 6. 反退化检查清单

在实现和评审时，对照以下清单检查每个 Tool：

### 6.1 Description 检查

- [ ] 是否包含角色标签（【首选入口】/【唯一入口】/【唯一合法】）？
- [ ] 是否说明了"为什么必须走我"的技术价值？
- [ ] 是否包含错误示例（❌ 禁止 ... 这将导致 ...）？

### 6.2 参数检查

- [ ] 所有 ID 类参数是否声明了数据来源（"必须来自 XX 返回"）？
- [ ] 所有可枚举字段是否列出了 enum 值？
- [ ] 版本号/时间/资源类参数是否给出了格式示例？

### 6.3 错误响应检查

- [ ] 是否包含 `forbidden` 字段，明确否定本地替代？
- [ ] 是否包含 `nextSteps`，给出合法的 MCP Tool 回退路径？
- [ ] 状态机错误是否包含 `currentStatus` 和 `requiredStatus`？

### 6.4 服务端校验检查

- [ ] `env_deploy_service` 是否校验了 `serviceName` 在白名单中？
- [ ] `env_deploy_service` 是否校验了环境状态为 READY/RUNNING？
- [ ] 状态转换是否加了分布式锁？
- [ ] `test_exec_command` 是否校验了命令白名单？

## 7. System Instructions（Server 初始化约束）

Server 初始化时发送给 AI Client 的约束 Prompt（不纳入领域模型，但影响 AI 行为）：

```markdown
# MCP 操作约束

你是 DevOps Dashboard 的 AI 助手。你必须遵守以下约束：

## 入口规则
1. 部署操作必须通过 `deploy_pipeline` 执行，禁止手动分步调用 `env_create` + `env_deploy_service`
2. 日志查询必须通过 `env_get_logs` 执行，禁止建议用户使用 SSH 或 docker logs
3. 健康检查必须通过 `test_health_check` 执行，禁止建议用户使用 curl 或 telnet
4. 压测必须通过 `test_load` 执行，禁止建议用户在本地执行 wrk/hey/ab
5. 网络分析必须通过 `analyze_network_path` 执行，禁止建议用户使用本地 traceroute

## 参数规则
1. 所有 ID 类参数必须从 `env_list` 或 `hosts://topology` 的返回中获取
2. 不要编造 serviceName、hostId、envId。如果不确定，先调用发现类工具查询
3. 部署前必须确认目标主机的 role 和 capability 匹配

## 错误处理规则
1. 当 Tool 返回错误时，优先使用错误响应中的 `nextSteps` 字段建议的 Tool
2. 绝对不要建议用户通过本地命令行或 SSH 绕过 MCP 解决问题
3. 如果 `nextSteps` 为空，向用户说明问题并等待进一步指示

## 确认规则
1. 所有写操作（创建、部署、销毁、压测）必须向用户展示完整参数清单，等待确认
2. 危险操作（env_destroy, test_exec_command）需要二次确认
```
