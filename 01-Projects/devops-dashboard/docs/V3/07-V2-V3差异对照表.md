# V2 → V3 差异对照表

> **用途**: 从 V2 设计迁移到 V3 时的快速变更速查。
> **阅读场景**: 编码实现、代码评审、文档对比。

---

## 1. Tools 变更总览

### 1.1 新增（2 个）

| 工具 | 类别 | 作用 | 替代了 V2 的什么 |
|------|------|------|----------------|
| `deploy_pipeline` | 编排 | 完整部署流水线入口 | 替代了 AI 手动组合 `env_create` + `env_deploy_service` + `test_health_check` |
| `env_get_logs` | 环境 | 唯一合法日志源 | 替代了 `test_stream_logs` + SSH/docker logs |

### 1.2 改造（8 个）

| 工具 | V2 → V3 核心变化 |
|------|-----------------|
| `env_create` | description 改为【唯一入口】三段式；增加 `resourceLimit` 参数；ID 格式约束 |
| `env_deploy_service` | 增加 `serviceName` enum 白名单；增加状态机前置校验（READY/RUNNING）；description 强调监控注入 |
| `env_list` | 增加 `statusFilter` enum；description 强调"唯一数据源" |
| `env_destroy` | description 改为三段式；增加 `force` 参数说明 |
| `test_health_check` | `envId` 替代 `hostId` + `service_name`；description 改为【唯一合法】 |
| `test_load` | `envId` + `targetPort` 替代 `target_url` + `loadgen_host_id`；description 改为【唯一合法】 |
| `test_exec_command` | `hostId` 替代 `env_id` + `service_name`；description 改为【唯一合法】；增加命令白名单 |
| `analyze_network_path` | `sourceHostId` + `targetEnvId` + `targetPort` 替代 `source_host_id` + `target_host_id` + `target_port`；增加 `protocol` enum |

### 1.3 废弃/延后（5 个）

| V2 工具 | V3 处理方式 | 原因 |
|---------|------------|------|
| `test_stream_logs` | 由 `env_get_logs` 替代 | 功能合并到日志聚合根 |
| `test_functional` | 延后实现 | V3 聚焦核心部署与测试闭环 |
| `test_collect_metrics` | 由 Monitoring 自动采集 | 不再暴露为独立 Tool |
| `env_get_access` | 由 `deploy_pipeline` 内部返回 | 不再作为独立 Tool |
| `session_create/record/conclude` | 延后实现 | 实验会话功能延后到 V3+ |

### 1.4 Resources 变更

| Resource | V2 → V3 |
|---------|---------|
| `hosts://topology` | 【保留】不变 |
| `templates://list` | 【保留】不变 |
| `templates://{id}` | 【保留】不变 |
| `envs://list` | 【保留】不变（但注意 `env_list` Tool 与 `envs://list` Resource 是两个东西） |

## 2. Environment 状态机对照

### 2.1 V2 状态（旧）

```
CREATING → RUNNING → STOPPED → DESTROYED
    ↘         ↘
     FAILED    FAILED

NOT_FOUND (查询时返回)
```

### 2.2 V3 状态（新）

```
CREATING → READY → DEPLOYING → RUNNING → DESTROYED
              ↘        ↘           ↘
               ERROR ← ERROR ← ERROR
```

### 2.3 状态映射

| V2 状态 | V3 状态 | 说明 |
|---------|---------|------|
| `CREATING` | `CREATING` | 不变 |
| `RUNNING` | `RUNNING` | 不变 |
| `STOPPED` | `DESTROYED` | V2 的 STOPPED 在 V3 中直接标记为 DESTROYED |
| `DESTROYED` | `DESTROYED` | 不变 |
| `FAILED` | `ERROR` | 统一为 ERROR，不区分失败来源 |
| `NOT_FOUND` | — | V3 不再作为状态，查询不存在时直接返回错误 |
| — | `READY` | V3 新增：环境就绪但未部署 |
| — | `DEPLOYING` | V3 新增：部署进行中 |

### 2.4 转换规则对照

| 转换 | V2 | V3 |
|------|-----|-----|
| 创建成功 | `CREATING → RUNNING` | `CREATING → READY` |
| 部署 | 无中间状态 | `READY → DEPLOYING → RUNNING` |
| 停止 | `RUNNING → STOPPED` | `RUNNING → DESTROYED`（不再保留 STOPPED） |
| 失败 | `CREATING → FAILED`, `RUNNING → FAILED` | `CREATING → ERROR`, `DEPLOYING → ERROR` |
| 修复 | 无 | `ERROR → READY`（修复后重新部署） |
| 覆盖部署 | 无 | `RUNNING → DEPLOYING`（版本升级） |

## 3. 参数变更对照

### 3.1 env_create

| 参数 | V2 | V3 | 变化 |
|------|-----|-----|------|
| `target_host_id` | ✅ | ❌ 改为 `hostId` | 命名风格：snake_case → camelCase |
| `env_name` | ✅ | ❌ 改为 `name` | 简化命名 |
| `type` | ✅ `enum: [DEV,TEST,STAGING,EXPERIMENT]` | ✅ `enum: [docker, native]` | **语义变化**：V2 是环境类型，V3 是运行时类型 |
| `runtime` | ✅ `enum: [docker, native]` | ✅ 字符串（如 'docker:26.0'） | V3 的 `runtime` 是版本约束，运行时类型由 `type` 承担 |

## 4. Description 风格对照

### 4.1 V2 风格（功能说明式）

```
"在指定的 Target Host 上创建一个新的空环境。Target Host 必须具有 target 角色且资源充足。"
```

### 4.2 V3 风格（三段式领域契约）

```
"【唯一入口】在远程宿主机上创建隔离的部署环境。
所有环境生命周期必须通过此工具管理，以确保网络策略、资源配额、监控探针和 DNS 记录被正确注入。
错误示例：❌ 禁止本地执行 'docker run -d redis'，这将绕过网络隔离..."
```

### 4.3 风格变化总结

| 维度 | V2 | V3 |
|------|-----|-----|
| 语气 | 说明性、被动 | 指令性、主动 |
| 语义 | "这是什么" | "这是什么 + 为什么必须走我 + 禁止什么" |
| 长度 | 1-2 句话 | 3 段式，包含反例 |
| 对 AI 的影响 | 信息传递 | 决策引导 + 路径封堵 |

## 5. 错误响应格式对照

### 5.1 V2 格式

```json
{
  "isError": true,
  "content": [
    {
      "type": "text",
      "text": "{\"code\":\"HOST_NOT_FOUND\",\"message\":\"Host not found: vm-invalid\",\"details\":{}}"
    }
  ]
}
```

### 5.2 V3 格式

```json
{
  "isError": true,
  "content": [
    {
      "type": "text",
      "text": "{\"error\":{\"code\":-32000,\"message\":\"Host not found\",\"data\":{\"forbidden\":\"禁止本地执行...\",\"nextSteps\":[\"env_list\"]}}}"
    }
  ]
}
```

### 5.3 字段变化

| V2 字段 | V3 字段 | 变化 |
|---------|---------|------|
| `code` (字符串) | `code` (整数) | 类型变化：字符串 → 整数 |
| `message` | `message` | 不变 |
| `details` (对象) | `data` (对象) | 重命名 |
| — | `currentStatus` | 新增（状态机错误） |
| — | `requiredStatus` | 新增（状态机错误） |
| — | `suggestion` | 新增 |
| — | `forbidden` | **关键新增**：封堵本地替代 |
| — | `nextSteps` | **关键新增**：引导回退路径 |

## 8. 快速迁移检查清单

### 从 V2 代码迁移到 V3 时检查：

- [ ] `EnvironmentStatus` 枚举是否更新了？（新增 READY/DEPLOYING/ERROR，移除 STOPPED/FAILED）
- [ ] `tools/list` 返回是否只有 10 个 Tool？
- [ ] 所有 Tool 的 `description` 是否符合三段式？
- [ ] 参数命名是否从 snake_case 改为 camelCase？
- [ ] `serviceName` 是否有 enum 白名单？
- [ ] 错误响应是否包含 `forbidden` 和 `nextSteps`？
- [ ] `env_deploy_service` 是否增加了状态机前置校验？
- [ ] `deploy_pipeline` 是否实现了 Saga 补偿？
