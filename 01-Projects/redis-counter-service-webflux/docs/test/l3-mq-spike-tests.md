# MQ 异步队列削峰 - 测试报告

> **测试目标**：验证 MQ 在五层防御 L4 层的异步削峰能力，包括消息发送、消费、顺序性、死信处理和接口响应时间。
> **服务器地址**：`localhost:8080` / `10.0.0.142:8080`
> **消息队列**：RabbitMQ
> **Redis**：Cluster 模式（10.0.0.102:6379）

---

## 1. 背景与目标

秒杀场景下，L4 层通过 RabbitMQ 将同步下单转换为异步处理，达到削峰填谷的效果。本次测试验证：
1. 预扣成功后消息正确发送到 MQ，接口返回 202
2. 预扣失败时不发 MQ，直接返回 200 业务错误
3. 消费者正确处理订单消息
4. 高并发下接口响应时间 < 100ms
5. 消费失败时消息进入 DLQ

## 9. 命令速查

### 初始化库存

```bash
curl -X POST http://localhost:8080/stock/incr \
  -H "Content-Type: application/json" \
  -d '{"sku":"TEST_T5","qty":100}'
```

### 发送预扣请求

```bash
curl -s -w "\nHTTP_CODE:%{http_code}\n" http://localhost:8080/spike/order \
  -X POST \
  -H "Content-Type: application/json" \
  -H "X-User-Id: user123" \
  -H "X-Request-Id: req-t5-001" \
  -d '{"items":[{"sku":"TEST_T5","qty":1}]}'
```

### 检查 Redis 库存

```bash
redis-cli -c -h 10.0.0.102 GET stock:TEST_T5
```

### 检查 MQ 队列消息数

```bash
rabbitmqctl list_queues name messages

# 或 REST API
curl -s -u guest:guest http://localhost:15672/api/queues/%2F/spike-order-queue
```

### 检查 DLQ

```bash
rabbitmqctl list_queues name messages | grep -E "(spike-order-queue|dlq)"
```

### wrk 压测

```bash
wrk -t4 -c100 -d30s --latency -s post_body.lua http://localhost:8080/spike/order
```
