## Phase 3: JMeter HTTP 压测（80/100/150 并发）

> 测试时间：2026-05-05
> 测试工具：JMeter
> 测试目标：验证 Redis 计数器服务在不同并发下的性能表现

### 测试结果汇总

| 并发数 | 样本数 | 错误率 | 平均响应 | 中位数 | P95 | P99 | 最大值 | 吞吐量 |
|-------|-------|-------|---------|-------|-----|-----|-------|--------|
| 80 | 1,004,950 | 0% | 1.93ms | 2ms | 3ms | 3ms | 49ms | 33,622/s |
| 100 | 1,040,964 | 0% | 2.34ms | 2ms | 3ms | 4ms | 142ms | 34,788/s |
| 150 | 1,047,333 | 0% | 3.51ms | 4ms | 5ms | 7ms | 177ms | 35,010/s |

### 性能分析

**1. 吞吐量边际递减**
- 80 → 100 并发：+1,166/s (+3.5%)
- 100 → 150 并发：+222/s (+0.6%)
- 150 并发时接近服务上限（~35K/s）

**2. 延迟递增明显**
- 平均响应：1.93ms → 3.51ms (+82%)
- 但中位数相对稳定（2ms → 4ms），说明主要是长尾在恶化

**3. 长尾问题**
- 最大响应时间：49ms → 142ms → 177ms
- P99 延迟：3ms → 7ms，150并发下长尾明显

**4. 零错误率**
- 全程无错误，服务稳定

### 结论

| 指标 | 表现 | 评价 |
|------|------|------|
| 吞吐量天花板 | ~35K/s | 良好 |
| 延迟稳定性 | P99 3ms → 7ms | 可接受 |
| 服务可靠性 | 0% 错误率 | 优秀 |
| 扩展性 | 80→150并发 QPS仅+4% | 接近瓶颈 |

## Phase 4: JMeter vs wrk 压测工具对比

> 测试时间：2026-05-06
> 测试目的：验证压测工具效率和 CPU 对压测结果的影响

### 测试结果汇总

| 测试端 | 工具 | 并发 | QPS | 平均延迟 | P95 | P99 | 最大值 | CPU 规格 |
|--------|------|------|-----|---------|-----|-----|-------|---------|
| 外部 Windows | JMeter | 80 | 33,622 | 1.93ms | 3ms | 3ms | 49ms | 8C16T |
| 外部 Windows | JMeter | 100 | 34,788 | 2.34ms | 3ms | 4ms | 142ms | 8C16T |
| 外部 Windows | JMeter | 150 | 35,010 | 3.51ms | 5ms | 7ms | 177ms | 8C16T |
| 内部 Debian | JMeter | 80 | 21,741 | 2.82ms | 4ms | 6ms | 283ms | 2C（受限） |
| 内部 Debian | wrk | 80 | 23,906 | 3.92ms | - | - | 117ms | 2C（受限） |

### 工具对比分析

**JMeter vs wrk 效率**
- JMeter (33.6K) > wrk (23.9K)，JMeter 效率高约 40%
- JMeter 更适合高并发 HTTP 压测场景

**CPU 对压测的影响**
- JMeter 80并发：外部 33.6K vs 内部 21.7K（差距 35%）
- 内部 VM CPU 受限，导致 JMeter 成为瓶颈
- **压测端 CPU 压力比网络压力大得多**

---

## 压测方法论总结

### 关键结论

> **1. 压测端 CPU 是压测的主要瓶颈之一**
> - JMeter 需要大量 CPU 资源处理并发请求
> - 2核 VM 的 JMeter 性能远低于 16核 Windows
> - 网络带宽（iperf 950Mbps）不是瓶颈

> **2. PVE 内部压测无法测出服务器极限**
> - VM CPU 限制导致 JMeter 自身成为瓶颈
> - 同物理机测试：压测工具和被测服务共享资源
> - **服务器压测更适合外部测试**

> **3. 压测工具选择**
> - JMeter 效率高于 wrk（约 40%）
> - JMeter 适合复杂的 HTTP 场景（cookies, headers, POST body）
> - wrk 适合简单场景，快速获取基准数据

### 压测环境推荐配置

| 组件 | 推荐配置 | 说明 |
|------|---------|------|
| 压测端 CPU | 8核+ | JMeter 高并发需要充足 CPU |
| 压测端内存 | 4GB+ | JMeter 内存占用较大 |
| 网络 | 千兆+ | iperf 验证带宽充足 |
| 被测服务 | 独立宿主机 | 避免资源竞争 |

### 不推荐的压测方式

| 方式 | 问题 |
|------|------|
| PVE 内部 VM 压测 | CPU 受限，无法发挥 JMeter 能力 |
| 同物理机压测 | 压测工具和被测服务竞争 CPU |
| 低配压测端 | 压测端自身成为瓶颈，结果不准 |
