## 决策 1：Redis 客户端选型

### 选项

| 选项 | 优点 | 缺点 |
|------|------|------|
| **Lettuce** | 异步高性能、Spring 内置支持 | API 较底层 |
| Redisson | 功能丰富（锁、队列等）、封装完善 | 重量级、学习成本 |
| Jedis | 简单直观、社区成熟 | 同步阻塞、不支持集群 |

### 决策

**选择：Lettuce**

### 原因
1. WebFlux 响应式项目需要非阻塞客户端
2. Spring Boot 3 内置 Lettuce
3. 轻量级，便于理解底层原理
4. 性能足够（>100K QPS）

### 约束
- 如后续性能不满足，再考虑 Redisson
- 不使用 Jedis（同步阻塞不适合响应式）

## 决策 2：限流算法优先级

### 选项

| 优先级 | 算法 | 理由 |
|--------|------|------|
| P0 | 令牌桶 | 最常用，支持突发流量 |
| P0 | 滑动窗口 | 最精确，感知边界 |
| P1 | 漏桶 | 恒定速率，削峰填谷 |
| P2 | 固定窗口 | 简单但有边界穿透问题 |

### 决策

**Phase 1 实现：令牌桶 + 滑动窗口**

Phase 2 再考虑漏桶和固定窗口。

## 决策 3：可重入锁实现

### 选项

| 选项 | 实现方式 | 优点 | 缺点 |
|------|---------|------|------|
| 记录线程 + 计数 | `HSET lock threadId count` | 简单 | 无法跨 JVM |
| Redis 嵌套 | 锁内嵌套锁 | 跨进程 | 实现复杂 |

### 决策

**使用 Hash 记录 threadId 和 count**

```lua
-- 可重入加锁
local count = redis.call('HGET', key, threadId)
if count then
    redis.call('HINCRBY', key, threadId, 1)
    redis.call('EXPIRE', key, ttl)
    return 1
else
    local result = redis.call('SET', key, threadId, 'NX', 'EX', ttl)
    if result then
        redis.call('HSET', key, threadId, 1)
        return 1
    end
    return 0
end
```

## 决策 4：看门狗续期策略

### 选项

| 策略 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| 固定续期 | 每 10 秒续期 | 简单 | 可能过早或过晚 |
| 动态续期 | TTL/3 时续期 | 精确 | 实现复杂 |
| 无续期 | 依赖 TTL | 简单 | 业务可能中断 |

### 决策

**选择：动态续期（TTL/3）**

- 首次续期：持有锁后立即设置看门狗任务
- 续期间隔：TTL / 3
- 停止条件：锁已释放或业务完成

## 决策 5：Redlock 复杂度

### 选项

| 选项 | 实现方式 | 适用场景 |
|------|---------|---------|
| 单机锁 | 单 Redis 实例 | 开发/测试 |
| Redlock | 5 实例多数投票 | 生产环境 |
| Redisson | 封装完善 | 快速实现 |

### 决策

**Phase 3 再实现 Redlock**

Phase 1-2 聚焦单机锁和限流核心功能，Redlock 作为进阶内容。

## 决策 6：API 设计风格

### 选项

| 选项 | 描述 | 适用场景 |
|------|------|---------|
| 同步 REST | 同步响应 | 简单场景 |
| 响应式 REST | WebFluxMono/Flux | 高并发 |
| gRPC | 二进制协议 | 微服务间 |

### 决策

**选择：响应式 REST API（WebFlux）**

- 与项目整体响应式风格一致
- 支持背压（backpressure）
- 更高的并发处理能力

## 决策 8：项目结构

### 备选结构

```
方案 A（按功能分）：
lock-limiter-service/
├── lock/        # 锁模块
├── limiter/     # 限流模块

lock-limiter-service/
├── interface/   # 接口定义
├── impl/        # 实现
```

**选择：方案 A（按功能分）**

- 与需求文档结构一致
- 便于按模块独立开发
- 符合 DDD 思想（领域驱动）
