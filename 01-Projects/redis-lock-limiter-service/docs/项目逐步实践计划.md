## Phase 1：分布式锁核心实现

### 目标

实现可靠的分布式锁，支持基础加锁、解锁、续期功能。

### 交付物

| 文件                          | 描述        |
| --------------------------- | --------- |
| `lock/DistributedLock.java` | 锁接口定义     |
| `lock/RedisLock.java`       | Redis 锁实现 |
| `lock/LuaScripts.java`      | Lua 脚本加载器 |
| `lua/acquire_lock.lua`      | 加锁脚本      |
| `lua/release_lock.lua`      | 解锁脚本      |
| `lua/renew_lock.lua`        | 续期脚本      |

### 实现步骤

#### Step 1.1：定义锁接口

```java
public interface DistributedLock {
    boolean lock(String key, long ttlSeconds);
    boolean unlock(String key);
    boolean tryLock(String key, long ttlSeconds, long waitTime);
    boolean isLocked(String key);
}
```

#### Step 1.2：实现基础 Redis 锁

- 使用 `SET key value NX EX ttl` 原子加锁
- 使用 Lua 脚本校验 + 删除（防误删）
- 唯一标识使用 UUID

#### Step 1.3：加载 Lua 脚本

- 应用启动时预加载脚本
- 使用 `RedisScript` 接口

#### Step 1.4：单元测试

- 单线程加锁/解锁
- 10 线程并发抢锁
- 锁过期自动释放

### 验收标准

- [ ] 10 线程并发只有 1 个成功获取锁
- [ ] 解锁只能删除自己持有的锁
- [ ] 锁持有者崩溃后 TTL 自动释放

### 易错点预警

| 错误    | 原因              | 预防               |
| ----- | --------------- | ---------------- |
| 锁无法获取 | `SET NX` 失败后未重试 | 实现 tryLock 等待机制  |
| 误删他人锁 | 先 GET 再 DEL 非原子 | 使用 Lua 脚本原子操作    |
| 锁无法续期 | 锁已过期            | 看门狗在 TTL 1/3 时续期 |

## Phase 2：限流器与高级特性

### 目标

实现令牌桶、滑动窗口限流器，支持可重入锁、看门狗续期。

### 交付物

| 文件                                  | 描述     |
| ----------------------------------- | ------ |
| `limiter/RateLimiter.java`          | 限流器接口  |
| `limiter/TokenBucketLimiter.java`   | 令牌桶实现  |
| `limiter/SlidingWindowLimiter.java` | 滑动窗口实现 |
| `lock/ReentrantLock.java`           | 可重入锁实现 |
| `lock/Watchdog.java`                | 看门狗续期  |

### 实现步骤

#### Step 2.1：令牌桶限流器

- 使用 List 存储时间戳队列
- 每次请求前清理过期令牌
- 计算剩余令牌数，决定是否放行

#### Step 2.2：滑动窗口限流器

- 使用 Sorted Set 存储请求时间戳
- 清理窗口外请求
- 统计窗口内请求数

#### Step 2.3：可重入锁

- 使用 Hash 结构：`threadId -> count`
- 获取锁时 count + 1
- 解锁时 count - 1，为 0 时删除 Key

#### Step 2.4：看门狗续期

- 后台线程每 TTL/3 秒检查
- 锁仍被持有则续期
- 业务完成前阻止锁释放

### 验收标准

- [ ] 令牌桶支持突发流量（先消费后补充）
- [ ] 滑动窗口精确限流，无穿透
- [ ] 同一线程多次获取锁成功
- [ ] 看门狗在业务未完成时自动续期

### 易错点预警

| 错误    | 原因       | 预防                   |
| ----- | -------- | -------------------- |
| 限流不准  | 时间窗口计算错误 | 使用精确时间戳，测试边界         |
| 可重入死锁 | 未记录线程 ID | Hash key 使用 threadId |
| 看门狗空转 | 锁已不存在    | 续期前检查锁是否还在           |

## Phase 3：生产级特性

### 目标

实现 Redlock、监控指标、性能优化，支持集群部署。

### 交付物

| 文件                                  | 描述           |
| ----------------------------------- | ------------ |
| `lock/RedissonLikeLock.java`        | Redisson 风格锁 |
| `config/RedisClusterConfig.java`    | 集群配置         |
| `controller/LockController.java`    | REST API     |
| `controller/LimiterController.java` | 限流 API       |
| `test/LockLimiterBenchmark.java`    | JMH 性能测试     |

### 实现步骤

#### Step 3.1：Redlock 多实例协调

- 向 N 个 Redis 实例获取锁
- 过半成功才算成功
- 失败时释放所有实例的锁

#### Step 3.2：REST API

- 加锁/解锁 API
- 限流检查 API
- 返回 429 状态码

#### Step 3.3：性能测试

- JMH 基准测试
- 10000 QPS 压测
- P99 延迟验证

#### Step 3.4：监控指标

- 锁获取成功率
- 限流拦截率
- P99 延迟

### 验收标准

- [ ] Redlock 在 3 个实例下正常工作
- [ ] API 返回正确的 429 状态码
- [ ] 10000 QPS 下 P99 < 10ms
- [ ] 监控指标可导出

### 易错点预警

| 错误         | 原因              | 预防               |
| ---------- | --------------- | ---------------- |
| Redlock 脑裂 | 实例故障后未释放        | 设置合理的 ttl 和重试    |
| 内存泄漏       | Sorted Set 无限增长 | 确保过期时间正确设置       |
| 性能瓶颈       | 同步阻塞            | 使用 Lettuce 异步客户端 |
