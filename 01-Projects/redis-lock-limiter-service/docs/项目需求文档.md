## 1. 项目概述

### 1.1 项目背景

在分布式系统中，多个服务实例可能同时访问共享资源，导致数据不一致或竞争条件。传统的单机锁无法跨 JVM 生效，需要引入分布式锁来协调。同时，高并发场景下 API 需要限流保护，防止系统过载。

本项目将实现一个**生产级的分布式锁与限流服务**，基于 Redis 提供高性能、可靠的锁机制和多种限流算法。

### 1.2 应用场景

| 场景 | 描述 | 解决问题 |
|------|------|---------|
| **秒杀抢购** | 库存扣减，防止超卖 | 分布式协调 |
| **防重复提交** | 用户重复点击，同一订单多次创建 | 幂等性保证 |
| **API 限流** | 保护下游服务，限制调用频率 | 系统保护 |
| **任务调度** | 多个 worker 争抢同一任务 | 互斥执行 |
| **优惠券发放** | 每个人只能领取一次 | 并发控制 |

## 2. 功能需求

### 2.1 分布式锁模块

#### 2.1.1 基础功能

| 需求 | 描述 | 优先级 |
|------|------|-------|
| `lock(key, ttl)` | 尝试获取锁，设置过期时间 | P0 |
| `unlock(key)` | 释放锁 | P0 |
| `tryLock(key, ttl, waitTime)` | 尝试获取锁，支持等待 | P0 |
| `isLocked(key)` | 检查锁状态 | P1 |

#### 2.1.2 高级功能

| 需求 | 描述 | 优先级 |
|------|------|-------|
| 可重入锁 | 同一线程多次获取锁 | P1 |
| 看门狗续期 | 业务未完成时自动续期锁 | P1 |
| 公平锁 | 按请求顺序获取锁 | P2 |
| 红锁（Redlock） | 多 Redis 实例协调 | P2 |

#### 2.1.3 安全要求

- **防误删**：只能删除自己持有的锁（通过唯一标识）
- **原子性**：Lua 脚本保证 Check-and-Delete 原子性
- **死锁预防**：锁必须有过期时间

### 2.2 限流模块

#### 2.2.1 限流算法

| 算法 | 描述 | 优先级 |
|------|------|-------|
| 令牌桶 | 平滑限流，支持突发流量 | P0 |
| 滑动窗口 | 基于时间窗口的精确限流 | P0 |
| 漏桶 | 恒定速率输出 | P1 |
| 固定窗口 | 简单计数限流 | P2 |

#### 2.2.2 限流维度

| 维度 | 描述 | 优先级 |
|------|------|-------|
| 全局限流 | 整个系统总请求数 | P0 |
| 用户限流 | 按用户 ID 限流 | P0 |
| IP 限流 | 按 IP 地址限流 | P1 |
| 接口限流 | 按 API 路径限流 | P0 |

#### 2.2.3 限流响应

| 响应方式 | 描述 | 优先级 |
|----------|------|-------|
| 返回 429 | HTTP 429 Too Many Requests | P0 |
| Retry-After Header | 告知客户端重试时间 | P1 |
| 降级处理 | 限流时返回默认值 | P2 |

### 4.3 Redis 数据结构

| 用途 | 数据结构 | Key Pattern |
|------|---------|-------------|
| 普通锁 | String | `lock:{resource}` |
| 可重入锁 | Hash | `lock:reentrant:{resource}` |
| 令牌桶 | String + List | `limiter:token:{key}` |
| 滑动窗口 | Sorted Set | `limiter:window:{key}` |
| 固定窗口 | String | `limiter:fixed:{key}:{window}` |

## 5. API 接口

### 5.1 分布式锁 API

```
POST /api/lock/acquire
Content-Type: application/json

Request:
{
  "key": "order:123",
  "ttlSeconds": 30,
  "uniqueId": "worker-001"  // 可选，用于可重入
}

Response (成功):
{
  "success": true,
  "lockKey": "order:123",
  "ttl": 30
}

Response (失败):
{
  "success": false,
  "reason": "LOCK_HELD"
}
```

```
POST /api/lock/release
Content-Type: application/json

Request:
{
  "key": "order:123",
  "uniqueId": "worker-001"
}

Response:
{
  "success": true,
  "released": true
}
```

### 5.2 限流 API

```
POST /api/limiter/check
Content-Type: application/json

Request:
{
  "key": "user:12345:api:/order",
  "limit": 100,
  "windowSeconds": 60
}

Response:
{
  "allowed": true,
  "remaining": 99,
  "resetAt": 1715856000
}

Response (被限流):
{
  "allowed": false,
  "remaining": 0,
  "retryAfter": 30
}
```
