# Sentinel 流量控制效果

## 概述

当请求超过限流阈值时，Sentinel 提供三种处理策略，适用于不同业务场景。

## 三种策略

### 1. 直接拒绝 (Default)

**机制**：超阈值立即抛出 `FlowException`

**适用场景**：
- 过热保护，快速失败
- 非核心服务，调用方需处理异常

**特点**：简单直接，无需额外配置

---

### 2. Warm Up（预热/冷启动保护）

**机制**：阈值从低到高渐进爬升，防止冷启动冲击

**核心参数**：
| 参数 | 默认值 | 含义 |
|------|--------|------|
| `coldFactor` | 3 | 初始阈值 = 目标值 / 3 |
| `warmupPeriod` | 可配置 | 预热时长（默认 10s） |

**曲线公式**：
```
threshold = count - (count/coldFactor) × (1 - (1 - t)²)
```
其中 `t = elapsed/warmupPeriod`（0 → 1）

**曲线形状**：抛物线左半边（先快后慢）

**适用场景**：
- 冷启动保护（缓存空、连接池未满、JIT 未编译）
- 需要逐步加载的服务

---

### 3. 匀速排队 (RateLimiter)

**机制**：让请求匀速通过，实现削峰填谷

**核心风险公式**：
```
最坏排队线程数 = QPS阈值 × 超时时间(秒)
```

**约束**：仅支持 QPS 模式，不支持并发数模式

**适用场景**：
- 削峰填谷，不能丢的请求
- 需要平滑处理的场景

**风险点**：线程阻塞可能导致线程池耗尽

---

## 策略对比

| 策略 | 场景 | 特点 |
|------|------|------|
| 直接拒绝 | 过热保护、非核心服务 | 快速失败、调用方处理异常 |
| Warm Up | 冷启动、缓存预热 | 阈值爬坡、抛物线曲线 |
| 匀速排队 | 削峰填谷、不能丢的请求 | 线程阻塞、需控制超时 |
