# Sentinel 熔断机制

## 一句话定义

熔断器是保护系统免受"慢调用/异常"级联故障的机制，通过统计滑动窗口内的错误比例或慢调用比例，超过阈值时自动切断请求，进入恢复探测期。

## 熔断 vs 限流的本质区别

| 维度   | 限流 (Flow Control) | 熔断 (Circuit Breaker) |
| ---- | ----------------- | -------------------- |
| 保护对象 | 系统不被**流量**打垮      | 系统不被**慢依赖**拖死        |
| 关注指标 | QPS（请求数量）         | RT / 异常率（请求质量）       |
| 典型场景 | 防刷、突发流量           | 下游超时、数据库慢查询          |
| 控制粒度 | 全局 / 参数级别         | 调用链级别                |

## 三种熔断策略

### 1. 慢调用比例 (SLOW\_REQUEST\_RATIO)

```
触发条件：慢调用数 / 总请求数 > 阈值
配置项：
  - maxRT: 最大响应时间阈值（如500ms）
  - slowRatioThreshold: 慢调用比例阈值（如0.5=50%）
  - minRequestAmount: 最小请求数（如5，避免误判）
  
适用：下游服务响应变慢但未完全不可用
```

### 2. 异常比例 (ERROR\_RATIO)

```
触发条件：异常数 / 总请求数 > 阈值
配置项：
  - errorRatioThreshold: 异常比例阈值
  
适用：下游服务抛出业务异常
```

### 3. 异常数 (ERROR\_COUNT)

```
触发条件：绝对异常数 > 阈值（如60秒内5个异常）
配置项：
  - errorCountThreshold: 异常数阈值
  
适用：低流量场景，绝对数量更有意义
```

## 核心实现逻辑

```java
public boolean tryPass(Context context) {
    SlidingWindowCounter counter = getCounter();
    long total = counter.total();
    
    if (total < minRequestAmount) {
        return true;  // 请求数太少，不触发
    }
    
    double ratio = (double) slow / total;
    if (ratio >= slowRatioThreshold) {
        return false;  // 触发熔断！
    }
    return true;
}
```

**本质**：LeapArray 统计 + 一个 if 判断

## 悬挂请求问题与解决方案

### 问题定义

正在执行、RT 已超标但尚未结束的请求——它算不算"慢调用"？

### 三种视角

| 视角   | 判断      | 理由            |
| ---- | ------- | ------------- |
| 结果视角 | 还不算     | 可能再过1ms就成功了   |
| 资源视角 | **已经算** | 已占线程N秒，造成实际压力 |
| 预测视角 | 大概率算    | RT已超标，边际收益递减  |

### Sentinel 的选择：结果视角（延迟计入）

- 只在请求**结束时**才更新计数器
- 悬挂请求不影响统计
- "自然平滑"：延迟计入 = 时间上的分散

### 更优方案：分代桶（资源视角）

```
┌─────────────────────────────────────────────┐
│           Pending Request 分代模型            │
├─────────────────────────────────────────────┤
│                                             │
│  [新生代桶] ← 新请求先放这里                 │
│     │                                       │
│     │ 时间窗口滑动时                         │
│     ▼                                       │
│  [老年代桶] ← 从新生代"晋升"过来的            │
│     │                                       │
│     │ 超过最大年龄                           │
│     ▼                                       │
│  回收/强制标记为慢调用                        │
│                                             │
└─────────────────────────────────────────────┘

优化：用 AtomicLong 替代 map 遍历
      pendingCount.incrementAndGet()  [请求开始]
      pendingCount.decrementAndGet()  [请求结束]
```

## 熔断状态机

```
         ┌──────────┐
    ────→│  CLOSED   │ ← 正常状态，放行所有请求
         └────┬─────┘
              │ 满足熔断条件
              ▼
         ┌──────────┐
         │   OPEN    │ ← 熔断状态，拒绝所有请求
         └────┬─────┘
              │ 经过 recoveryTimeout
              ▼
         ┌──────────┐    探测成功    ┌──────────┐
         │ HALF_OPEN│ ──────────── →│  CLOSED  │
         └────┬─────┘              └──────────┘
              │ 探测失败
              ▼
         ┌──────────┐
         │   OPEN    │ ← 重新熔断
         └──────────┘
```
