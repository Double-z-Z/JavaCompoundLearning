# DDD 异常分层设计

## 一句话定义
**异常必须按层级分离**：Domain 层抛业务异常，Infrastructure 层负责将技术异常"翻译"为领域异常，Application 层只捕获领域异常。

## 核心理解

### 三层异常体系

| 层级 | 异常类型 | 示例 | 谁能抛出 |
|------|---------|------|---------|
| **Domain** | 业务规则异常 | `EnvironmentNotReadyException`, `InvalidStateTransitionException` | Domain 层 |
| **Application** | 用例编排异常 | `ExperimentNotFoundException` | Application Service |
| **Infrastructure** | 技术故障异常 | `DockerComposeException`, `JpaOptimisticLockException` | Infra 层 |

### 核心原则

1. **Domain 层不能感知技术**
   - ❌ 不能 import `JpaPersistenceException`, `SQLException`, `DockerAPIException`
   - ✅ 只能抛出自定义的业务异常

2. **Infrastructure 层负责"翻译"**
   - 技术异常 → 领域异常（带上下文信息）

3. **调用方（AppService）只捕获领域异常**
   - 不需要知道底层用的是 JPA 还是 MyBatis，Docker 还是 K8s

### 翻译示例

```java
// Infrastructure 层：技术异常 → 领域异常
@Component
public class DockerComposeProvisioner implements EnvironmentProvisioner {
    
    @Override
    public Mono<Environment> provision(EnvironmentSpec spec) {
        return executeDockerCompose(spec)
            .onErrorMap(DockerAPIException.class, e -> 
                new EnvironmentProvisionException(
                    "环境创建失败: " + e.getMessage(),  // 业务语义
                    e                                   // 保留原始异常链
                )
            );
    }
    
    @Override
    public Mono<Void> teardown(EnvironmentId id) {
        return executeDockerComposeDown(id)
            .onErrorMap(ProcessTimeoutException.class, e ->
                new EnvironmentTeardownException(
                    "环境销毁超时（可能资源未释放）",
                    e
                )
            );
    }
}
```

### 目录结构建议

```
domain/
└── environment/
    └── exception/
        ├── EnvironmentException.java              // 基类
        ├── EnvironmentProvisionException.java     // 创建失败
        ├── EnvironmentTeardownException.java      // 销毁失败
        └── InvalidStatusTransitionException.java  // 状态转换非法

infrastructure/
└── environment/
    └── exception/
        ├── DockerComposeException.java            // Docker 特有异常
        └── PveApiException.java                   // PVE API 特有异常
```

## 关键关联

- [[领域接口纯洁性]] - 关联原因：异常类型也是接口的一部分，必须使用领域异常而非技术异常
- [[DDD分层架构]] - 关联原因：异常分层是四层架构的重要体现，防止异常跨越层级
- [[防退化红线]] - 关联原因：直接在 Domain 层 catch 技术异常是最常见的退化路径之一

## 我的误区与疑问

- ❌ 误区：以为直接 throw new RuntimeException("Docker 启动失败") 就够了
- ❌ 误区：以为 AppService 应该 catch Exception 打印堆栈
- ❓ 疑问：是否需要为每个业务场景都创建自定义异常？

## 代码与实践

```java
// ✅ 正确的三层异常处理
@Service
public class ExperimentApplicationService {
    
    public ExperimentDTO create(CreateExperimentCommand cmd) {
        try {
            // 1. 编排用例
            Experiment experiment = createExperiment(cmd);
            
            // 2. 持久化（可能抛出 Infrastructure 异常）
            return experimentRepository.save(experiment);
            
        } catch (EnvironmentNotReadyException e) {
            // 3. 只捕获领域异常（已被翻译过的）
            throw new BusinessException("环境未就绪，无法创建实验", e);
        }
    }
}

// Domain 层：只抛业务异常
public class Experiment extends AggregateRoot<ExperimentId> {
    public void start(Environment environment) {
        if (!environment.isReady()) {
            throw new EnvironmentNotReadyException(
                environment.getId(), 
                environment.getStatus()
            );
        }
        this.status = ExperimentStatus.RUNNING;
    }
}
```
