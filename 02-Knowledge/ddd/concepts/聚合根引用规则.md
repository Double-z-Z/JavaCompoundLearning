# 聚合根引用规则

## 一句话定义
**聚合根之间只能通过 ID 引用，禁止直接持有对象引用、禁止共享事务、禁止继承**——这是保护聚合边界的核心规则。

## 核心理解

### 三条铁律

| 规则 | ✅ 正确做法 | ❌ 违规做法 |
|------|-----------|-----------|
| **引用方式** | 只持 ID（值对象） | 直接持有对象引用 (@OneToOne, @ManyToOne) |
| **事务边界** | 各自独立事务 | 隐式共享事务 (cascade=ALL) |
| **继承关系** | 组合优于继承 | 聚合根继承另一个聚合根 |

### 为什么不能用 @OneToOne(cascade=ALL)？

**问题本质**：JPA 的"实体关系"覆盖了 DDD 的"聚合边界"

| 维度 | @OneToOne 持对象 | DDD 推荐（ID 引用） |
|------|----------------|-------------------|
| 聚合边界 | ❌ 模糊 | ✅ 清晰 |
| 事务范围 | ❌ 隐式扩大（两个聚合共享事务） | ✅ 各自独立 |
| 生命周期 | ❌ 耦合（orphanRemoval 自动级联删除） | ✅ 解耦（领域事件协调） |
| Repository 归属 | ❌ 混乱 | ✅ 明确 |

**具体风险**：
1. **可以直接修改另一个聚合根**：违反"聚合根是外部访问唯一入口"
2. **隐式级联删除**：删除 Experiment 时意外删除 Environment
3. **事务粒度失控**：乐观锁无法在单个聚合级别工作

### 正确做法：ID 引用 + 显式加载

```java
// 领域层：只持 ID
public class Experiment extends AggregateRoot<ExperimentId> {
    private EnvironmentId dedicatedEnvironmentId;  // 值对象
    
    public EnvironmentId getDedicatedEnvironmentId() {
        return dedicatedEnvironmentId;
    }
}

// 基础设施层：JPA 映射为普通字段
@Entity
public class ExperimentJpaEntity {
    @Embedded
    private EnvironmentId dedicatedEnvironmentId;
    // ❌ 没有 @OneToOne Environment 映射
}

// 应用层：需要时显式加载
@Service
public class ExperimentApplicationService {
    public ExperimentDTO getDetail(ExperimentId id) {
        Experiment experiment = experimentRepo.findById(id);
        // 需要环境信息时再查
        Environment env = environmentRepo.findById(experiment.getDedicatedEnvironmentId());
        return assembleDTO(experiment, env);
    }
}
```

### 跨聚合操作的两种模式

#### 模式 1：应用层编排（强一致性需求）
```java
@Transactional
public void concludeExperiment(ExperimentId expId) {
    Experiment exp = experimentRepo.findById(expId);
    exp.conclude();  // Domain 层行为
    
    Environment env = environmentRepo.findById(exp.getDedicatedEnvironmentId());
    env.release();   // 另一个聚合的操作
    
    experimentRepo.save(exp);
    environmentRepo.save(env);
}
```

#### 模式 2：领域事件（最终一致性）
```java
public class Experiment extends AggregateRoot<ExperimentId> {
    public void conclude() {
        registerEvent(new ExperimentConcludedEvent(id, dedicatedEnvironmentId));
    }
}

// Environment 领域监听此事件并异步释放资源
@EventListener
public void on(ExperimentConcludedEvent event) {
    Environment env = environmentRepo.findById(event.getEnvironmentId());
    env.release();
    environmentRepo.save(env);
}
```

## 关键关联

- [[聚合根-AggregateRoot]] - 关联原因：本规则是聚合根"一致性边界"的具体体现
- [[值对象-ValueObject]] - 关联原因：ID 引用必须通过值对象实现（如 EnvironmentId）
- [[防退化红线]] - 关联原因：违反此规则是最常见的架构退化路径之一

## 我的误区与疑问

- ❌ 误区：以为 @OneToOne 方便，可以省去手动查询
- ❌ 误区：以为 cascade=ALL 是"级联保存"的简便写法
- ❓ 疑问：每次都要显式加载，性能会不会有问题？（答案：可以通过缓存/批量查询优化）

```java
// ✅ 修正方案

    private EnvironmentId dedicatedEnvironmentId;  // 只引用 ID
}
```
