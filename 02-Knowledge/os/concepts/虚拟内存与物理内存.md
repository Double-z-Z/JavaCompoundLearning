# 虚拟内存与物理内存

## 一句话定义
虚拟地址空间是内核给进程的"支票簿"（承诺），物理内存是真正的"现金"（兑现）。`malloc` 只签支票，第一次写入时才触发缺页中断逐页兑现。

## 核心理解

### VIRT vs RES 的 160 倍差距
```
VIRT = 进程申请的全部虚拟地址空间（含 mmap 预留、线程栈、共享库映射）
RES  = 实际分配了物理页的部分

Node.js 进程：VIRT 44.7GB / RES 273MB = 差距 160 倍
原因：V8 堆预留 4GB+、16 个线程栈各 8MB 虚拟、.so 映射、glibc malloc arena
```

在 64 位系统上虚拟地址空间几乎无限（128TB），VIRT 大不是问题。

### 页表 + MMU + 缺页中断
CPU 的 MMU 硬件做虚拟→物理地址翻译，查多级页表。如果页表 entry 没有物理页号 → 缺页中断 → 内核分配 4KB 物理页 → 重新执行指令。**4KB 页内部虚拟地址和物理地址是线性偏移的，缓存行（64B）永不跨页。**

### Active / Inactive LRU
Linux 维护两个链表：Active（热页）和 Inactive（冷页）。回收时优先丢 file 页（磁盘有备份，零成本），anon 页要先 swap。

### Anon vs File 页
```
anon 页 = malloc/new 出来的（堆、栈）→ 回收要先写 swap
file 页 = 从磁盘读入的（代码段、文件缓存）→ 回收直接丢弃
```
这就是为什么 `free` 优先回收 `buff/cache`——全是 file 页。

- [[Linux内存监控]] - free/vmstat//proc/meminfo 是实现这套机制的观测窗口

## 我的误区与疑问
- ❌ 最初问"虚拟内存是否会破坏连续内存的缓存命中率" — 4KB 页内部连续，跨页瓶颈是 TLB 不是缓存
- ❌ 以为更新数据时也要更新 TLB — 改数据不改映射，TLB 不变；只有换页/mmap 才触发 TLB 刷新

## 深入思考
💡 malloc(1GB) 瞬间 VIRT 涨 1GB，RES 不动。Java 的 `ByteBuffer.allocateDirect(100MB)` 同理——Netty 用 PooledByteBufAllocator + 大页对齐来减少 TLB 压力。
