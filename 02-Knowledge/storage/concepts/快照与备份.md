# 快照与备份

## 一句话定义
快照是标记某一时刻状态并延迟复制数据的机制；备份是立即全量复制数据的独立副本。


## 核心理解

### 本质区别

| 维度 | 快照 | 备份 |
|------|------|------|
| **创建时机** | 瞬间完成（仅记录元数据） | 耗时（复制全部数据） |
| **存储方式** | 按需复制（Copy-On-Write） | 立即全量存储 |
| **空间占用** | 初始几乎为零，随写入增长 | 立即占用完整空间 |
| **数据独立性** | 依赖原始数据 | 完全独立 |
| **删除中间节点** | 需要合并数据（成本高） | 可直接删除 |

### 快照的实现机制（Copy-On-Write）

**单快照场景**：
- 创建时：仅记录指向原始数据的指针
- 写入时：将旧数据复制到快照区，新数据写入原位置
- 标记已复制，避免重复复制

**快照链场景**：
```
原始数据 ← 周一快照 ← 周二快照 ← 周三快照
```
- 每次写入时，旧数据复制给**最新的、尚未拥有该数据块的快照**
- 读取时需要回溯快照链 reconstruct 完整状态

### 与Git的对比

| | Git Commit | 文件系统快照 |
|--|-----------|-------------|
| 存储内容 | 文件内容的哈希引用（blob） | 与前一状态的差异 |
| 独立性 | 独立（每个commit自带完整索引） | 链式依赖 |
| 删除中间节点 | 可清理（gc） | 必须合并数据 |
| 重复修改存储 | 每个commit存完整内容 | 只存第一次被覆盖的旧值 |


## 关键关联

- [[CopyOnWriteArrayList]] - 关联原因：Java中的COW是全量复制，而文件系统快照是增量复制，两者适用场景不同
- [[Git版本控制]] - 关联原因：Git的commit是独立可访问的，而快照是链式依赖的，删除中间节点的代价不同
- [[数据一致性]] - 关联原因：快照创建时的一致性保证需要特殊处理（如数据库快照的一致性视图）
