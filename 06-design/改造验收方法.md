此次改造的验收不是"文件是否创建"，而是**系统是否能自运转、人是否能快速决策、知识库是否停止熵增**。以下是可操作的验收方案：

---

## 一、结构验收（Week 1 结束）

| 检查项 | 验证方法 | 通过标准 |
|-------|---------|---------|
| `.agent/goals/` 存在且含模板 | `ls .agent/goals/` | 有 `GOAL-模板.md`，有 `_archive/` 目录 |
| `.agent/_system/` 存在且可写 | `ls .agent/_system/` | 有 `emergence.md`、`gap-analysis.md`、`health.md` |
| `AGENTS.md` 精简 | `wc -l AGENTS.md` | ≤ 60 行，无目录结构说明，无评估触发条件 |
| `profile.md` 无历史对话 | `grep -c "本次对话" .agent/profile.md` | 0 次出现，历史已迁移 |
| `config.md` 无 AGENTS.md 重复路径 | 对比两文件路径表 | 无重复条目，AGENTS.md 只引用 config.md |

## 二、流程验收（Week 2-3，逐个 Skill 测试）

### 测试 1：涌现检测是否写入日志

**操作**：
1. 在 `02-Knowledge/redis/` 下手动创建 6 篇笔记，每篇链接到另外 3 篇同主题笔记
2. 对 Agent 说"整理笔记"

**通过标准**：
- Agent 对话末尾输出："检测到密度溢出，建议创建 EMRG-Redis，请查看 `.agent/_system/emergence.md` 审批"
- 打开 `emergence.md`，能看到待审批条目，含触发数据（笔记数、链接数）

### 测试 2：Gap 矩阵是否生成且等人决策

**操作**：
1. 创建 `GOAL-Test-2026-Q2.md`，定义 2 个缺口（一个有 EMRG 证据，一个无）
2. 对 Agent 说"开始每周回顾"

**通过标准**：
- Phase 3 输出 Gap 矩阵表格，前 5 列已填，第 6 列显示 `[待填]`
- Agent 明确说："请填写'你的决策'列，只有标记 ✅ 的缺口会进入下周推荐"

### 测试 3：学习推荐是否过滤拒绝清单

**操作**：
1. 在 `profile.md` 拒绝清单中加入"React 前端深入"
2. 对 Agent 说"开始今日学习"

**通过标准**：
- 推荐选项中**不出现** React 相关内容
- 如 Agent 检测到某选项涉及 React，输出："根据战略边界，React 前端深入已过滤（原因：非职业方向）"

### 测试 4：错误归档是否暴露缺口并提示 GOAL

**操作**：
1. 模拟一个错误，涉及"Service Mesh"概念
2. 该概念不在任何 active GOAL 中
3. 对 Agent 说"保存这个错误"

**通过标准**：
- 错误归档后，Agent 输出："该错误涉及概念不属于任何 active GOAL，是否创建 GOAL？"
- 如用户确认，调用 GOAL 管理 Skill 生成模板

### 测试 5：GOAL 到期是否自动归档

**操作**：
1. 创建一个 GOAL，deadline 设为昨天
2. 对 Agent 说"开始每周回顾"

**通过标准**：
- Phase 4 标红该 GOAL，提示："已过期，建议归档"
- 用户确认归档后，文件物理移动到 `.agent/goals/_archive/`
- `profile.md` 当前快照中的 GOAL 计数自动减 1

## 三、效果验收（Week 4，系统运行一周后）

### 3.1 人把握方向的速度

| 场景 | 旧系统耗时 | 新系统耗时 | 通过标准 |
|-----|-----------|-----------|---------|
| 判断"本周该学什么" | 10-30 分钟（翻笔记、想计划） | **≤ 30 秒** | 打开 `health.md` 或每周回顾报告，一眼看到 P0 缺口 |
| 判断"知识库是否健康" | 无法判断（看 Graph View 猜） | **≤ 30 秒** | 看到僵尸 MOC 数、孤儿笔记数、未验证占比 |
| 判断"某个技术是否该学" | 纠结（LLM 推荐 vs 自己犹豫） | **≤ 5 秒** | 查 `profile.md` 拒绝清单，命中即否 |

### 3.2 垃圾山是否停止增长

| 指标 | 验收方法 | 通过标准 |
|-----|---------|---------|
| 孤儿笔记增长率 | 对比改造前后 2 周，`03-Practice/` 和 `02-Knowledge/` 中 7 天无入链的笔记数 | 增长率 ≤ 0（或下降） |
| 僵尸 MOC 数 | `health.md` 中 30 天未编辑的 EMRG 数 | ≤ 2 个（允许少量历史遗留） |
| 无 GOAL 关联的学习 | 抽查最近 10 篇原子笔记，检查是否关联 active GOAL | ≥ 80% 有关联（允许 20% 探索性学习） |

### 3.3 上下文是否不再腐烂

| 指标 | 验收方法 | 通过标准 |
|-----|---------|---------|
| 单次对话加载文件数 | 在 Skill 输出中检查（或看 Agent 上下文摘要） | ≤ 3 个完整文件 |
| 推荐相关性 | 连续 5 次"开始今日学习"，检查推荐是否偏离 P0 GOAL | 5/5 次均关联 P0 缺口 |
| 拒绝清单命中率 | 记录 LLM 推荐中被过滤的主题数 / 总推荐数 | ≥ 90% 的边界外主题被过滤 |

| **总计** | **35-60 分钟/周** | **≤ 15 分钟/周** | 减少 ≥ 60% |

## 五、失败信号（改造未通过的明确指标）

如果出现以下任一情况，说明改造失败，需要回滚或重新设计：

| 失败信号 | 含义 | 应对措施 |
|---------|------|---------|
| Agent 每周回顾时加载文件 > 5 个 | 加载协议未被遵守，上下文仍在腐烂 | 检查 Skill 是否按 AGENTS.md 约束执行 |
| `emergence.md` 30 天内无一条记录 | 涌现检测未触发或 Agent 未写入 | 检查整理笔记 Skill 的 Step 4 是否执行 |
| Gap 矩阵中"人决策"列 4 周未填 | 用户不参与决策，系统退化为纯 Agent 驱动 | 简化 Gap 矩阵格式，或改为 Agent 提案人默认 ✅ |
| 拒绝清单为空或 Agent 从不命中 | 边界约束失效 | 检查学习推荐 Skill 是否读取 profile.md #拒绝清单 |
| GOAL 创建后 2 周无更新 | GOAL 管理 Skill 未被触发或人放弃维护 | 将 GOAL 创建与错误归档/每周回顾强制绑定 |

## 六、一句话验收标准

> **改造成功的标志不是文件齐全，而是：每周五你花 15 分钟看 Agent 生成的诊断报告，打几个 ✅/❌，就能明确知道下周该学什么、不该学什么——而知识库在没有你手动整理的情况下，结构健康度在自动改善。**
