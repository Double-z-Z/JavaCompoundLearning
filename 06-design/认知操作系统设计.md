# 认知操作系统设计文档

> **版本**: v1.0\
> **日期**: 2026-05-06\
> **背景**: 基于 Obsidian + AI Agent 的复利学习工程，解决 LLM 推荐导致的知识库结构熵增与方向迷失问题\
> **适用平台**: Trae IDE / Claude Code (双平台兼容)

***

## 1. 背景与核心问题

### 1.1 原始痛点

在基于 LLM 的复利学习工程中，存在三个结构性矛盾：

| 矛盾                    | 表现                                              | 后果                    |
| --------------------- | ----------------------------------------------- | --------------------- |
| **LLM 的生成性 vs 人的策展性** | LLM 擅长横向扩展知识，但无法判断对个人职业路径的 ROI                  | 学习路线分裂，知识库变成"垃圾山"     |
| **MOC 的链接性 vs 方向性**   | Obsidian Graph View 只显示"连接存在"，不显示"连接强度"和"方向正确性" | 看到密集网络误以为健康，实则是结构性肥胖  |
| **知识积累 vs 能力缺口**      | 笔记越来越多，但生产环境的技术债务并未减少                           | 学了很多，工作中仍然被同样问题 block |

### 1.2 关键洞察

> **技术负债不是"学习计划"，而是"带破产清算日期的能力缺口合约"。**\
> **知识图谱不是"学过的所有东西"，而是"经过涌现规则筛选、可让 LLM 快速理解思维模式的最小有效模型"。**

***

## 2. 设计目标

1. **方向锚定**: 所有学习推荐必须关联到具体的技术负债（GOAL），拒绝清单过滤边界外主题
2. **结构自治**: 知识图谱（EMRG）通过涌现规则自组织，人只负责审批相变，不负责手动分类
3. **Gap 显性化**: LLM 负责对比"应然"（GOAL）与"实然"（EMRG），人只负责在决策列打勾/打叉
4. **上下文守恒**: Agent 每次对话加载文件 ≤ 3 个完整文件，防止上下文腐烂

***

## 3. 核心概念体系

### 3.1 双轨制架构

```
┌─────────────────────────────────────────────────────────────┐
│                      认知操作系统                             │
├──────────────────────┬──────────────────────────────────────┤
│     GOAL 层 (应然)    │          EMRG 层 (实然)              │
│   技术负债 / 目标层   │        知识图谱 / 涌现层              │
├──────────────────────┼──────────────────────────────────────┤
│ • 能力缺口地图        │ • 已内化的知识地形                    │
│ • 动态能力缺口清单    │ • 自下而上的主题聚合                  │
│ • 有 deadline 和退出条件│ • 有成熟度标记 (verified/theoretical)│
│ • 绑定真实驱动事件    │ • 通过涌现规则自组织                  │
│ • 人定义，Agent 对比  │ • Agent 检测，人审批                  │
└──────────────────────┴──────────────────────────────────────┘
              ↕ Gap 分析（诊断矩阵）
```

### 3.2 GOAL（技术负债 MOC）

**定义**: 与当前职业坐标绑定的、可验证的能力缺口清单。

**关键属性**:

- `driver`: survival（生存层）/ promotion（晋升层）/ decision（决策层）
- `deadline`: 到期未完成则强制归档，防止无限悬挂
- `evidence`: 必须关联真实事件（Incident、面试复盘、Code Review block）
- `exit_conditions`: 什么算完成？什么算失败？
- `gaps[]`: 缺口矩阵，与 EMRG 层对比

**模板**:

```markdown
---
type: goal
driver: survival
deadline: 2026-06-30
status: active
---

# GOAL-JVM-Tuning-2026-Q2

## 负债描述
- 驱动事件: [[03-Practice/mistakes/INCIDENT-2026-04-15-GC-Stall]]
- 根治标准: 8G 堆下 99.9% 请求 < 100ms

## 缺口矩阵
| 能力 | 当前 EMRG 证据 | 缺口等级 |
|-----|---------------|---------|
| ZGC 调优 | [[EMRG-Java-JVM]] 仅有 CMS | 🔴 高 |

## 退出条件
- [ ] 产出 [[EMRG-G1-ZGC-压测报告]]
- [ ] 未完成则于 deadline 自动移入 _archive/
```

### 3.3 EMRG（涌现 MOC）

**定义**: 经过涌现规则筛选、具有结构相变能力的知识节点。

**涌现规则（相变触发条件）**:

| 规则       | 触发条件                                   | 涌现动作                  |
| -------- | -------------------------------------- | --------------------- |
| **密度溢出** | 同一主题下原子笔记 ≥ 5 篇，内部双向链接 ≥ 3 条           | 该主题晋升为独立 EMRG         |
| **跨界链接** | 某笔记被 ≥ 2 个不同领域 EMRG 引用                 | 触发跨域枢纽检测              |
| **时间衰减** | 某 EMRG 90 天未编辑且笔记无新增链接                 | 降级至 Archive           |
| **实践验证** | 某主题下 ≥ 1 篇笔记含 GitHub Commit 或 Incident | 标记 maturity: verified |
| **概念裂变** | 单个 EMRG 下子主题超过 7 个                     | 分裂为 2-3 个次级 EMRG      |

### 3.4 Gap 分析

**定义**: 不是"待学清单"，而是"诊断矩阵 + 学习合约"。

**形式**: `META-Gap-当前.md`

| 缺口 ID  | 目标能力   | 当前 EMRG 证据                 | 差距等级 | 学习策略     | **人决策** |
| ------ | ------ | -------------------------- | ---- | -------- | ------- |
| G1-ZGC | ZGC 调优 | \[\[EMRG-Java-JVM]] 仅有 CMS | 🔴 高 | 专项突破 2 周 | \[待填]   |

**关键设计**: Agent 生成前 5 列，人只填最后一列。没有决策的 Gap 矩阵不能进入学习推荐。

## 5. Agent 加载协议与行为模式

### 5.1 分层加载协议（Context Protocol）

```
[对话开始]
  → Layer 0: 读取 config.md（若 Session 未加载，只读一次）
  → Layer 1: 读取 profile.md 的 #当前快照 + #拒绝清单 + #环境默认值
  → [意图识别]
      ├─ 策展意图（"开始今日学习"）→ Layer 2: 扫描 goals/ frontmatter + EMRG frontmatter
      ├─ 对话意图（"AQS 原理"）   → Layer 2: Obsidian CLI search 按需检索
      ├─ 归档意图（"整理笔记"）   → Layer 2: 读取模板 + 当前对话历史
      └─ 周期意图（"每周回顾"）   → Layer 2: 读取 _system/ 全量
  → Layer 3: 实时查询（Obsidian CLI / rg，禁止预扫描全库）
```

**加载上限约束**:

- 单次对话累计加载完整文件 ≤ 3 个（frontmatter 切片不计入）
- 优先 frontmatter，正文按需切片
- 禁止对话开始时预扫描 `02-Knowledge/` 全库

### 5.2 三种行为模式

| 模式       | 触发词      | 加载组合                                                   | 产出                       |
| -------- | -------- | ------------------------------------------------------ | ------------------------ |
| **策展模式** | "开始今日学习" | profile Layer 1 + goals frontmatter + EMRG frontmatter | 3 个选项（关联 GOAL + 拒绝过滤）    |
| **对话模式** | 具体技术问题   | profile Layer 1 + Obsidian CLI search + 相关 EMRG        | 苏格拉底式引导，不给答案             |
| **归档模式** | "整理笔记"   | 模板 + 对话历史 + 涌现检测                                       | 原子笔记 + mastery 更新 + 涌现日志 |

## 6. Skill 体系与改造清单

### 6.1 现有 Skill 改造

#### 学习推荐 SKILL.md

**新增约束**:

```markdown
## 加载清单（严格）
1. `.agent/profile.md` — #当前快照、#拒绝清单、#个性化指令
2. `.agent/goals/` — 扫描所有 `.md` 的 frontmatter（只读 YAML，不读正文）
3. `04-Maps/Emergent/` — 扫描 frontmatter 的 maturity 字段

## 禁止加载
- profile.md 的 #长期愿景
- P1/P2 GOAL 的正文（除非用户追问）
- 02-Knowledge/ 全量扫描

## 强制检查
1. 拒绝清单过滤：命中则告知用户并说明原因
2. GOAL deadline 检查：过期则标红并提示归档
3. Gap 矩阵读取：仅推荐"人决策"为 ✅ 的缺口
```

**输出格式**:

- 每个选项必须包含：`[GOAL-ID]` + 缺口说明 + 关联 EMRG
- 长内容（>500 字）自动附加 TL;DR
- 末尾给出置信度（高/中/低）

#### 整理笔记 SKILL.md

**新增步骤**:

```markdown
## Step 4: 涌现检测（强制）
1. 统计该笔记所在 `02-Knowledge/<主题>/` 的文件数和内部链接数
2. 如果命中密度溢出阈值：
   - 检查 `04-Maps/Emergent/` 是否已存在 EMRG-<主题>
   - 如不存在：追加到 `.agent/_system/emergence.md`
   - 对话末尾提示用户审批

## Step 5: GOAL 缺口同步
- 如该笔记关联某 GOAL 缺口，更新 `gap-analysis.md` 的进度列
- 如该概念已验证，在 GOAL 中标记为 🟢 已达标

## Step 6: EMRG 成熟度更新
- 如该笔记属于某 EMRG 且含 Commit/Incident 链接
- 更新 EMRG frontmatter 的 maturity 字段
```

#### 错误归档 SKILL.md

**新增步骤**:

```markdown
## Step 2: GOAL 关联检查（强制）
1. 提取错误涉及的核心概念
2. `obsidian search query="tag:概念"` 查找归属 EMRG
3. 读取 EMRG frontmatter 的 `related_goal` 字段
4. 如无关联 GOAL：提示"该错误暴露了新能力缺口，是否创建 GOAL？"

## Step 3: 缺口暴露检查
- 如错误涉及概念不属于任何 active GOAL
- 在 `.agent/_system/emergence.md` 记录："高频错误模式涌现"
```

### 6.2 新增 Skill（必须）

#### 每周回顾 SKILL.md

**触发**: "开始每周回顾"

**Phase 流程**:

```markdown
## Phase 1: 系统健康扫描
- 读取 `.agent/_system/health.md`（Dataview 仪表盘）
- 输出：僵尸 MOC 数、孤儿笔记数、到期 GOAL 数

## Phase 2: 涌现审批
- 读取 `.agent/_system/emergence.md`
- 向用户展示待审批项（密度溢出/跨界链接/概念裂变）
- 用户回复 ✅/❌/⏸️，Agent 执行创建/忽略/推迟

## Phase 3: Gap 矩阵生成
- 扫描所有 active GOAL 的缺口矩阵
- 对比 `04-Maps/Emergent/` 的成熟度
- 生成 `gap-analysis.md`（Agent 写前 5 列，人填决策列）

## Phase 4: GOAL 时效检查
- 扫描 `.agent/goals/` 的 deadline
- 7 天内到期：预警
- 已过期：提示归档

## Phase 5: 下周计划
- 仅对 gap-analysis.md 中标记 ✅ 的缺口，生成下周学习推荐
```

#### GOAL 管理 SKILL.md

**触发**: 用户说"创建 GOAL"、错误归档暴露新缺口、每周回顾发现新缺口

**职责**:

- 按模板生成 `.agent/goals/GOAL-xxx.md`
- 整理笔记填补缺口后，更新 GOAL 进度
- deadline 到期且未完成，移入 `_archive/`

#### EMRG 管理 SKILL.md

**触发**: 整理笔记涌现检测被用户确认后

**职责**:

- 按模板生成 `04-Maps/Emergent/EMRG-xxx.md`
- 子主题超过 7 个时，分裂为次级 EMRG
- 90 天无更新且笔记无新增链接，移入 `04-Maps/_archive/`

## 7. 全局约束（Rule 层）

`01-project-workflow.md` 保留为**跨 Skill 宪法**，只包含：

### 7.1 Skill 触发映射表

| 用户输入           | 意图 | 触发 Skill | 禁止行为                 |
| -------------- | -- | -------- | -------------------- |
| "开始今日学习"       | 策展 | 学习推荐     | 不预加载 02-Knowledge 全库 |
| "整理笔记" / 对话结束  | 归档 | 整理笔记     | 不跳过 mastery 更新       |
| "保存错误" / 排查完故障 | 归档 | 错误归档     | 不遗漏 GOAL 关联          |
| "每周回顾"         | 周期 | 每周回顾     | 不忽略过期 GOAL           |

### 7.2 Mastery 统一计算标准

| 场景      | 分值      | 判定标准                    |
| ------- | ------- | ----------------------- |
| 完成练习    | +10\~20 | 正确应用概念                  |
| 建立新关联   | +10\~15 | 发现与已有知识的新连接             |
| 教学/讲解   | +15\~25 | 向他人解释或纠正误区              |
| 复习巩固    | +5\~10  | 间隔复习后准确回忆               |
| 发现偏差    | -5\~10  | 练习中犯错或对话中发现误解           |
| **硬约束** | —       | 同一对话内 mastery 跳跃 ≤ 30 分 |

### 7.3 全局质量红线

- 任何推荐必须关联 GOAL 或 EMRG
- 任何笔记必须 ≥ 2 个双向链接
- 任何错误归档必须关联 GOAL（如无则提示创建）
- 任何对话结束必须更新 `profile.md` 的 #当前快照（仅坐标，不写历史）

## 9. 验收标准

1. **涌现可审计**: 当保存第 5 篇同主题笔记并链接 3 个同主题笔记时，Agent 在对话末尾说："检测到密度溢出，建议创建 EMRG-xxx，请查看 `.agent/_system/emergence.md` 审批。"
2. **Gap 可决策**: 每周回顾时，Agent 输出 Gap 矩阵，明确指出"ZGC 调优缺口 🔴 高，因为 EMRG-Java-JVM 仅有 CMS 证据"，等人填决策列。
3. **推荐可过滤**: 当用户让 Agent 推荐时，Agent 自动跳过拒绝清单中的前端/K8s 项，并说出"根据战略边界，\[主题] 已拒绝（原因：xxx）"。
4. **方向可 30 秒把握**: 每周五打开 `.agent/_system/health.md`，一眼看到僵尸 MOC 数、孤儿笔记数、到期 GOAL 数。

## 10. 设计原则总结

> **`.agent/`** **是驾驶舱：`profile.md`** **是方向盘（当前坐标 + 边界），`goals/`** **是目的地（技术负债），`_system/`** **是仪表盘（Agent 自动维护，人只读）。**
>
> **`04-Maps/`** **是地图（知识地形），`01-03`** **是战场（项目、笔记、练习）。**
>
> **AGENTS.md 是宪法（边界约束），Skill 是法律（具体行为），frontmatter 是数据库（单一真相源）。**
>
> **涌现不是"我觉得该建 MOC 了"，而是 Agent 按协议扫描后强制提案，人只有批准/拒绝权。**
