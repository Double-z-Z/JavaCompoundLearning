# OpenCode Pipeline Orchestrator — 实现规划与路线图

## 1. 版本规划

### V0.1 MVP (当前 — 已部分实现)
**目标**: 验证核心机制，30 分钟跑通一次五阶段工作流

| 功能 | 状态 | 阻塞 |
|------|------|------|
| 状态机引擎 (Run/Stage/Gate) | ✅ 已实现 | — |
| 后端 Agent 执行 (subprocess) | ✅ 已实现 | — |
| 产物文件系统监控 | ✅ 已实现 | — |
| 单页 HTML UI (启动/审批/预览/日志) | ✅ 已实现 | — |
| 多模型配置 (DeepSeek/MiniMax/Kimi) | ✅ 已实现 | — |
| 环境变量注入 (secrets.json) | ✅ 已实现 | — |
| 实时流式日志 (stdout/stderr 解析) | ✅ 已实现 | 日志格式待优化 |
| 上下文路径注入 | ✅ 已实现 | — |
| 自动 Gate (file_exists) | ✅ 已实现 | — |

**已知缺陷**:
- 日志 ANSI 码未完全清理，显示混乱
- 交互式 Stage 未实现 (architect/reviewer 仍是 backend)
- 产物内容未注入 Prompt (仅路径)
- 无错误重试机制
- UI 预览按钮硬编码路径

## 2. 技术债务清单

| 债务 | 影响 | 偿还计划 |
|------|------|---------|
| 硬编码 WORKFLOW | 无法配置新流程 | V0.3 改为 YAML 加载 |
| 硬编码 AGENT_CONFIG | 无法调整 Prompt | V0.3 改为外部配置 |
| 无测试覆盖 | 重构风险 | V0.2 补充端到端测试 |
| 文件系统轮询 | 性能差 | V0.2 改为 inotify |
| 单进程 Sidecar | 无法水平扩展 | V0.4 考虑多进程 |
| 无数据库 | 状态丢失风险 | V0.3 评估 SQLite |

## 3. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| OpenCode CLI 行为变更 | 中 | 高 | 封装适配层，隔离 CLI 细节 |
| 模型 API 限流/涨价 | 高 | 中 | 多模型路由，本地模型兜底 |
| PTY 跨平台兼容性 | 中 | 中 | 先用暂停指引方案兜底 |
| 长上下文超限 | 高 | 中 | 产物截断 + 摘要提取 |
| 并发文件冲突 | 低 | 高 | 每个 Run 独立 worktree |

## 4. 里程碑定义

| 里程碑 | 验收标准 | 预计时间 |
|--------|---------|---------|
| M1: 后台跑通 | 点击启动 → 自动完成 architect→coder→reviewer，产物非空 | 已完成 |
| M2: 人类介入 | 在 direction-gate 审批，驳回后 coder 重新执行 | 已完成 |
| M3: 交互对话 | architect 阶段人类在 UI 中与 Agent 实时对话 | V0.2 |
| M4: 自举迭代 | 用本工作流修改 sidecar.py，合并到 main | V0.3 |
| M5: 知识复利 | 决策日志自动导出到 Obsidian，形成知识图谱 | V0.4 |
